## 2. 설정·바인딩 계약

- 차량에 예를 들어 `ammoIncidents:{enabled:true,victimProfileId:'M1A2_1998',...}`를 명시 등록한다. 원본 프로파일에 위험 데이터가 없으면 기존 동작을 유지하고, 비활성 표시는 `{enabled:false}`처럼 명확히 구분한다. 활성 설정을 다른 차량 ID로 복사하고 피해 차량 바인딩을 고치지 않으면 거부한다.
- 공격 탄약 정책은 **실제로 날아온 탄의 ID** M829A2/A1/M830을 각각 연결한다. 공격 탄종·저장된 탄종·차량의 기본 탄종·다음 선호를 구분한다. 저장 탄약 반응 계수는 이번 세 탄 모두 1이라는 시험 설정으로 명시하며 미확인 폭약량/탄약별 실제 유폭성을 추정하지 않는다.
- 7구역 매핑, 지원 탄종/구획, 유한 확률·보호 계수·시간, 비음수 정수/비율, 합계 1, 정책 ID/차량 ID/재고 바인딩을 로드·내보내기 단계에서 검증한다. 알 수 없는 활성 ID·빈 행·NaN·중복/누락은 조용히 다른 차종 값으로 대체하지 않는다. 설정이 없는 공격 무기에 보편적 기본 유폭 확률을 부여하지 않는다.
- 사건별 구획 선택·발생·결과 roll은 seed+착탄 ID+피격 차량 ID+고정 단계 키로 분리한다. 기존 명중/구역/도탄/WIP15/WIP18 난수 키와 순서를 바꾸지 않는다. UI/렌더/조회·Worker 완료·배속 프레임 묶음에서 추첨하지 않는다.

## 3. 초기 시험 표와 판정 순서

**아래 숫자는 이번 구현을 실행·비교하기 위한 새로운 조정 가능 시험안이다. 실제 취약부·배치/관통 경로·보호 성능·발생률 자료가 아니다.**

먼저 확정된 피격 7구역에서 아래 고정 분포로 가상 대상 하나를 선택한다. `none`은 탄약고 기회 없음이다. 좌/우 측면은 이번 공통 측면 행을 사용한다. 정밀 표시용 탄착점·파티클 충돌 좌표를 내부 탄약고 명중 근거로 사용하지 않는다.

| 피격 구역 | ready | semiReady | reserve | none |
|---|---:|---:|---:|---:|
| hullFront | 0 | .10 | .15 | .75 |
| hullSide | .05 | .15 | .30 | .50 |
| hullRear | 0 | .10 | .20 | .70 |
| turretFront | .10 | .10 | 0 | .80 |
| turretSide | .30 | .20 | 0 | .50 |
| turretRear | .40 | .25 | 0 | .35 |
| upper | .15 | .15 | .10 | .60 |

| 공격 탄약 | 사고 기본 확률 [시험] |
|---|---:|
| M829A2 | .30 |
| M829A1 | .30 |
| M830 | .40 |

선택 구획의 사고 확률은 `기본 확률 × 잔존 적재율 × 위험 전달 계수`다. 잔존 적재율은 §5의 소유 규칙에 따른 **그 구획의 사용 가능 탄+그 구획 소유 예약탄**을 WIP19 구획 용량으로 나눈 값이다. 0~1이며 저장 탄종별 반응 계수는 이번 모두 1이다. 위험 전달 계수는 작을수록 보호가 큰 가상 설정이다. 추가 관통/입사각/계산 HP 피해 배율은 이번 사고 확률에 다시 곱하지 않는다.

| 구획 | 위험 전달 계수 [시험] | 사고 발생 후 탄약 손실 | 격리 화재 | 치명 사고 |
|---|---:|---:|---:|---:|
| ready | .50 | .70 | .28 | .02 |
| semiReady | .65 | .65 | .32 | .03 |
| reserve | .80 | .60 | .35 | .05 |

- **자격:** 실제 명중·관통 성공·비도탄이며 일반 HP 피해 처리 후 살아 있는 참여 차량만 사고를 판정한다. 빗나감·비관통·근접 비관통·도탄·중복 착탄·이미 격파/이번 일반 피해로 격파된 차량은 사고 처리에서 제외한다. 관통 뒤 과관통 분류도 이 자격 안에서 동일 규칙을 사용한다.
- `none` 또는 선택 구획의 소유 탄 0이면 사고 없음이다. 빈 구획의 기회를 다른 구획으로 재분배하거나 나올 때까지 재추첨하지 않는다. 약실 탄만 남은 상태는 이번 저장 탄약고 사고 대상이 없다.
- 발생은 `roll < chance`, 결과는 표 순서의 반열린 누적 구간으로 **정확히 하나** 선택한다. 경계·확률 0/1·빈 구획·탄수 감소를 검증한다. 예: 가득 찬 ready에 turretRear·A2 조건의 ready 경로 확률은 `.40×.30×1×.50=.06`, 그 경로의 치명 확률은 `.06×.02=.0012`다. 조건부 결과 확률을 피격 전체의 즉사율로 보고하지 않는다.

## 4. 세 결과·수명과 기존 피격 반응

| 결과 | 이번 효과 [시험] |
|---|---|
| 탄약 손실 | 선택 구획 소유 탄의 25%를 올림하여 최소 1발 소실. 추가 HP 피해·사격 중단 없음 |
| 격리된 탄약고 화재 | 선택 구획 소유 탄 전부 소실 + **8초 사격 안전 중단**. 추가 HP/승무원 피해·시간당 피해 없음. 차량 기동·관측·지정·조준은 유지 |
| 치명 사고 | 차량 HP 0·표준 격파 경로 한 번. 차량 전체 저장/약실/예약 탄은 사건 손실로 한 번 정리하며 신규 사고·행동 정지 |

- 화재는 구획별 파괴/영구 고장이 아니다. 용량은 유지하고 8초 종료 뒤 남은 탄과 기존 공급/보충 조건으로 다시 운용할 수 있다. 외부에서 탄을 생성하지 않는다. 화재 중 새 격리 사고는 `until=max(기존 until, now+8)`로 처리해 시간을 누적 가산하지 않는다. 빈 구획은 재발·기간 연장의 근거가 되지 않는다.
- 안전 중단 동안 수동/자동 발사와 장전·준비·보충 작업 진행을 막는다. 생존 예약탄·진행률은 동결하며 부상 계수를 초기화하지 않는다. 관측·조준과 이동은 기존대로다. 시뮬레이션 일시정지 시 기간/작업도 멈춘다. 만료 뒤 작업은 남은 상태에서 재개하거나 유효 탄을 새로 예약한다.
- 안전 중단의 동결 대상은 탄약 작업 진행이다. 기존 피로/동요 회복·장비 이상 기간·부상/기동 갱신은 각각의 기존 규칙을 유지한다. 안전 중단을 발사선 차폐나 시야 상실로 기록해 표적 차폐 캐시를 새로 만들지 않는다.
- 기존 일반 HP→생존 시 WIP18 한 범주 반응을 보존하고, 그 뒤 사고를 처리한 최종 결과로 WIP15 피격 반응과 공개/격파 상태를 마무리한다. 사고가 추가 WIP18 부상이나 WIP15 피격을 새로 반복 호출하지 않는다. 일반 HP 격파는 기존 흐름을 그대로 사용한다.
- 하나의 착탄 처리 단위에서 최종 HP·격파 원인·한 번만 실행되는 격파 콜백·관측 HP/잔해 결과가 일치해야 한다. 치명 사고의 추가 잔여 HP 손실과 일반 HP 피해를 내부 기록에서 구분하고 합계는 실제 HP 감소와 같게 한다. 기존 탄도 `computedDamage`를 사고 확률/피해로 덮어쓰지 않는다.
- 이미 발생한 발사체는 사수의 사고/격파와 무관하게 기존 동결 정보로 비행/착탄한다. 같은 틱에 여러 발이 도착하면 기존 impactAt/ID 순서와 최신 재고를 사용한다. 두 번째 사건이 이미 소실된 탄을 다시 소실시키거나 격파 콜백/잔해를 다시 생성하면 안 된다.

## 5. 탄약 소유·손실과 예약 작업의 원자적 처리

- **소유 규칙:** 준비/장전용 또는 보충용 예약탄은 작업 완료 전까지 원구획 소유다. 약실 이동/즉응 구획 이전이 완료되는 순간에만 소유가 바뀐다. 약실 탄은 별도 소유이며 생존 사고의 구획 손실 대상에 넣지 않는다. 사건 직전 재고/예약 스냅샷 하나에서 확률과 손실을 계산한다.
- 매 탄종의 `남은 탄 = 사용 가능 저장탄 + 유효 예약탄 + 약실 탄`을 유지한다. 전체 이력에서는 `초기 42 = 실제 발사 수 + 사고로 소실한 수 + 남은 수`를 만족한다. 준비·보충·취소·pause는 발사/손실 수를 증가시키지 않는다.
- 25% 부분 소실의 탄종별 배분은 구획 소유 탄 구성 비례의 정수 배분을 사용한다. 버림 뒤 남은 발수는 소수부 큰 순서, 동률은 프로파일 지원 탄종 순서로 배분한다. 탄종별 손실은 해당 소유 수량을 넘지 않는다. 동일 탄종에서는 사용 가능 저장탄을 먼저 차감하고 부족한 몫에만 그 구획 예약탄을 소실시킨다. 이 분배에 새 난수를 쓰지 않는다.
- 예: 즉응 소유 탄 A2/A1/M830이 7/4/6이면 25% 올림은 5발이며 손실 배분은 2/1/2다. 소유 탄이 예약탄 1발뿐인 구획은 부분 소실에서도 그 1발과 작업 토큰이 함께 소실된다.
- **예약탄이 소실되면** 토큰을 무효화하고 해당 작업을 취소한다. 소실탄을 취소 반환 경로에 다시 넣지 않는다. 부분 손실에서 살아남은 예약탄과 다른 구획 소유 예약탄은 유지하며, 격리 화재면 기간 동안 진행만 동결한다.
- 치명 사고는 모든 예약을 **반환 없이 손실 처리**한 뒤 저장/약실을 정리하고 표준 격파를 실행한다. 일반 HP 격파의 기존 정리 정책과 구분한다. 이후 `cancelAmmoTask`·격파 정리·패널 조회·reset이 소실탄을 복구하면 안 된다.
- 재고 변경은 기존 FireControl 또는 별도 작은 재고 서비스 한 곳에서 수행한다. 기존 가변 총탄 카운터를 별도로 감소시키지 않는다. Combat→FireControl 역방향 require로 순환 의존을 만들지 말고 필요한 콜백/서비스를 명시 연결한다. 시나리오 reset은 사고 기록/기간/누적 손실까지 초기화해 원래 42발·장전 A2·다음 자동으로 복원한다.

## 6. 사격·AI·안전 중단 연결

- 안전 중단은 별도 사유(예: `ammo-safety` / 표시 `탄약고 화재 대응`)로 발사 직전까지 검사한다. 이미 큐에 있던 수동/자동 명령도 탄약·발사 번호·난수·비행체·효과를 만들지 않고 거절한다. WIP16 무발사 probe도 소비 없이 중단 사유를 처리한다.
- 살아 있는 약실/유효 준비·장전 예약탄/사용 가능한 선호 탄이 있으면 화재 기간을 탄약 소진으로 취급하지 않는다. halt AI는 같은 표적·정지 임무를 유지하고 만료 뒤 정상 재개한다. 사고로 **실제 총탄 0**이 되면 기존처럼 교전을 풀고 같은 임무로 한 번 복귀한다.
- 유효 작업 없이 선택 탄종만 소진된 경우, 예약탄 소실 직후, 다른 탄으로 다음 선호 변경, 만료·재사고 경계에서 기존 WIP19의 무한 정차/지정·복귀 반복 방지를 유지한다. 자동/보류 모드는 사고가 임의로 바꾸지 않는다.

## 7. 표시·효과·공개 정보

- 기존 우측 상단 명령/하단 선택 정보 구조를 유지한다. 선택 **아군**에 남은 구획/탄종 재고, 작업 중단 사유/기간, 최근 사고의 손실 발수·시각을 간결하게 표시한다. 이전 손실 기록과 현재 활성 사고를 구분한다.
- 아군 유닛 위에는 활성 기간에만 `탄약고 화재 대응 8s` 같은 짧은 문구를 기존 최대 2줄 우선순위에 넣는다. 사격 불가 원인이므로 일반 탄 준비/보충보다 우선한다. 손실만 발생한 결과는 짧은 알림/선택 정보 기록으로 처리하며 영구 지도 꼬리표로 남기지 않는다. **승무원 피해는 계속 우측에만 표시한다.**
- 유폭/화재 연출은 확정 사건 뒤 기존 효과 예산·풀에 등록한다. 탄약 일부 손실은 작은 반응, 격리 사고는 짧은 화염 분출/연기, 치명 사고는 한 번의 강한 폭발로 차이를 준다. 튀는 탄/파편은 표시용이며 추가 피해·연쇄 사건을 만들지 않는다. 과도한 불기둥·지속 대량 입자를 피하고 저품질/동작 감소 옵션을 존중한다.
- 미관측 적의 사고도 WIP12 사격 효과처럼 **사고 시점의 고정 월드 좌표에서 짧은 물리 연출**은 보일 수 있다. 미관측 차량을 따라가는 화염/연기·이름/HP·상태 문구는 추가하지 않는다. 연출의 외형 차이는 허용하되 공개 효과 사건에 적 실제 ID·내부 구획/탄종/잔탄·작업·보호 계수·확률/roll·사고 결과 레코드를 넣지 않는다.
- 사고 효과만으로 미관측 적의 격파를 확정하거나 접촉/잔해를 생성하지 않는다. 관측 HP·기억 스냅샷·최신 관측 병합과 실제 잔해 재발견 규칙을 보존한다. `combatView`/`publicRecord`/발사·착탄 기록·공개 스냅샷에 새 내부 상태가 통째로 퍼지지 않게 경계별로 검사한다. 아군의 권한 있는 상태와 비공개 디버그 사건은 별도다.

## 8. 결정성·실행 경로·성능

- 사건은 착탄 시 한 번, 상태는 고정 0.05초 틱으로 갱신한다. 렌더·조회는 읽기만 한다. 활성 사고가 없는 경우 단차별 상수 수준 조회, 사고 발생 때 세 구획/세 탄종의 작은 처리만 사용한다. 추가 매 프레임 LOS·전체 적 쌍·탄약고 내부 물리·대량 객체/DOM 생성을 넣지 않는다.
- 프로파일·탄약 내보내기, 페이지·단일 HTML·내장 Worker·Node/독립 LOS·합성 지도 로더와 테스트 팩토리의 새 의존성을 빠짐없이 연결한다. 미참여/비활성 fixture는 기존 결과·발사/피격 반응 난수를 보존한다. 활성 사고가 바꾼 전투 전체가 기존과 동일하다고 주장하지 않는다.
- 같은 환경의 기준/신규 비활성/활성 50·100대에서 상태 갱신·조회/문구·효과 비용의 중앙값/P95와 기본 앱 틱/렌더를 구분해 측정한다. 효과 예산/시간당 사고 수를 명시하고 실제 휴대폰 미실시 범위를 분리한다.
