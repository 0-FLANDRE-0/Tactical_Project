## 3. 결과가 먼저, 이펙트가 나중

1. 기존 발사 승인·비행·착탄 시점과 명중/면 선정 확률을 유지한다. 실제 명중·선택 면·입사각을 바탕으로 도탄 여부를 처리하고, 도탄하지 않은 명중에 기존 게임 관통·피해 처리를 연결한다.
2. **명중·선택 면·도탄 등 내부 결과가 확정된 뒤** 해당 결과를 표현하는 이펙트 이벤트를 만든다. 파티클이 차량 외곽에 닿았는지, 화면에 보이는지, 어느 텍스처가 선택됐는지는 결과를 바꾸지 않는다.
3. 빗나감은 기존 방식으로 확정된 지면·건물 등의 표시 탄착점에 표현한다. 확정된 명중·비관통·관통·도탄은 그 결과와 모순되지 않는 피격 위치·표현을 사용한다. 연출을 위해 명중이나 피격 면을 다시 추첨하지 않는다.
4. **도탄은 해당 사건의 관통·HP 피해 0**으로 끝낸다. 도탄 뒤 보이는 탄광·불꽃·파편은 별도 게임 탄, 새 사격, 새 충돌, 표적 탐색, 추가 피해 이벤트를 만들지 않는다. 아군·적·다른 차량·잔해를 지나가도 피해나 게임 상태 변경이 없어야 한다.
5. 같은 발사/착탄 ID는 내부 판정·도탄 추첨·피해 적용과 이펙트 생성 각각에서 중복 처리되지 않아야 한다. 재조회·콜백 재전달·프레임 재생·지도 이동으로 재추첨하거나 효과를 다시 생성하지 않는다.
6. 새 도탄 난수는 기존 명중/피격 면 난수를 밀어내지 않는 독립된 사건 키/영역을 사용한다. 텍스처 변형·파티클 위치/속도/회전은 **별도 표시용 seed**로 만든다. 프레임마다 전투 난수를 호출하지 않는다.
7. 이펙트 켜짐/꺼짐, 파티클 예산·품질, 줌·DPR·프레임 묶음이 달라도 같은 게임 seed·명령의 명중/피격 면·도탄·피해 결과는 같아야 한다. 기존 결정적 재현성과 피해 중복 방지를 유지한다.

## 4. 선택 면의 입사각·게임 관통/도탄

- 착탄 시 확률로 선택된 전/측/후 면과 좌우, **착탄 시점의 실제 차체/포탑 방향**을 사용한다. 차체와 포탑 방향을 섞지 않고 발사 당시 표적 자세로 되돌리지 않는다. 기존 게임 박스 면 규약과 아카이브를 따른다.
- 표시 탄착점이나 텍스처의 회전으로 피격 면·입사각을 다시 정하지 않는다. 도탄을 피하려고 더 유리한 다른 면으로 바꾸거나 면을 재추첨하지 않는다. 상부 구역은 현행 비활성 상태를 유지한다.
- 활성 시험탄의 기존 거리 노드·각도 노드·장갑·HP·피해 배율은 보존한다. 고각에서는 아카이브에 승인된 **기존 마지막 각도 노드에서 면에 평행한 한계각의 0까지 이어지는 게임 보간**을 적용한다. 기존 낮은 각도 구간의 보간과 거리 밖 끝값 정책은 유지한다. 새 실장비 성능값이나 별도 물리 관통 공식을 만들지 않는다.
- 도탄 확률은 아카이브의 해당 시험탄 게임 기준각과 구간 보간을 데이터로 연결한다. 전체 탄종에 임의 공통값을 채우거나 미정 탄약을 활성화하지 않는다. 런타임 레지스트리와 내보낸 JSON이 같은 기준을 가리켜야 한다.
- 도탄 판정은 유효한 미처리 명중 사건에 한 번만 적용한다. 확률의 양 끝과 중간값을 검증하고, 비교 연산·경계·난수 호출 규약을 문서화한다. 도탄 성공 분기는 관통·피해 평가로 다시 진입하지 않는다.
- 도탄하지 않으면 해당 입사각의 게임 관통값과 기존 선택 구역 방호값으로 관통/비관통·HP 처리를 한다. 별도의 장갑 경사 보정이나 추가 관통 확률을 겹쳐 넣지 않는다. 비관통 피해 0 등 이번에 바꾸기로 하지 않은 피해 정책은 유지한다.
- 새 상태/기록에는 도탄과 비관통을 구별할 수 있는 결과를 남긴다. 0 관통값·각도 경계에서 NaN·음수 피해·0 나눗셈이 없어야 하고, 원래 착탄 정렬·사건 ID·격파 전이·잔해 규칙을 보존한다.
- 이 값들은 게임 밸런스 데이터다. 실제 탄약/장갑의 성능 추정이나 현실 물리 검증으로 소개하지 않는다.

## 5. 자체 텍스처와 연출 방향

**시각 목표:** 절제된 황백색 섬광, 회백/회갈색 연기와 먼지, 작고 빠른 탄광, 작은 충돌 불꽃. 전용 투명 텍스처의 부드러운 가장자리와 겹침으로 표현한다.

1. 자체 제작한 투명 PNG/WebP 스프라이트 또는 atlas를 저장소에 둔다. 발사 섬광·연기/먼지·작은 불꽃/파편·탄광에 필요한 소재와 제작 원본/과정을 기록한다. 외부 CDN·이미지 URL·런타임 다운로드에 의존하지 않는다.
2. 실행 파일에 텍스처를 내장하고 처음 사용하기 전에 디코딩을 완료한다. 프레임마다 이미지 객체나 새 텍스처를 만들지 않는다. 텍스처 실패가 시뮬레이션이나 전체 게임 시작을 막지 않게 하고 개발 검증에서는 누락을 분명히 실패시킨다.
3. **발사:** 실제 발사 이벤트가 기록한 포구 위치·방향에서 짧은 섬광, 옅은 연기와 먼지를 만든다. 이동/선회한 현재 사수 객체를 따라 포구 효과가 끌려가지 않는다.
4. **예광:** 비행을 읽을 수 있는 짧고 빠른 밝은 핵과 잔상으로 표현한다. 굵고 긴 상시 레이저처럼 보이지 않게 한다. 기존 포구·발사 방향·게임 비행 시간과 결과 뒤의 탄착점 계약을 유지한다. 가독성을 위한 잔상은 표시 수명만 조정하며 실제 비행/착탄을 늦추지 않는다.
5. **피격/탄착:** 지면·건물·차량 충돌과 내부 결과에 맞는 짧은 불꽃·먼지·파편을 보여준다. 차량 명중마다 거대한 폭발을 넣거나 기존 연출과 새 연출을 중복으로 겹치지 않는다. 확정된 피해량을 연출 난수로 바꾸지 않는다.
6. **도탄:** 선택 면/입사 방향을 참고한 짧은 튕김 탄광과 충돌 불꽃 뒤 소멸한다. 이것은 결과를 보여주는 애니메이션이고 별도 물리 탄의 비행/피해 계산이 아니다.
7. 큰 ‘명중!’·‘도탄!’ 글자나 새 피해 숫자를 매 충돌에 띄우는 표현을 기본으로 하지 않는다. 기존 체력바·선택/표적 표시·오른쪽 정보 패널은 유지하고, 관측 가능한 최근 결과에 도탄 표시가 필요하면 짧게 연결한다.
8. 월드 좌표와 화면 크기 규칙을 구분해 전체 지도와 최대 확대 모두에서 읽히게 한다. 줌에 따라 섬광·탄광이 과도하게 커지거나 완전히 사라지지 않게 최소/최대 화면 크기를 둔다. 연기·먼지는 지형을 오래 덮지 않게 한다.
9. 파티클 위치·방향·수명은 사건 시점의 분리된 사본에서 계산한다. 시뮬레이션 일시정지 시 효과 시간도 멈추며, 배속·초기화·선택 변경·지도 이동에서 유령 효과나 잘못된 재생이 남지 않게 한다. 모션 줄이기에서는 부가 입자를 줄이되 핵심 발사/충돌 표시는 유지한다.

## 6. 미관측 적 사격의 공개 규칙

**사용자 확정:** 적이 보이지 않아도 발사·예광·탄착/피격·도탄 이펙트와 파티클을 표시한다. 이펙트가 드러내는 사건 위치·방향과 정성적 충돌/도탄 모습은 의도된 정보 공개다.

- 아군/적군 및 관측 여부 때문에 효과를 통째로 누락하지 않는다. 미관측 명중도 표시용 충돌 이벤트를 내보내고, 미관측 빗나감만 먼지를 보여주던 비대칭을 없앤다. 적 사격 표시가 발사 팀 필터에 계속 막히지 않는지 실제로 검사한다.
- **효과 공개와 유닛 공개는 구분한다.** 효과를 봤다고 적 모델·이름·차종·HP·조준 상태를 추가하거나 탐지/식별·팀 접촉·선택·표적 지정·영구 잔해를 자동 생성하지 않는다. 기존 접촉 기억과 마지막 확인 HP는 유효 관측이 갱신할 때만 바뀐다.
- 기존 상세 사격/피해 이벤트를 양 팀에 무제한 공개하는 방식으로 해결하지 않는다. 렌더러가 필요한 최소한의 분리된 **표시용 사건**을 사용한다. 예: 불투명한 효과 ID, 시각, 종류, 발생 위치, 표시 방향/경로, 수명·표시 seed. 비공개 사수/표적 객체 참조·이름/프로파일·현재 HP·정확한 피해/방호 수치·적 잔탄·대상 지정 정보는 담지 않는다.
- 효과 ID가 미식별 적의 내부 유닛 ID를 그대로 드러내거나, 렌더러가 그 ID로 실제 적 객체를 찾아가게 하지 않는다. 사격 시점 위치가 효과로 드러나는 것은 허용하지만 그 뒤 숨은 적의 이동을 효과가 실시간 추적하지 않는다.
- 기존 공개 패널·snapshot의 숫자/접촉 규칙은 유지한다. 미관측 도탄의 모양이 보인다는 이유로 숨은 HP나 정확한 관통 수치를 패널·개발용 공개 snapshot에 덧붙이지 않는다. 숨은 격파를 영구 잔해/격파 텍스트로 공개하는 정책도 이번에 바꾸지 않는다.
- 표시 사건에는 안정된 중복 방지 키와 제한된 보관 기간/개수를 둔다. 재조회·카메라 이동·늦은 프레임에도 효과가 중복 생성되지 않고, 지난 사건을 읽기 위해 전체 전투 기록을 매 프레임 다시 복제하지 않게 한다.
- 화면 밖 효과는 그리기를 생략할 수 있지만 내부 판정·시각을 바꾸지 않는다. 화면에 들어왔을 때 아직 수명이 남은 효과만 정상 나이로 표시한다. 화면 가장자리 공격 방향 UI 같은 새 기능은 이번 필수 범위에 넣지 않는다.

## 7. 성능·보존 범위

- 전역/사건별 파티클 상한, 사건 큐 상한, 수명과 품질별 예산을 명시한다. 입자가 많아지면 부가 연기·먼지부터 줄이고, 각 발사/충돌을 알아볼 핵심 표시는 유지한다. 입자 수를 줄여도 전투 결과는 같아야 한다.
- 텍스처·버퍼/작업 객체는 재사용하고, 종료 입자·사건은 제거한다. 매 프레임 전체 유닛/전투 기록 검색·텍스처 디코딩·새 캔버스 생성으로 바꾸지 않는다. 객체 풀을 쓰더라도 오래된 공개 사본을 덮어쓰지 않는다.
- 이펙트 렌더러/파티클은 LOS·사격·피해 API를 호출하지 않는다. 도탄 후 파티클에 물리 충돌·주변 차량 탐색을 연결하지 않는다.
- WIP11E 공유 LOS, 지도 캐시·지형 강조·내장 Worker, 입력·가로 전용 UI·일시정지 복원·관측/경계·후보 순서를 보존한다. 이펙트 표시를 위해 센서 거리·주기·정밀도·이동/지도 데이터를 변경하지 않는다.
- 효과가 없는 50/100대 관측 fixture는 같은 조건으로 비교해 WIP11E 최적화가 유지되는지 확인한다. 양 팀이 반복 사격하는 효과 스트레스 장면은 별도로 측정해 CPU·프레임 지연 중앙/P95·동시 입자/큐 크기·메모리 추이를 기록한다. 표시 비용과 시뮬레이션 비용을 분리하고 서버 CPU 값을 모바일 FPS 보장으로 바꾸지 않는다.

## 8. 검증·완료 기준

### 8-1. 판정·도탄·피해

- 선택 면과 착탄 시 차체/포탑 독립 방향, 좌우 측면, 각도 보간의 노드/구간 경계/고각 한계, 기존 거리 끝값, 도탄 곡선의 끝·중간·경계와 추첨 비교 규약을 검사한다. 기존 낮은 각도/도탄 없는 경우와 의도된 WIP12 변경을 구분한다.
- 새 도탄의 확정 성공/실패 분기를 통제된 난수로 검사하고, 실제 코어의 탐지·확보·조준·발사·비행·착탄에서도 새 처리가 연결되는지 확인한다. 모든 검사를 `ready`/착탄 결과 주입만으로 대신하지 않는다.
- 도탄 사건은 최초 대상의 HP·모듈·추가 피해가 0이고 이후 탄광이 다른 아군/적/잔해를 지나가도 새 피해·격파·비행 사건이 생기지 않아야 한다. 중복 ID 재전달과 같은 시각의 여러 착탄도 검사한다.
- 이펙트 활성/비활성·입자 예산·품질·프레임 묶음·줌/DPR이 달라도 게임 결과와 결정 난수 기록이 일치해야 한다. 기존 명중/피격 구역 동결 기준표를 새 결과로 덮어쓰지 않는다. 새 고각·도탄 규칙 때문에 의도적으로 달라진 기대값은 이유와 별도 기준을 기록한다.

### 8-2. 공개·연출 통합

- 팀 접촉에 없는 적이 실제로 발사하는 장면에서 포구·예광·탄착/도탄을 확인한다. 적 모델·라벨·HP·선택/접촉·숨은 이동 정보는 새로 공개되지 않아야 한다. 미관측 명중과 빗나감 모두 효과가 나와야 한다.
- 미관측 동안 실제 HP가 바뀌어도 기억 HP는 고정되고, 다시 관측하면 갱신되는 기존 C05/C06을 유지한다. 기존 잔해 공개/선택 불가와 팀 공유/자체 확보 구분도 확인한다.
- 효과의 공개 객체/snapshot을 직접 검사해 비공개 숫자·유닛 참조·내부 식별자가 섞이지 않았는지 확인한다. 반환 사본 변조가 저장 상태에 영향을 주지 않아야 한다.
- 사수 이동/선회/격파 후에도 이미 기록한 포구와 사건 위치를 유지한다. 도탄·관통·비관통·지면/건물 탄착의 모습이 확정 결과와 일치하고, 재조회·토글·선택 변경·프레임 지연으로 중복되거나 되감기지 않아야 한다.
- 원본 단일 HTML을 실제 Chromium에서 실행한다. 1440×900과 844×390 가로, DPR 1/2, 전체 지도·중간·최대 확대, 일반/지형·등고선·시야 홀드, 세로 차단/복귀·일시정지·배속·초기화를 검사한다. 새 텍스처가 외부 통신 없이 로드되고 페이지/이미지 오류가 없어야 한다.
- 실제 발사·피격·도탄의 연속 프레임이나 짧은 녹화를 남긴다. 정적 스크린샷만으로 사건 시점·수명·중복 방지와 비행 방향을 검증했다고 하지 않는다. 강제로 만든 아트 미리보기는 통합 판정 검사의 증거와 구분한다.

### 8-3. 회귀·실행 파일

- 현재 전체 Node 회귀, 새 판정·공개·이펙트 검사, 지형 재현성·원본 자료 품질, 실제 브라우저를 실행한다. LOS의 WIP07A/WIP11D 원본·WIP11E 동등성 검사를 보존하고, 새 시각 필드만 명시적으로 분리한다. 게임 상태 차이를 넓게 제외해 검사를 통과시키지 않는다.
- 결과 수·실패·건너뜀·미실행과 통제 난수 검사/실제 코어 통합 검사를 구분한다. HTML/Worker 모듈 순서를 확인하고, 이미지 제작/빌드용 파일과 검사 fixture가 불필요하게 런타임에 포함되지 않게 한다.
- `python3 build.py`, `python3 scripts/package_release.py WIP12`를 실행하고 **버전 HTML = dist**, ZIP 단일 HTML·CRC·해제 바이트·SHA-256과 반복 패키징 일치를 확인한다. 텍스처도 HTML에 내장되어야 하며 이전 WIP 실행 파일을 보존한다.
- `file://`가 정책으로 막히면 정확한 오류를 남기고 같은 파일을 로컬 HTTP로 검사한다. headless viewport와 실제 모바일 지속 성능·발열 검증은 구분한다.
