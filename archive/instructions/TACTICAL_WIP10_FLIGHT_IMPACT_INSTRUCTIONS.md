**원칙**
1. **명중 판정은 확률로만 한다.** 탄착점은 판정이 끝난 **뒤**, 결과와 모순되지 않게 생성하는 부산물이다. 탄착점으로 명중·구역을 판정하지 않는다.
2. **발사 시점에는 추첨하지 않는다.** 발사 때 사격 품질을 스냅샷으로 저장하고, 착탄 예정 시각에 최종 명중을 **한 번만** 추첨한다. 두 시점에서 각각 추첨하는 방식은 금지한다.
3. 판정 순서: **최종 명중 → (명중 시) 7구역 중 하나 → 탄착점 생성.** 세부 부위는 이번 범위가 아니다.
4. **이중 적용 금지**
   - 관측·식별 품질은 확보 조건(관문)으로만 쓰고 확률에 곱하지 않는다.
   - 표적 기동은 "발사 때 예측 위치와 착탄 때 실제 위치의 차이"로만 반영한다. 그래서 WIP09의 통계적 기동 오차 `σ_man`은 **제거**한다.
   - 자차 이동은 안정화 오차 항에만 넣는다.
5. **발사 후 관측 상실로 자동 실패시키지 않는다.** 착탄 시 차폐는 사수 시야가 아니라 **발사 순간 기록한 포구 위치 → 착탄 시점 실제 표적**의 기하로 판단한다.
6. 차체와 포탑은 각자의 실제 방위로 독립 판정한다. 방향 분배는 360° 연속이어야 하고 0°/360° 경계에서 이어져야 한다.
7. 모든 수치는 **게임 튜닝값**이다. 실제 사통장치·탄도 성능이 아니라고 주석과 문서에 명시한다.
8. 아카이브(`archive/`)는 수정하지 않는다. 아카이브 내용과 코드 사이에 어긋나는 점은 릴리스 문서에 기록만 한다. 이미 알려진 것: 전투 메모 7절 표가 WIP06 기준이라 WIP08/09 상태(사격 존재, 포탑 표본이 실제 포탑 각도 사용)를 반영하지 못함.

## 2. 2단계 판정

### 2-1. 표적 속도 추정 분리

WIP09는 조준 리셋(`resetAim`) 때 `previousSample`·`targetVelocity`도 같이 지운다. 이제 예측 위치가 실제 결과를 좌우하므로 속도 추정을 조준 상태에서 분리한다.
- 속도 추정 상태는 **표적 키가 바뀔 때**, 또는 **자기 포수 관측 간격이 `queryPeriod × 5`를 넘을 때만** 리셋한다.
- 조준 리셋, 발사 간격, 정렬 이탈로는 리셋하지 않는다.
- 계산식은 WIP09와 같다 (`Δpos / Δt`, 자기 포수 관측 pose만 사용, 숨겨진 실제 속도 사용 금지).

### 2-2. 발사 시점 [A] — 추첨 없음

기존 발사 승인·재검증(fresh sight, 정렬, 거리, 탄수, 간격, 보이는 표적 > 0)은 그대로 둔다. 통과하면:

1. **오차 예산 (발사 시)**: WIP09 `errorBudget`에서 `σ_man`을 뺀다.
   - `σx = √(σ_disp² + σ_lay² + σ_lead² + σ_own²)`
   - `σz = √(σ_disp² + σ_lay² + σ_rng² + σ_own²)`
   - `σ_lead`(사통장치 리드 계산 잔차)는 유지한다. 실제 기동 편차와는 다른 항이다.
2. **비행시간**: `ToF = R0 / (muzzleVelocity × velocityRetention)`. `R0`은 WIP09와 같이 사수 차량 중심 → 발사 시 표적 pose 거리.
3. **예측 위치**: `P_pred = pose0.xy + v_obs × ToF` (사통장치의 직선 예측).
4. **조준점**: 발사 시 보이는 직사각형(fresh sight 표본)의 면적 가중 중심 `a = (a_x, a_z)`. 표적 중심 기준 좌표.
5. **탄 방향**: `β_s = atan2(P_pred − origin)`, `origin` = 기존 `G.muzzleWorld`.
6. **스냅샷 저장**: 발사 번호, 시각, 사수 ID, 표적 키, 내부 표적 ID(공개 금지), `origin`, `fireEye`(freshSight가 쓰는 발사선 눈높이), `β_s`, `R0`, `ToF`, `impactAt = now + ToF`, `σx`, `σz`, `P_pred`, `a`, 탄속 값들, `hitChanceAtFire`.
   - `hitChanceAtFire`는 "표적이 예측대로 움직인다"고 가정한 값(편향 0)이다. 기록·표시용이며 추첨에 쓰지 않는다.
7. 탄수 차감, 발사 간격 시작, 조준 리셋은 기존과 같다.
8. 공개 `fired` 이벤트를 남긴다 (5-3절). **난수 소비 0.**

### 2-3. 비행 [B]

- 시나리오 런타임(WeakMap)에 비행 중 탄 목록을 둔다. 시나리오 초기화 때 비운다.
- 고정 스텝(0.05초)마다 `impactAt ≤ 현재 시각`인 탄을 처리한다. 처리 순서는 `impactAt` 오름차순, 같으면 발사 ID 순.
- 일시정지 중에는 진행하지 않는다. 배속이나 프레임 묶음과 무관하게 같은 스텝에서 처리돼야 한다.
- 사수가 이동·선회하거나 관측을 잃어도 비행 중 탄에는 영향 없다.

### 2-4. 착탄 시점 [C] — 최종 추첨 1회

1. **실제 표적 상태**: 시뮬레이션 원본 표적의 현재 pose1(위치, 차체 방위, 포탑 방위). 관측 기록이 아니라 실제 상태다. 표적이 시나리오에서 사라졌으면 결과는 `miss`, 사유 `target-gone`, 4절 탄착점 계산으로 넘어간다.
2. **차폐 재평가**: `exposure(origin, target, fireEye)`로 9개 표본을 다시 계산한다. 포수 FOV·거리 조건은 적용하지 않는다(탄에는 시야각이 없다). 이 표본으로 `presentedRects`를 만든다. 관찰자 위치는 `origin`.
3. **편향**: `d = pose1.xy − P_pred`, 탄 방향 기준 `e⊥ = (−sin β_s, cos β_s)`, `e∥ = (cos β_s, sin β_s)`.
   - 가로 편향 `b = d · e⊥`
   - 거리 편향 `δR = d · e∥`
   - 세로 영향 `δz = −g × R1 × δR / (2 × v_avg²)`, `R1 = |pose1.xy − origin|`, `v_avg = muzzleVelocity × velocityRetention`, `g = 9.81`
4. **평균 탄착 위치** (실제 표적 중심 기준): `μ = (a_x − b, a_z + δz)`
5. **최종 확률**: WIP09 `rectProbability`로 각 직사각형 확률을 구한다. 표준편차는 `Sx = σx × R1 / 1000`, `Sz = σz × R1 / 1000`. `finalHitChance = P_hull + P_turret`(0~1 clamp). 보이는 직사각형이 없으면 0.
6. **추첨**: `random(사수ID:번호:hit)` 1회 → 명중이면 `random(사수ID:번호:zone)`으로 3절 분포에서 구역 1회. 키는 WIP09와 같다.
7. 결과를 4절 탄착점 생성으로 넘기고, 공개 `impact` 이벤트를 남긴다.

## 3. 박스 투영 면적 구역 분배

`distribution()`의 묶음 내부 전/측/후 가중을 박스 투영 면적으로 바꾼다. 차체/포탑 비중(`P_hull`, `P_turret`)은 WIP09 그대로.

- 공격 방향: 착탄 때 **표적 → origin** 방위. 부위별 상대각 `a = diff(공격 방향, 그 부위의 실제 방위)`(차체는 차체 방위, 포탑은 포탑 방위)
- 부위 박스: 차체 `hullLength × width`, 포탑 `turretLength × turretWidth`
- 가중치
  - `front = 폭 × max(0, cos a)`
  - `rear = 폭 × max(0, −cos a)`
  - `side = 길이 × |sin a|`
- 정규화해서 해당 묶음 비중을 곱한다. `upper`는 0 유지.
- 구역 키는 기존 7개 그대로. 측면이 선택되면 결과에 `side: 'right' | 'left'`를 추가한다(`sin a > 0`이면 right, 표적 기준). 측면이 아니면 `null`.

## 4. 탄착점 생성 (표시용)

### 4-1. 표적 평면 좌표 뽑기

표적 평면 좌표계: 실제 표적 중심 기준 가로 `x`(e⊥ 방향), 높이 `z`(표적 지면 기준). 분포는 `N(μ, Sx, Sz)`.

- 정규 난수는 Box–Muller. 균등 난수 키 `사수ID:번호:impact:k:a`, `사수ID:번호:impact:k:b`, `k = 0, 1, 2, …`
- **명중**이면 선택된 구역의 부위(차체/포탑) 직사각형 **안**의 점만 채택
- **빗나감**이면 모든 보이는 직사각형 **밖**의 점만 채택
- 최대 `impact.rejectionAttempts`(64)번 시도. 실패 시 대체값
  - 명중: `μ`를 해당 직사각형 안으로 clamp
  - 빗나감: `(μ_x, 보이는 직사각형 최고 z + 0.25 × Sz)` (윗넘김)
- 이 난수 키는 hit/zone 키와 분리돼 있어 기존 판정에 영향이 없다.

### 4-2. 지면·건물 착탄 위치

- **명중**: 탄착점 = 표적 평면 점 `Q = pose1.xy + x·e⊥`, 높이 = 표적 지면 + z. 종류 `hit`.
- **빗나감**: 발사 지점부터 탄 경로를 따라가며 처음 걸리는 지점을 찾는다.
  - 출발 높이 `H0 = heightAt(origin) + fireEye`, 표적 평면 높이 `Hq = heightAt(pose1) + z`, 수평 거리 `S = |Q − origin|`
  - 수평 거리 `s`에서 경로 높이:
    `h(s) = H0 + (Hq − H0) × s / S + g × s × (S − s) / (2 × v_avg²)`
    (발사점·표적 평면점을 지나는 포물선. `s > S`면 현 아래로 떨어짐)
  - `s = 10m`부터 `impact.marchStepM`(2m) 간격으로 `min(S + impact.maxBeyondM(3000), 지도 경계)`까지 검사. 처음으로 `h(s) ≤ heightAt` 또는 `buildingAt(...)?.roof ≥ h(s)`이 되는 구간을 찾으면 이분법 4회로 다듬는다.
  - 종류: `ground` / `building` / `out-of-map` / `max-distance`
  - `beyond = s − S` (음수면 표적 앞 단탄, 양수면 너머 장탄)
- 숲은 막지 않는다. 숲은 시야용이다.
- 차체를 숨긴 표적에서 가려진 차체 영역으로 들어간 빗나감은 위 계산에서 자연스럽게 앞 능선이나 둔덕에 걸린다. 따로 처리하지 않는다.
- **탄착점은 피해·판정에 쓰지 않는다.** 화면 표시(예광선 끝, 흙먼지, 섬광)와 이벤트 기록용이다.

## 5. 데이터·이벤트·프로파일

### 5-1. 프로파일 (`fireControl`)

- **제거**: `maneuverAccel`, `maneuverReferenceSpeed` (검증에서 폐기 필드로 거부)
- **추가**: `impact: {rejectionAttempts: 64, marchStepM: 2, maxBeyondM: 3000}` (양수 검증)
- 나머지 WIP09 값은 그대로. `data/vehicles/M1A2.json` 재내보내기.

### 5-2. 상태 노출

`fireStatus`/`view`에 `inFlight: [{id, impactAt, remaining}]`(이 사수의 비행 중 탄)를 추가. `lastShot`은 착탄 처리 뒤에 갱신한다.

### 5-3. 공개 이벤트 (아군 팀 필터 유지, 내부 표적 ID 비공개)

- `fired`: `{type:'fired', id, time, team, shooterId, targetKey, origin, muzzleHeading, tof, impactAt, hitChanceAtFire}`
- `impact`: `{type:'impact', id, time, team, shooterId, targetKey, result, zone, side, finalHitChance, hitChanceAtFire, bias:{lateral, radial, dz}, impact:{kind, x, y, z, beyond}}`
- **정보 공개 규칙 (기존 WIP07 원칙 연장)**
  - 착탄 시각에 사수 팀이 그 표적을 **현재 관측 중**이면 명중/빗나감과 구역을 공개한다.
  - 관측 중이 아니면 `result: 'unobserved'`로 공개하고 `zone`·`side`·`bias`와 명중 탄착 좌표는 숨긴다.
  - 빗나간 탄의 지면·건물 착탄점은 흙먼지가 보이는 것으로 보고 공개한다. 단, 명중했는데 미관측이면 좌표를 포함하지 않는다.
  - 내부 기록(테스트용 core 접근)에는 실제 결과를 모두 남긴다.
- 이벤트 보관 한도 200개 유지(`fired`·`impact` 합산).

## 6. 패널·화면

- 기존 두 줄(`fireDetails`의 "예상 명중 …" 줄 + `hitSummary`)을 **한 줄**로 합친다.
  예: `예상 명중 76% (발사 시) · 오차 0.38밀 · 표적 3.7×1.9m · 명중 시: 차체 전 38% / 차체 측 4% / 포탑 전 57%`
- 비행 중: `비행 중 · 착탄까지 0.8초`
- 결과: `최근 단발: 명중 · 차체 측(우)` / `빗나감 · 표적 너머 340m 지면` / `빗나감 · 표적 앞 12m 지면` / `결과 미확인`
- 미식별·기억 접촉에는 기존처럼 숨긴다.

- 공개 규칙에 따라 숨긴 좌표는 그리지 않는다.

## 8. 테스트

**단위**
- 7절 표 전부 통과
- 발사 시 난수 소비 0, 착탄 시 hit·zone 각 1회. 탄착점 키는 별도 스트림
- 탄착점: 합성 상황에서 시드 1000개로 돌려서, 명중은 전부 선택 부위 직사각형 안, 빗나감은 전부 밖. 대체값 경로도 강제로 한 번 검증
- 구역 분배: 0°/360° 연속성, 확률 합 1, `upper` 0, side 부호
- 경로 계산: 평지에서 위로 빗나간 탄은 `beyond > 0`, 아래로 빗나간 탄은 `beyond < 0`. 건물 앞을 지나면 `building`

**통합**
- 같은 시드·명령 → 같은 `fired`/`impact` 결과. 1×/4× 배속과 프레임 묶음이 달라도 동일
- 착탄 처리는 `impactAt` 이후 첫 고정 스텝
- 발사 직후 사수가 포탑을 돌려 관측을 잃어도 착탄은 정상 처리
- 발사 직후 표적이 엄폐물 뒤로 완전히 들어가면 `finalHitChance` 0, 빗나감 착탄점이 엄폐물에 걸림
- 발사 직후 표적이 정지하면 횡단 표적 명중률이 크게 떨어짐(7-2와 같은 경향)
- 미관측 착탄 → `unobserved` 공개, 좌표 숨김
- 일시정지 중 비행 진행 없음, 시나리오 초기화 시 비행 중 탄 삭제
- 기존 LOS·관측 결과 대조 fixture 동일. 기존 Node·Chromium 테스트 통과. 바뀐 테스트는 사유를 릴리스 문서에 적는다

## 10. 판단이 애매할 때

- 이 지시서와 아카이브 원칙이 충돌하면 **아카이브 원칙이 우선**한다. 충돌 내용은 릴리스 문서에 적고, 멈추지 말고 보수적으로 처리한다.
- 지형, 시야 LOS 알고리즘, 관측 확률, 길찾기, 도안은 바꾸지 않는다. 바꿔야 할 것 같으면 바꾸지 말고 기록만 한다.
- 수치를 임의로 "더 현실적으로" 조정하지 않는다. 표의 초깃값을 그대로 쓴다.
