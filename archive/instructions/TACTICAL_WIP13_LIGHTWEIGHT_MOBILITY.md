## 2. 확인한 문제와 현재 코드

### 2.1 전후진 반전은 실제 이동 오류다

`src/sim-core.js`의 `issueMove()`는 후진 요청을 즉시 `u.reverse`에 저장한다. `stepTank()`는 양수인 `u.speed`를 유지한 채 이 플래그로 위치 변화의 부호를 뒤집는다. 제동을 거쳐 실제 진행 방향을 바꾸는 단계가 없다.

기준 main의 **실제 이동 적분기**를 평탄한 합성 도로에서 실행해 확인한 사례:

| 조건 | 명령 직전 실제 전진 속도 | 후진 명령 뒤 첫 0.05초의 실제 후진 속도 |
|---|---:|---:|
| 약 40km/h 주행 | 40.164km/h | 40.234km/h |
| 약 60km/h 주행 | 60.014km/h | 59.474km/h |

후진 속도 상한을 넘은 채 반대 방향으로 이동한 뒤 감속하는 경우도 있다. **표시 문구나 속도 상한만 수정해서 완료로 처리하지 않는다.**

### 2.2 함께 확인할 기존 한계

- `src/vehicle-profiles.js`의 질량·엔진 출력은 현재 제원 표시에 쓰이며 `driveAcceleration()`은 별도의 단순 가속 곡선을 사용한다.
- 현재 마지막 경유점에 가까워지면 `u.speed=0`으로 즉시 정지하는 분기가 있다. 정상 도착의 감속과 도착 판정을 연결한다.
- 현재 선회는 속도에 따라 줄어드는 각속도 제한과 목표 방향 오차를 사용한다. 경로를 바꿨을 때 급격한 속도 방향 전환이나 불필요한 제자리 회전이 생기는지도 검증한다.
- `tests/vehicle.test.cjs`는 정지 상태에서 후진 출발과 최고속도 등을 검사한다. **이미 전진 중인 상태에서의 후진 전환** 검사를 추가해야 한다.

**TACTICAL의 현행 프로파일을 이번 제원 기준으로 사용한다.**

1. 질량·출력·도로/야지/후진 상한·가속 기준·경사 기준의 원본은 현재 차량 프로파일과 해당 JSON의 출처 기록이다. Tank_Project의 질량 설정이나 과거 인증용 설정을 그대로 덮어쓰지 않는다.
2. 질량과 출력이 실제 구동 계산에 영향을 주게 한다. 동일한 구동 설정의 합성 비교에서 질량 증가/출력 감소가 가속을 더 좋게 만들지 않아야 한다.
3. 출처가 있는 기존 성능 기준점은 유지한다. 새로 필요한 저속 구동 한계·손실·변속 시간·조향/제동 계수는 **경량 게임 모델의 근사값**으로 구분하고 이유와 단위를 적는다.
4. 변속 단수는 내부 전진 4단·후진 2단 표를 기본으로 한다. 출발 단수·변속 조건과 기어비의 출처/근사 여부를 기록한다. 중립·방향 전환 대기·제자리 선회는 별도의 운전 상태로 구분한다.
5. 자료가 없는 전체 엔진/변속기 성능 맵을 실측처럼 만들어 넣지 않는다. 기존 가속 기준 한 점에 맞았다는 사실을 모든 실차 주행 특성이 검증된 것으로 표현하지 않는다.
6. 런타임·내보낸 JSON·제원 UI가 같은 프로파일을 가리키게 한다. 공통 모델에 특정 차량의 상수를 직접 박아 넣지 않는다.

## 4. 경량 구동 모델의 필수 동작

### 4.1 실제 상태와 명령을 분리

- 실제 진행 방향을 가진 종방향 속도 또는 이에 동등한 단일 권위 상태를 둔다. 이동/후진 요청, 현재 구동 방향, 실제 속도, 현재 단수·변속 대기를 구분한다.
- 기존 `u.speed`를 양수 크기의 호환 값으로 유지하거나 부호 있는 값으로 바꾸는 선택은 가능하다. 어느 쪽이든 위치 적분·UI·관측·이동 사격·제동·정지 판정에 서로 다른 속도가 사용되지 않게 한다.
- 방향 요청 플래그를 바꾸는 것만으로 실제 속도 벡터나 위치 변화가 반전되어서는 안 된다.
- 새 명령을 받았다는 이유로 속도·회전 상태를 초기화하지 않는다. 정지·역방향·경로 재지정을 반복해도 일관되게 수렴해야 한다.

### 4.2 전진과 후진의 전환

1. 반대 방향 요청을 받으면 반대 방향 구동을 차단하고 현재 이동 방향으로 제동한다.
2. 정지로 볼 수 있는 작은 실제 속도와 필요한 전환 대기 조건을 충족한 뒤 새 방향을 연결한다. 허용 오차와 대기 시간은 데이터/설명에 둔다.
3. 이후 새 방향으로 가속한다. 전환 대기 중 이전 방향 구동이 다시 연결되어 앞뒤로 튀지 않게 한다.
4. 제동 중 새 경로·목표 방향 때문에 진행 방향이 갑자기 뒤집히거나 큰 차체 회전이 강제되지 않게 한다.
5. 전후진 요청을 다시 바꾸거나 정지 명령을 내려도 오래된 전환 예약이 남지 않아야 한다. 완전히 정지한 상태에서의 출발도 검사한다.

### 4.3 가속·자동변속·제동

- 질량·출력, 현재 속도와 선택 단수, 작은 구동력/손실 표로 가속을 계산한다. 저속 구동 한계와 고속 출력 한계를 이어 0속도 나눗셈과 비정상적인 출발 가속을 막는다.
- 기어가 표시 숫자로만 바뀌지 않고 구동력 또는 회전 상태에 실제로 영향을 주게 한다. 변속 전후 속도/위치의 불연속이나 운동 에너지의 갑작스러운 생성이 없어야 한다.
- 자동변속에는 상향·하향 조건 차이와 최소 유지 시간을 두어 경계에서 단수가 매 틱 왕복하지 않게 한다. 같은 명령·고정 틱에서는 결과가 결정적이어야 한다.
- 정상 제동은 유한한 감속으로 처리한다. 0을 지나 반대 방향으로 밀리는 현상, 정차 떨림, 정상 도착 때의 순간 정지를 없앤다.
- 도로/야지/후진 속도 상한은 기존 명목 기준으로 유지하되, 노면 전환이나 낮은 속도 목표로 인해 실제 속도를 즉시 잘라내지 않는다. 정상 상태의 상한과 과도 감속 구간을 구분한다.
- 경사·노면은 기존 높이장/노면 자료를 사용한다. 기존 경사 속도 기준과 새 저항을 어떻게 함께 적용하는지 명시하고 같은 효과를 중복으로 과도하게 감산하지 않는다.
- 내리막 무한 가속·정차 중 크리프를 방지한다. 자동 정차 유지 같은 게임용 근사는 문서화한다.
- 격파나 실제 충돌 방지의 안전 정지는 정상 도착 제동과 구분한다. 이번 작업 때문에 충돌체 통과나 파손 차량 재출발을 허용하지 않는다.

### 4.4 조향·경로 추종

- 속도에 따른 회전 반경/각속도와 조향 반응을 연결한다. 빠르게 달리던 차량이 즉시 제자리 선회를 시작하거나 차체 방향만 바꿔 속도 방향을 급전환하지 않게 한다.
- 저속·정차 시 제자리 선회를 지원하고, 큰 방향 전환은 필요한 감속과 연결한다. 후진에서도 차체 앞뒤와 경로 진행 방향이 일치하는지 검사한다.
- 좌우 구동 차이를 소수 값으로 근사할 수 있다. 개별 궤도·차륜 객체나 접촉 반복 해법은 필요하지 않다.
- 기존 경로 탐색·경유점·충돌 검사를 재사용한다. 경유점마다 급하게 꺾이거나 장애물 앞에서 전후진/회전을 반복하지 않게 한다.
- 짧은 이동·가까운 목표로 재지정·도착 직전 정지에서도 물리적 제동을 먼저 처리한다. 도착 허용 거리·속도를 함께 사용하고 보정을 위한 순간 이동/방향 반전은 만들지 않는다.
- 차체/포탑의 기존 독립 제어와 경계·교전 임무를 유지한다. 차체 선회가 포탑을 무조건 같은 각도로 돌리는 회귀를 만들지 않는다.

## 5. 계산 비용·기존 기능과의 연결

- 기본 갱신은 현재의 **0.05초 고정 틱**을 유지한다. 프레임마다 별도 구동 적분이나 240Hz 반복을 추가하지 않는다. 수치 안정성은 이 시간 간격에 맞춘 작은 상태 전이·보간·해석적 제한으로 확보한다.
- 차량당 상태와 구동 표의 크기를 고정하고, 구동 갱신은 일정량의 산술/조회로 끝낸다. 변속·엔진·조향마다 새 지형 샘플, LOS, 경로 탐색을 반복하지 않는다.
- 기존에 얻은 노면/경사 값을 공유하고, 변경할 필요가 없는 표는 한 번 준비한다. 매 틱 불필요한 객체·배열 생성이나 전역 차량 쌍 순회를 추가하지 않는다.
- 1배속/2배속·일시정지·프레임 묶음에서 같은 고정 틱 수라면 동일한 이동 상태가 되어야 한다. 초기화·격파 시 구동·변속·대기 상태를 함께 정리한다.
- UI의 후진 버튼은 요청 모드다. 실제로 전진 제동 중이면 ‘감속/후진 대기’처럼 현재 상태를 표시하고 즉시 ‘후진 40km/h’로 표시하지 않는다. 요청 모드와 현재 단수/진행 상태는 혼동하지 않게 한다.
- 기어 표시가 필요하면 기존 상태/정보 영역에 작게 추가한다. 새 수동 변속 패널·RPM 관리 미니게임은 만들지 않는다. 렌더러가 구동 상태를 갱신해서는 안 된다.
- 관측 속도 추정과 이동에 따른 기존 사격 계산은 실제 이동과 같은 상태를 사용한다. 이동이 바뀐 경우의 전투 결과 변화와 사격 확률식 자체의 변경을 구분한다.
- WIP11E의 LOS·9표본·2m 지형 정밀도·관측 주기, WIP12의 효과 연결/입자 우선순위·확률 결과/도탄 추가 피해 없음·정보 공개를 유지한다.
- 구동 함수는 팀과 분리해 재사용 가능하게 하되, 이번 시나리오에 적 자율 이동 명령을 추가하지 않는다.
- 새 모듈을 분리하면 단일 HTML 빌드, Node 로더, 실제 Worker 번들 모두의 로딩 순서와 의존성을 함께 갱신한다. 외부 파일 요청 없이 오프라인 실행되어야 한다.

## 6. 검증과 완료 기준

실제 실행 경로를 검사한다. 새 함수만 호출한 결과나 UI 문구만으로 전환 버그의 해결을 주장하지 않는다. 기준 main과 변경 후의 코드/실행 조건을 함께 보존한다.

### 6.1 필수 동작 검사

| 항목 | 확인할 결과 |
|---|---|
| 주행 중 전후진 전환 | 앞 절의 약 40/60km/h 사례와 후진→전진을 실제 적분기로 재현. 월드 위치 변화로 측정한 진행 속도가 제동·정지·재가속 순서를 따름 |
| 명령 번복 | 제동/변속 대기 중 전후진 재요청·정지·다른 목표 지정에 오래된 예약이나 반복 튐이 없음 |
| 가속과 제원 | 현행 평지 가속 기준·도로/야지/후진 정상 상한을 확인. 질량·출력의 인과 관계도 별도 합성 조건에서 확인 |
| 변속 | 정지 출발·상향/하향·경계 유지에서 구동 연결이 작동하고 단수 진동·속도 점프·NaN이 없음 |
| 정상 제동과 도착 | 고속 정지·짧은 이동·가까운 목표 재지정에서 연속 감속. 도착 직전 강제 속도 0이나 위치 보정이 없음 |
| 선회 | 정차 선회·저속 직각 경로·고속 큰 방향 전환·후진 굽은 경로에서 회전/감속이 자연스럽고 도착 가능 |
| 지형과 장애물 | 평지·오르막/내리막·도로/야지 경계·좁은 장애물 주변에서 충돌·통과 가능 경사 규칙 유지 |
| 상태·결정성 | 정지 유지·초기화·격파, 같은 고정 틱의 1배속/2배속·일시정지에서 상태·위치가 일치 |
| 기존 시스템 | 차체/포탑 독립·경계·표적 속도 추정·이동 사격·LOS·이펙트가 실제 게임 루프에서 연결됨 |

- 평탄한 합성 지형은 구동 자체를 분리하는 데 쓰고, 실제 지도 검사도 함께 수행한다.
- 가속/정지 시간·거리, 최대 감속/각속도, 변속 횟수 등 필요한 작은 시계열을 남긴다. 측정 조건·단위·허용 오차는 결과를 보고 임의로 느슨하게 바꾸지 않는다.
- 기존 이동 기준이 의도적으로 달라지는 검사는 변화의 이유와 새 물리 계약을 설명한다. 버그를 재현하던 검사를 삭제하거나 결과 스냅샷만 교체해서 통과시키지 않는다.
- 정지 차량·같은 자세를 사용하는 전투 검사는 기존 판정 유지가 기준이다. 실제 경로/속도가 달라진 이동 장면은 같은 seed만으로 이전 모든 명중 결과까지 같아야 한다고 요구하지 않는다.
- 단위/실제 적분기 검사와 **실제 Chromium UI 조작**을 모두 수행한다. 최소한 이동 중 후진 요청·제동·새 방향 출발, 정차·선회, 1배속/2배속을 기록한다.

### 6.2 성능 검사

- 새 구동 함수 자체는 1대/100대의 동일 입력 묶음으로 준비 운동 후 반복 측정한다. 중앙값·P95와 실행 환경을 기록한다.
- **경량 목표:** 이 환경에서 차량 100대의 구동 계산 한 틱 비용이 중앙값 1ms 이내가 되도록 한다. 충돌/경로 탐색/관측을 제외한 측정임을 명시하며 전체 게임 성능과 혼동하지 않는다.
- 실제 지도에서도 기존 이동 다수 차량 조건을 재사용해 변경 전후 전체 틱·구동·LOS/관측·렌더 비용과 경로 탐색 횟수를 기록한다. 조건·반복 횟수·표본 수를 같게 한다.
- 새 궤적 때문에 관측량/경로가 달라지면 그 차이를 보고한다. 서로 다른 경로의 전체 비용 차이를 전부 구동계 비용으로 귀속하지 않는다.
- 성능 목표 초과나 지속적인 프레임 악화가 있으면 원인을 줄이고 재측정한다. 전체 작업을 임의의 다른 최적화 과제로 확대하지 않는다. 실제 기기에서 측정하지 않은 결과를 모바일 실측이라고 쓰지 않는다.

### 6.3 회귀·산출물
