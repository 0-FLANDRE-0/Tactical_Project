## 2. 현재 동작과 이번에 바꿀 부분

- WIP14는 이미 적의 이동/순찰, `maintain/halt/auto`, 실제 제동·정차·재개, 0.75초 분산 판단과 경로 요청 예산을 구현했다. 이들 자체를 새 기능으로 보고하지 않는다.
- 현재 AI의 `ownContact()`는 가장 최근에 관측한 자체 식별 접촉을 고른다. 반면 실제 포수 표적은 observation의 지정/추적·인계가 결정한다. **AI가 멈추게 한 접촉과 실제 사격 표적이 서로 달라질 수 있는 구조를 정리한다.**
- 현재 자체 식별 접촉이 있기만 하면 정차 정책이 반응할 수 있다. 전차장 시야에는 들어오지만 주포 사거리 밖인 접촉 때문에 계속 멈추는 경우를 막는다.
- 실제 발사 권한은 계속 fire-control이 가진다. AI의 후보 선택은 탐지·식별·포수 확보·정렬·조준·장전·현재 발사선을 대신하지 않는다.
- WIP15 이후 고정 틱 순서는 **이동 → 도착 비행체/피해/일시 이상 → 관측 → AI → 장전/조준/새 발사**다. WIP14 문서의 이전 순서를 그대로 복사하지 않는다.

## 3. 관측 입력과 표적 선택

### 3.1 사용할 수 있는 정보

- 판단 입력은 해당 차량의 자체 관측 접촉 사본, 자체 위치/실제 속도, 자기 프로파일·탄약/장전·일시 이상 상태, 기존 임무와 현재 교전 상태로 제한한다.
- 자동 후보는 **자체 현재 관측·식별·적 확인**이 있고 유효한 관측 위치가 있으며, 자체 관측으로 잔해/격파가 확인되지 않은 접촉이다. 관측 시스템의 현재성 계약을 따른다.
- 후보 거리는 관측 사본의 위치로 계산하며 주포와 포수의 최대 사거리 중 작은 값 이내여야 한다. 전차장만 현재 관측한 표적은 정상 인계를 거쳐 확보할 후보일 뿐 즉시 발사할 수 있는 표적은 아니다.
- 팀 공유 정보만 있거나 기억만 남은 표적은 새 자동 사격 후보로 삼지 않는다. 기존 유예 중 위치 기억은 관측 시스템의 기존 규칙대로 사용할 수 있다. 사용자 직접 지정의 기존 팀 정보 전달 경로도 유지하되 자체 확보 전 발사는 허용하지 않는다.
- 상대 실체 배열의 좌표·HP·현재 명령·조준 방향·실제 격파 여부·탄약·이상 타이머를 읽지 않는다. 미관측 적 사격 효과도 새 식별 접촉이나 사수 신원으로 바꾸지 않는다.

### 3.2 우선순위와 유지 규칙

- 유효한 플레이어 직접 지정은 자동 점수보다 우선한다. 수동 지정 변경/취소는 AI 유지시간 때문에 지연되지 않는다. 기존의 실제 관측/발사선 상실에 따른 정상 인계·만료 규칙을 유지한다.
- 자동 후보의 초기 점수는 `1 - clamp(관측 거리 / 자체 유효 최대 사거리, 0, 1)`에 **자체 포수 현재 관측 +0.15**, **현재 선택 표적 유지 +0.15**를 더한다. 적의 숨은 상태를 참조하지 않는 가벼운 시험 규칙이다.
- 처음 고르거나 기존 표적이 유효성을 잃은 경우에는 최선의 유효 후보를 고른다. 동점이면 자체 최초 식별 시각이 빠른 후보, 이후 안정된 접촉 key 순으로 결정한다. 누락된 식별 시각의 처리도 결정적으로 정의한다.
- 현재 자동 표적이 유효하면 §5의 최소 유지시간을 지키고, 다른 후보가 점수 차이와 연속 판단 조건을 모두 만족할 때만 바꾼다. `lastSeen`의 작은 차이만으로 표적을 계속 바꾸지 않는다.
- 관측 상실 유예 중 동일 표적이 돌아오면 정상 흐름으로 이어간다. 새로운 유효 후보로 전환할 수 있는 조건과 기존 표적의 유예를 구분하고, 한 후보를 골랐다가 다음 관측 틱에서 이전 후보로 되돌리는 순환을 방지한다.
- 포수 확보·조준·정렬 대기나 장전만으로 표적을 버리지 않는다. 기존 발사선 검사에서 차폐가 확인된 표적은 정상 인계 경로와 재선택 대기를 사용한다. 후보마다 새 LOS를 쏴서 점수를 매기지 않는다.

### 3.3 소유권과 실제 연결

- 선택 결과를 실제 observation의 자동 지정/인계 경로에 연결하고, 이동 AI도 같은 선택/확보/상실 상태를 사용한다. UI나 디버그 변수의 표적 key만 바꾸는 구현은 완료로 보지 않는다.
- `C.designate()`의 공개 직접 지정은 현재 `manual` 출처다. AI가 이를 그대로 호출해 자신의 표적을 플레이어 지정으로 가장하지 않는다. 필요한 내부 자동 인계 진입점을 두고 출처·소유권을 보존한다.
- 새 AI 선택과 기존 observation 자동 후보 큐/헌터킬러/발사선 상실 인계 사이에 표적 결정 소유자를 명시한다. 서로 매 틱 지정해서 조준·획득 시간이나 재시도 대기를 초기화하지 않는다. 동일 표적/동일 명령은 다시 지정하지 않는다.
- 실제 표적 전환 때만 기존 조준 리셋·표적 속도 추정 규칙을 적용한다. 전환 중에는 정상 선회·확보·조준을 기다리며, `acquired/current`를 임의로 만들지 않는다.
- AI는 기존처럼 명시적으로 활성화된 차량에 붙인다. 임의 `makeTank()`와 AI를 쓰지 않는 기존 fixture의 자동 인계 정책까지 조용히 바꾸지 않는다. 양 팀에 AI를 명시 적용한 경우에는 같은 규칙을 사용한다.

## 4. 교전 상태와 기본 임무

| 상황 | 요구 동작 |
|---|---|
| 활성 교전·상실 유예 없이 유효 후보 없음 | 기존 이동/순찰 임무 수행. 사거리 밖 식별 접촉만으로 정차·추격하지 않음 |
| 유효 후보 있음·이동 유지 정책 | 같은 기본 경로를 유지하며 정상 인계·사격 수행 |
| 유효 후보 있음·정차 정책 | 현재 임무/경유점 보존 → 실제 제동 → 기존 정차 유지 조건 뒤 자동사격 허용 |
| 자체 관측/사거리 조건 상실 | 새 발사는 공통 관문에서 즉시 차단. 기존 유예·관측 대기 후 유효 후보가 없으면 같은 기본 임무 재개 |
| 다른 유효 후보로 인계 | 같은 교전 정차를 유지해 확보·조준 진행. 표적 전환마다 기본 이동을 잠깐 재개하거나 제동 명령을 반복하지 않음 |
| 기존 정상 발사선 검사에서 차폐 확인 | 대안이 있으면 정상 인계. 알려진 후보가 모두 차폐되면 제한된 상실/관측 대기 뒤 기본 임무로 복귀. 새 엄폐 해소 경로·무제한 재선택을 만들지 않음 |
| 장전 중·장전탄 없음 | 남은 총탄이 있으면 임무/표적을 보존하고 장전 대기. 탄약 소진으로 분류하지 않음 |
| 관측장비 이상 | 정상 관측·확보 유지, 기존 조준 속도 0.70배/오차 1.25배 적용. 이상 자체로 상실/복귀하지 않음 |
| 사통 일시 이상 | 정상 교전 상태·표적·장전 보존, 기존 조준/새 발사 정지와 자동 복구 대기. 이를 영구 교전 불능이나 새 이동 명령으로 바꾸지 않음 |
| 총탄약 소진 | 자동교전 정차를 해제하고 유효한 기본 임무 재개. 재보급·후퇴 경로를 새로 만들지 않음 |
| 취소·새 이동 명령·임무 교체·격파 | 이전 교전/재개 상태와 억제를 정리. 완료·취소된 임무를 재생하지 않음 |

- `maintain/halt/auto`는 기존 의미를 유지한다. `auto`는 차량의 기동간 사격 가능 여부와 임무의 이동/정차 선호를 사용한다. 사격 명중률에 따른 새 확률적 정차 정책은 후속이다.
- 임무 ID/갱신 번호·경유점·완료 여부와 일시 교전 상태를 분리한다. 완료된 단일 이동 임무는 현 위치에서 교전할 수 있지만 상실 뒤 없는 경유점을 찾아 재출발하지 않는다.
- 교전 중 사용자가 임무를 바꾸면 최신 임무가 유효하다. 재관측을 여러 번 거쳐도 최초의 유효한 재개 상태를 보존하고 실제 복귀는 한 번만 수행한다.
- AI의 자동사격 억제, 플레이어의 `auto/hold`, 차량 능력에 따른 정차 필수 조건은 별개다. AI 판단이 `hold`를 `auto`로 바꾸거나 수동 발사 관문을 우회하지 않는다.
- 정차 정책의 즉시 자동사격 억제는 기존처럼 가벼운 매 틱 안전 조건으로 처리한다. 실제 속도와 정차 유지 조건은 최종 발사 직전에 다시 검사한다.
- 범위 이탈/재진입·접촉 깜빡임·차폐 반복에서 매 틱 정지/재개를 내리지 않는다. 임무 복귀는 상실 대기 종료라는 사건으로 한 번 처리하며, 동일 목표/path가 남으면 새 경로 요청을 하지 않는다.

## 5. 초기 시험 설정·실행 비용

아래 추가 계수는 **조정 가능한 초기 게임 튜닝 제안**이다. 실제 승무원 판단 시간이나 사용자 확정 밸런스로 설명하지 않는다. 구현 문서에 최종값·변경 이유·단위를 기록한다.

| 항목 | 초기 기준 |
|---|---|
| 일반 판단 | 기존 0.75초·차량 ID별 결정적 위상 유지 |
| 자동 표적 최소 유지 | 2.25초. 유효성 상실·사용자 명령·확인한 격파에는 적용하지 않음 |
| 더 나은 후보로 전환 | 현재 점수보다 0.20 초과 우위가 같은 후보에서 2회 연속 판단될 때, 최소 유지시간도 만족 |
| 상실 유예·관측 대기 | 기존 1.5초 + 2.5초 유지. 두 시간을 중복 누적하거나 장전/일시 이상을 상실 시간으로 세지 않음 |
| 차폐로 버린 자동 후보 재선택 | 같은 기하 상태에서는 최소 2초. 실제 새 관측/기하 변경 때 무효화 기준을 기록하며 사용자 직접 지정은 지연시키지 않음 |
| 새 AI 경로 요청 | 기존 전체 AI 틱 예산 2건·실패 재시도 2초 유지. sim-core 자체 재계획 비용과 구분해서 측정 |

- 후보 평가는 해당 차량의 자체 접촉 수에 비례하는 작은 순회로 구현한다. 매 프레임 전체 유닛 쌍 평가·전체 지도 비용장·새 LOS·후보별 경로 탐색을 추가하지 않는다.
- 판단 입력을 얻기 위해 UI용 전체 snapshot·비행체 배열·깊은 복사를 차량마다 만들지 않는다. 필요한 자기 상태만 읽는 작은 인터페이스를 사용한다.
- 결정 시각은 시뮬레이션 시간이다. pause/배속·렌더 빈도·UI 조회 횟수가 선택/전환 결과에 영향을 주지 않으며, 결정적 동점 처리에 새 난수가 필요하지 않다.
- 매 판단의 결과와 실제 변경 사건을 구분한다. 디버그 기록은 선택/전환/교전 대기/복귀 원인, 명령 횟수와 경로 요청을 검증할 수 있게 제한된 크기로 남긴다. 같은 결정을 반복 로그로 무한 축적하지 않는다.
- 적의 표적 우선순위·내부 임무·대기시간·경로·숨은 상태는 공개 snapshot/효과/UI에 노출하지 않는다. 제품에 점수표나 디버그 조작 패널을 새로 만들 필요는 없다.

## 6. 시나리오와 필수 검증

현재 작은 시험장에 맞는 고정 배치·seed·재현 명령을 준비한다. 시나리오 선택 UI는 필수가 아니며 공개 제품에 결과 강제/적 내부 상태 조작 기능을 넣지 않는다.

| 검증 묶음 | 반드시 확인할 사례 |
|---|---|
| 기본 교전 | 1대1에서 인계→확보→조준→장전→반복 사격. 이동 유지와 실제 제동/정차 정책 각각 검증 |
| 복수 표적 | 2대2에서 가장 최근 접촉만 따르지 않고 점수/유지 규칙으로 선택. AI 결정 표적·실제 포수 임무 일치, 완전 동점·관측 갱신 순서 변경에서도 결정성 |
| 명령 소유권 | 유효한 수동 지정 우선, 자동 출처 보존, AI 재지정으로 조준 초기화 반복 없음. 지정/취소/임무 교체 즉시 유효 |
| 정보 경계 | 팀 공유만/기억만/미식별은 자동 후보 제외. 적 숨은 좌표·HP·장전·이상·미관측 격파를 바꿔도 관측 입력이 같으면 결정 동일 |
| 사거리·차폐 | 전차장만 볼 수 있는 사거리 밖 접촉으로 영구 정차하지 않음. 범위 경계 반복·차폐→다른 표적 인계·모든 후보 차폐→복귀, 후보 점수 평가의 추가 LOS 없음 |
| 상실·재관측 | 상실 유예·관측 대기·재관측·재상실 후 같은 유효 임무/경유점으로 한 번 재개. 매 틱 정지/재개·경로 재요청 없음 |
| 장전·일시 이상 | 총탄은 있지만 장전 중인 상태, 마지막 탄·총탄 0, 관측 이상 6~8초, 사통 이상, 복합/반복 이상. 표적·임무 보존과 정상 복귀, 추가 만료/재시도 없음 |
| 수명 회귀 | 완료 임무 부활 방지, halt→maintain/auto 임무 교체 시 억제 해제, 취소·격파 뒤 예약된 재개 없음, 수동/자동·양 팀 최종 발사 관문 유지 |
| 시간·개수 | 같은 seed에서 pause/1배/2배/다른 렌더·조회 횟수 결과 동등. 최소 유지·연속 우위 경계, 표적 전환/정지/재개/신규 경로의 정확한 사건 횟수 |

- 순수 선택/상태 검사와 독립 실제 sim-core 검사를 모두 둔다. 실체를 제자리에서 바꾸거나 `current/acquired`를 강제로 참으로 만든 검사만으로 실제 연결을 증명하지 않는다.
- 실제 Chromium에서 복수 표적 선택·인계, 정차와 이동 유지, 상실 뒤 임무 복귀, WIP15의 관측 이상 중 사격 지속과 사통 복구를 확인한다. 기존 입력/Worker·미관측 사격·예광·잔해 회귀를 유지한다.
- 50/100대 자체 관측 fixture에서 선택 비용, 실제 결정·전환·명령 횟수, 중앙값/P95를 측정한다. 순수 100대 판단의 기존 1ms 경량 목표를 유지하고, 동일 조건의 WIP15 main과 비교한다. 측정에는 후보 수·판단 주기·준비/측정 시간·반복·환경을 기록한다.
- 판단 주기 동안 모든 활성 차량이 실제로 평가되는지 확인한다. 판단을 건너뛴 틱만 측정해 선택 비용으로 보고하지 않는다. 유효 후보가 여러 개 있는 사례와 실제 표적 전환 사례도 포함한다.
- 실제 지도 전체 틱도 같은 배치/seed로 비교하고 LOS·경로 요청 수를 확인한다. 선택 변화에 따라 교전·격파·생존 관측자가 달라지는 비용과 순수 AI 비용을 구분한다. 실측 없이 전체 FPS 개선이나 모바일 성능을 주장하지 않는다.
- 저장소의 Node·실제 Chromium·Python 지형/소스 필수 검사와 빌드를 수행한다. 의도적으로 바뀐 자동 표적 기대값은 이유를 적고, 기존 정보 경계·조준·발사·임무 수명 검사를 삭제하거나 약화하지 않는다.
