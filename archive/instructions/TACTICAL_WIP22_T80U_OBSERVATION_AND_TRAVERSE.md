## 3. 초기 프로파일 값

모든 각도는 아래 표에서는 **전체각/도**, 런타임에서는 저장소 관례대로 라디안·초·m로 변환한다. FOV 90°는 좌우 각각 45°다.

| 항목 | 이번 적용값 | 성격 |
|---|---:|---|
| 포탑 최대 선회 | 24°/s | T-80U 2차 자료 기반 채택값 |
| 전차장 큐폴라 최대 선회 | 40°/s | PNK-4S 2차 자료 기반 채택값 |
| 전차장 관측 | 2,000m / 게임 FOV 90° | 초기 게임 시험값 |
| 포수 관측 | 2,000m / 게임 FOV 30° | 초기 게임 시험값 |
| 전차장/포수 관측점 높이 | 지면 위 2.50m / 2.15m | 외형 근사·게임 시험값 |
| 주변 인지 | 200m / 360°, 실루엣까지만 | 공통 RTS 근거리 인지의 명시적 채택 |
| 전차장 자동 탐색 | 차체 기준 ±180°, 주기 90초, 속도 상한 12°/s | 초기 게임 시험값 |
| 포수 자동 탐색 | 차체 기준 ±30°, 주기 24초, 속도 상한 8°/s | 초기 게임 시험값 |
| 전차장 인계 대기 | 식별 후 자격 유지 0.50초 | 초기 게임 시험값 |
| 포수 자체 관측 확보 | 연속 유효 관측 0.40초 | 초기 게임 시험값 |

- 거리·FOV는 **게임 탐색 영역**이다. 실제 광학계 배율·시야각에서 직접 변환한 값 또는 실측 주간 최대거리로 표기하지 않는다. 값이 M1A2와 같은 항목도 T-80U 데이터에 명시하고 소유권을 분리한다. M1A2의 기존 값을 바꾸지 않는다.
- `T80U_1989`에 관측 장비 명칭, 탐색 범위/주기/속도, 추적 최대속도, 인계·확보시간과 근거를 명시한다. 발견/식별 증거·기억·확보 만료 등의 나머지 절차는 현재 공통 게임 규칙을 명시 참조해 시작한다. 새 탐지 보정 배율/무근거 성능 우열을 추가하지 않는다.
- 탐색은 고정 틱·seed 기반 초기 위상으로 결정적이다. 차체 기준의 탐색 중심/주기 목표를 기존 방식으로 계산하되 실제 방향 변경은 탐색속도 상한을 통과한다. 표적 지시/추적 때만 장비 최대 선회 상한을 사용한다. 주기 목표에 늦었다고 순간 이동해 따라잡지 않는다.
- 큐폴라 40°/s를 포탑에 적용하거나 12°/s 탐색 상한을 모든 추적에 적용하지 않는다. 제어/관측/그림은 같은 `u.turret`, `u.commander` 월드 방위를 사용한다. 포탑 포수 광학축의 별도 미세 선회·포신 고저각은 이번에 추가하지 않는다.

## 4. 관측만 켤 수 있도록 능력·검증 분리

현재 WIP21 레지스트리는 관측·구동·발사·AI 중 하나라도 활성화하면 나머지도 모두 요구한다. `Observation.control`은 포탑 속도를 `p.mobility.turretRate`에서 읽는다. **이 두 결합을 풀되 기존 운용 차량의 검증을 약화하지 않는다.**

- 프로파일 수준의 `target=true, observation=true, mobility=false, fire=false, ai=false`를 정상 지원한다. 포탑/큐폴라의 선회 설정을 관측/선회 프로파일에 둔다. M1A2의 기존 `mobility.turretRate` 읽기는 호환해 기존 수치·동작을 보존하되 T-80U를 위해 가짜 엔진·변속기·차량 이동 설정을 생성하지 않는다.
- 관측 활성에는 센서/탐색·선회/절차 필드를, 피격 가능에는 모델·제시 높이·장갑·HP를, 발사/기동 활성에는 각각의 기존 필수 필드를 검증한다. 비유한·음수 속도, 잘못된 FOV/거리/기간, 일관되지 않은 능력 선언을 거부한다. 전체 검사를 건너뛰거나 미구현 필드를 M1A2에서 깊은 복사하지 않는다.
- 기존 방호시험을 보존하기 위해 **프로파일이 허용한 기능을 시나리오의 개별 차량에서 끌 수 있는 좁은 실행 마스크**를 둔다. 방호시험 T-80U는 `observation`을 끄고 기존 고정 자세를 유지한다. 새 관측시험만 켠다. 마스크는 프로파일이 비활성한 발사/기동/AI를 켤 수 없다. 검증되지 않은 임의 `profileOverride`나 가짜 별도 역사형으로 대체하지 않는다.
- `makeTank`, `can`, 관측자 목록, 명령/API, 격파 정리에서 이 유효 능력 판단을 일관되게 쓴다. 방호시험의 관측 비활성 T-80U는 기존처럼 `observation` 상태도 생성하지 않는다. 새 관측 차량에도 `drive`, `fireControl`, 탄약·부상·피로·사고 상태가 생기면 안 된다.
- 관측자가 됐다는 이유로 `TacticalAI`의 이동·교전 컨트롤러를 등록하지 않는다. 특히 `controlAutomatic(true)`가 기존 전차장 자동 인계를 차단하는 경로를 확인한다. 관측 전용 T-80U는 Observation의 탐색·인계·추적을 사용한다.
- `designate` 뒤 `aiFor.manualChanged`, 격파 표적을 추적하던 관측자 정리 뒤 `fireFor.cancel`, 관측 상태 조회/센서 갱신 등 **기존에 모든 관측자가 발사/AI 가능하다고 가정한 호출을 점검**한다. 기능이 없으면 해당 하위 시스템을 호출하거나 초기화하지 않는다. 관측 중인 적/아군이 격파돼도 예외가 없어야 한다.

## 5. 탐색·발견·인계·추적 규칙

### 5.1 자기 시야로 발견

- 기존 500m 후보 버킷, 거리/FOV 사전 필터, 높이장/건물/숲 LOS와 0.1초 분산 관측을 재사용한다. T-80U가 아군이 됐을 때도 같은 로직/자기 프로파일을 적용하고 팀 색으로 탐지 성능을 바꾸지 않는다.
- 전차장 원뿔은 현재 큐폴라 방위, 포수 원뿔은 현재 포탑 방위에 붙는다. 적이 가까이 있다는 이유만으로 방향을 모르는 먼 표적을 향해 탐색 중심을 바꾸지 않는다. **실제 적 좌표는 기존 후보의 광학 표본 판정 안에서만** 사용하고, 탐색·추적 제어에는 자기 접촉/관측 사본과 명시 명령만 넘긴다.
- 근거리 주변 인지는 실제 실루엣 탐지까지만 허용한다. 360° 인지가 먼 아군 위치를 알리거나 즉시 차종 식별/포수 확보·확정 인계를 만들면 안 된다. 공유 정보도 자기 전차장/포수의 현재 관측으로 세탁하지 않는다.

### 5.2 전차장 발견과 포수 인계

- CITV/열상 능력과 **전차장 표적 지시 가능 여부**를 데이터에서 구분한다. 현재 `sensors.hunterKiller`가 전차장 큐/자동 인계까지 동시에 제어하므로, 전차장 지시 허용 필드를 분리한다. 기존 M1A2의 legacy 값은 같은 동작으로 해석하고, T-80U에는 명시적 전차장 지시 기능만 연결한다. 새 필드 이름은 코드 관례를 따르되 `hunterKiller=true` 복사만으로 작업을 끝내지 않는다.
- 자기 전차장 채널이 **현재 발견·식별한 적 접촉**만 자동 인계 후보로 삼는다. 최초 발견/식별·채널 출처를 기록하고 같은 표적에 0.50초 연속 자격이 유지되면 마지막 관측 자세를 포수에게 전달한다. 이 대기는 게임상의 지시 지연이지 인간 반응시간 실측이 아니다.
- 대기 중 실제 관측 상실, 식별 자격 상실, 관측 확정 잔해면 대기를 취소/재시작한다. 같은 대기를 프레임/조회마다 새로 시작하거나 여러 후보 사이에 누적 시간을 넘겨주지 않는다. 대기 상태는 후보별/유계로 관리하고, 인계된 같은 표적을 매 틱 중복 지정하지 않는다.
- 인계 대기는 **전차장 자동 인계 경로만** 지연한다. 기존 M1A2의 플레이어 직접 지정, AI 소유권·대기/우선순위, 포수 자체 발견 경로를 지연시키지 않는다. M1A2에는 새 지연을 암묵적으로 적용하지 않는다.
- ‘전차장 인계 접수’와 ‘포수 확보’를 별도 상태로 유지한다. 포수가 자기 FOV/거리/LOS로 연속 0.40초 확인하기 전에는 확보가 아니다. 전차장/팀 관측만으로 확보 시간을 누적시키지 않는다. 포수 스스로 식별한 접촉은 전차장 인계 없이 정상 추적할 수 있다.

### 5.3 실제 선회·상실·재탐색

- 포탑/큐폴라는 고정 0.05초 틱에서 최단 각도차를 따라 회전한다. 각 스텝의 변화는 각각 `24°/s × dt`, `40°/s × dt` 이하이고, 평상시 탐색은 각각 8°/s·12°/s 이하이다. ±180° 경계, 대각선·후방 지시, 동시 회전과 모드 전환에도 초기화/텔레포트하지 않는다.
- 추적할 방향은 허용된 최신 관측 자세에서 얻는다. 시야를 잃으면 현재 관측이 아니게 되고 기존 상실 유예/기억 규칙으로 마지막 위치를 처리한다. **숨은 표적의 실제 이동을 따라 포탑/큐폴라가 갱신되면 안 된다.** 유예·만료 뒤 탐색으로 복귀하고, 새 유효 접촉이면 다시 인계/확보한다.
- 포수가 확보한 뒤 전차장이 다른 방향을 둘러볼 수 있고, 전차장 시야 이탈만으로 포수의 유효 자체 추적을 끊지 않는다. 반대로 전차장이 보고 있다는 이유로 포수 자체 관측 상실을 무시하지 않는다.
- 일시정지에서는 방향·관측 증거·인계/확보시간이 멈춘다. 배속은 시뮬레이션 시간만 바꾼다. 렌더/패널 조회·시야 오버레이가 시뮬레이션 방위/탐지 시간을 진행시키면 안 된다.

## 6. 게임 연결·시험 시나리오·공개 경계

- 기존 시나리오 두 개를 유지하고 우측 기존 선택기에 **T-80U 관측시험**을 하나 추가한다. 콘솔/합성 fixture에서만 작동하는 것으로 끝내지 않는다.
- 새 시나리오는 정지 T-80U 관측 차량과 아군 M1A2를 서로 관측할 수 있는 검증된 위치/초기 방위에 배치한다. 적이 자기 FOV 바깥에서 시작해 탐색→전차장 발견→선회/추적이 실제로 보이는 사례를 포함한다. 아군 M1A2는 이동 가능하며 **이 시나리오에서만 최초 보류**로 시작해 관측을 살필 시간을 준다. 기존 버튼으로 수동/자동 사격 전환은 가능하고 기존 탄약·장갑·피격 판정이 그대로 작동한다.
- T-80U의 차체는 고정, 포탑/큐폴라만 실제 시뮬레이션 방위에 따라 돈다. 그림에 별도 가짜 스윕 애니메이션을 붙이지 않는다. 포탑 회전 중 피격되면 실제 그 시점의 포탑 방위로 기존 포탑 전/측/후 판정을 한다.
- 원본 도안의 부모 상대 도 단위와 게임의 월드 절대 라디안 계약을 어댑터에서 유지한다. 주포/포탑은 같은 축, 큐폴라는 별도 축이다. 주포 아래 차체 ERA·포탑 판 배열을 수정하거나 기관총 장착/사격을 새로 활성화하지 않는다.
- 플레이어가 정상 아군 관측으로 보는 적 모델에는 마지막 유효 관측 방위만 표시한다. 적이 미관측/기억 상태가 되면 숨은 실제 선회를 화면에 계속 반영하지 않는다. 다시 관측하면 정상 갱신하고, 격파 후에는 양쪽 선회와 적 관측을 정지시킨다.
- **적의 시야 원뿔·표적 목록·인계/확보 상태·관측 장비 내부 정보를 정상 아군 UI에 노출하지 않는다.** 내부 검증 로그/테스트 주입은 분리한다. 아군 시야를 보기 위해 적 센서를 아군 LOS에 섞거나 적이 아군을 봤다는 이유로 적 위치를 공개하지 않는다.
- 시나리오 전환/reset은 센서 마스크·탐색 위상·접촉·인계 대기/임무·적 방위·Worker 세대 토큰·기존 탄/효과를 새로 초기화한다. 조회만으로 관측 비활성 표적의 상태를 만들지 않는다. 정상 WIP21 방호시험은 여전히 관측 비활성인 고정 표적이다.

- 순수 제어 검사와 **실제 지형/코어에서 자기 관측→자동 인계→회전→포수 확보**를 모두 검사한다. 각도를 직접 주입한 테스트와 정상 탐지로 발생한 선회를 구분한다. 적 좌표를 추적 제어에 넣는 가짜 성공 fixture를 만들지 않는다.
- 기존 M1A2에는 선회·센서 값/인계 시간·관측 주기를 바꾸지 않는다. 같은 seed의 기본 시나리오에서 90초 이상 기존/신규 차량 상태·관측 통계를 비교하고, 기존 방호시험의 비활성 T-80U도 방위/상태/방호 결과를 비교한다. 기존 테스트는 정당한 새 프로파일 선언/시나리오 메타데이터 변경만 갱신하고 검사를 삭제/완화하지 않는다.
- 전체 Node/Python/실제 Chromium 회귀와 WIP21 피격시험, 단독 모델 회전/원본 대조 검사를 실행한다. 브라우저 스크린샷은 **화면 안의 현재 관측 T-80U를 기준으로** 카메라를 맞추고 포탑·큐폴라 선회 전후와 모바일을 제출한다. 화면 밖 차량이나 미리보기만으로 게임 연결을 입증하지 않는다.
- 관측자는 기존 스케줄로만 추가한다. 새 매 프레임 LOS·전체 적 쌍·렌더에서의 탐지/대기 갱신은 금지한다. 후보별 대기는 유계로 정리하고 같은 표적 인계를 반복 생성하지 않는다.
- 같은 장면/환경에서 기준/신규 기본·방호시험의 틱/렌더 중앙값/P95와 query/ray 수를 비교한다. 새 관측시험과 합성 정지 관측자 50/100대의 탐색/추적 비용은 별도 측정하고 차량 수·밀도·기간을 명시한다. 일시정지 렌더만으로 관측 query가 증가하지 않아야 한다. 새 관측자가 생겨 늘어난 비용과 기본 회귀를 구분한다.
