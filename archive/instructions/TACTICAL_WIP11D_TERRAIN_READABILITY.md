### 2-1. 선행 확인 — 여러 아군의 공개 적 체력 병합

**사용자가 전달한 문제:** WIP11C 기본 검사는 통과했지만 여러 아군의 적 정보를 합칠 때 오래된 체력이 최신 관측값을 덮어쓴다. 가장 최근에 실제로 확인한 값을 유지해야 한다.

**파일 확인 결과 (2026-11-08 KST):** PR #9의 원격 head `a037774a8348378563d1d3ddb7822a20eab19890`에는 이미 `fix: keep freshest team contact health in WIP11C` 수정이 들어 있다. `src/observation.js`의 `buildTeam()`이 자세의 `lastSeen`과 식별 정보의 `knowledgeAt`을 별도로 비교하며, `tests/wip11c-ui-guard.test.cjs`에 **C06** 회귀 검사가 추가됐다. 구현 문서 `docs/UI_AND_GUARD_WIP11C.md`에도 반영되어 있다. 이 수정이 포함된 기준에서는 같은 수정을 중복 적용하지 말고 보존·검증한다. 이후 head가 바뀌거나 squash/병합되면 커밋 SHA 존재 여부뿐 아니라 실제 코드·검사 내용을 확인한다.

지시서 갱신 과정에서 원래 체크아웃을 바꾸지 않고 격리한 파일 사본으로 C06을 실행해 **1개 통과**를 확인했다. 같은 검사에서 `observation.js`만 해당 수정의 부모 버전으로 바꾼 대조에서는 최신 1000 대신 오래된 1450을 반환해 실패했다. 따라서 오류 재현과 해당 수정의 회귀 방지는 확인했지만, 이번 확인으로 WIP11C 전체 검사·브라우저·원격 PR 병합까지 검증한 것은 아니다.

**수정이 빠져 있다면 다음 범위로 보완한다.**

1. 아군 A가 같은 적을 나중에 식별해 최신 HP를 얻었고 아군 B가 이전 HP를 기억하는 상황을 재현한다. B가 유닛 배열에서 뒤에 있거나, 주변 채널로 위치만 더 최근에 갱신했다는 이유로 B의 옛 HP가 팀 공개 접촉을 덮어쓰지 않아야 한다.
2. 위치·자세는 해당 관측 시각으로, 이름·차종·공개 체력은 **식별 정보가 실제 갱신된 시각**으로 선택한다. 현재 코드의 `lastSeen`과 `knowledgeAt` 의미를 확인한다. 병합 시각·렌더링 시각을 새 관측 시각으로 찍거나 위치 시각으로 HP의 신선도를 대신 판단하지 않는다.
3. `known.combat`의 현재/최대 HP·상태는 같은 유효 관측 사본으로 유지한다. 배열에서 마지막 항목이나 가장 낮은 HP를 선택하는 편법은 사용하지 않는다. 최신 관측이 정당하게 더 높은 HP를 담는 경우도 시간 기준을 따른다. 동일 관측 시각의 동률 처리 규칙이 필요하면 일관되게 명시한다.
4. 시야 상실 후에는 팀이 마지막으로 확인한 공개 HP를 유지한다. 새 유효 식별 관측 없이 실제 적 HP를 읽어 최신화하지 않는다. 주변 탐지나 위치 갱신만으로 식별용 HP 시각을 갱신하지 않는다. 미식별 접촉은 HP 비공개를 유지한다.
5. 공개 접촉·snapshot은 관측 사본을 반환한다. 반환된 `combat` 객체를 외부에서 수정해도 저장된 공개 지식이나 실제 적 상태가 바뀌지 않아야 한다. 최신 관측을 선택하면서 오래된 사본을 참조로 다시 섞지 않는다.
6. 기존 기억 만료·재관측·확인 잔해 정책과 팀 공유/선택 차량 자체 관측의 구분은 유지한다. 이번 수정으로 관측 범위·탐지/식별 조건·사격·피해 계산을 바꾸지 않는다.

**필수 회귀:** A/B 배열 순서를 뒤집은 경우, 오래된 HP를 가진 B의 위치만 더 최신인 경우, 모두 관측을 잃은 뒤 실제 HP가 달라진 경우, 재관측으로 공개값이 갱신되는 경우, 미식별 정보 비공개, 반환 사본 변조를 확인한다. 기존 C05/C06이 다루는 범위는 재사용하고 부족한 사례만 추가한다. 먼저 `node --test --test-name-pattern='C05|C06' tests/wip11c-ui-guard.test.cjs`로 좁혀 확인한 후 관련 관측/UI 회귀를 실행한다. 해당 파일의 모든 검사가 통과했다는 것과 프로젝트 전체 검사가 통과했다는 것을 구분한다.

## 3. 일반 지도와 지형 강조 모드

1. **일반 지도:** 기존 지도 성격과 건물·도로·숲의 구분을 유지하면서 고도 색조·주요 등고선의 기본 가독성을 개선한다. 기본 진입 모드로 사용한다.
2. **지형 강조:** 고도대의 차이와 사면 음영을 더 분명하게 하고 능선·골짜기 선을 표시한다. 숲·농경지의 장식적 대비와 나무 내부 디테일을 낮춰 그 아래 지형이 이어져 보이게 한다. 숲 경계·건물 외곽·도로·수계는 계속 알아볼 수 있어야 한다.
3. 지도 도구 영역에 **`지형` 토글 하나**를 둔다. 활성 상태와 `aria-pressed`를 동기화하고 짧은 설명을 제공한다. 관측/경계 팝업이나 차량 명령 영역에 새 설명 패널을 만들지 않는다. 버튼 조작이 지도 클릭·명령으로 전달되지 않게 한다.
4. 기존 **등고선 토글은 독립 유지**한다. 이를 끄면 두 모드 모두 등고선과 고도 숫자만 숨긴다. 고도 색조·음영·지형 강조 모드의 능선/골짜기 선은 유지한다. 숨겨진 세 번째 모드나 복잡한 설정 창을 만들지 않는다.
5. 강조 모드에서 작은 범례로 ‘낮음 → 높음’, ‘능선’, ‘골짜기’를 보여준다. 골짜기 선과 실제 물길을 구별할 수 있어야 한다. 범례·토글은 모바일 가로에서도 지도와 기존 조작을 과도하게 덮지 않는다.
6. 기존 시야 홀드는 두 모드에서 그대로 작동한다. 홀드 중에는 지형 강조선·음영의 대비를 낮춰 시야 경계가 먼저 읽히게 하고, 해제하면 이전 지도 모드로 돌아온다. 관측 결과나 범위를 변경하지 않는다.
7. 모드 전환은 선택·일시정지·카메라 위치·줌·진행 중 명령을 바꾸지 않는다. 초기화 후에도 사용자가 선택한 지도 모드를 유지하며, 새 페이지 진입은 일반 모드로 한다. 영구 저장 설정은 이번에 추가하지 않는다.
8. 실제 기준 브랜치가 WIP11C의 가로 전용 정책을 구현했다면 이를 유지한다. 세로 차단·가로 복귀가 지형 토글과 충돌하지 않아야 한다. 이전 화면의 왼쪽 상시 관측 패널을 되살리지 않는다.

## 4. 고도 색조·등고선·음영

### 4-1. 고도 색조

- 동일한 게임용 높이값에 **고정된 고도 팔레트**를 적용한다. 카메라가 이동할 때마다 화면 안 최저/최고 고도로 재정규화하지 않는다. 같은 위치의 색이 줌이나 화면 범위 때문에 달라지면 안 된다.
- 현재 지도 범위를 기준으로 저지대의 차분한 녹회색 → 중간 고도의 황록색 → 높은 곳의 밝은 황갈색으로 연속 변화시킨다. 약 290/340/390/440/510m를 초기 색상 기준점으로 삼을 수 있다. 이 구간은 표현 조정안이며 새 지형 데이터가 아니다.
- 높이 증가에 따른 명도 변화가 대체로 일정하게 읽히게 한다. 화려한 무지개·눈 덮인 고산 표현·고도 경계의 딱딱한 색 띠는 사용하지 않는다. 팔레트는 실제 전후 화면을 보고 조정한다.
- 고도와 지표 종류를 혼동하지 않게 한다. ‘어두운 곳은 모두 숲’, ‘밝은 곳은 모두 농경지’로 보이지 않아야 한다. 강조 모드에서도 실제 숲 경계를 읽을 수 있게 한다.

### 4-2. 주요 등고선과 고도 숫자

- 기존 **10m 일반선 / 50m 주요선**의 원래 고도와 경로를 보존한다. 능선을 잘 보이게 하려고 고도나 등고선 좌표를 임의로 이동하지 않는다.
- 주요선은 일반선보다 분명한 굵기·대비로 구별한다. 초기 조정 범위는 주요선 약 1.5~1.8 CSS px, 일반선 약 0.6~0.9 CSS px로 하되 실제 배경과 축척에서 검증한다. DPR 배율을 중복 적용하지 않는다.
- 전체 지도에서는 일반선 밀도를 줄일 수 있지만 주요선과 고도 숫자는 유지한다. 확대하면 원래 10m 선을 보여준다. 축척별 생략은 표시 규칙이며 원본 간격을 변경하지 않는다.
- 주요선 숫자는 기본 11~12px 수준의 화면 크기와 얇은 배경 테두리/여백으로 읽히게 한다. 지도 패널·버튼·화면 가장자리에서 잘리지 않게 배치한다. 기존 숫자와 중복하지 않는다.
- 숫자의 고도는 해당 선의 `level`을 사용하고 선과의 대응을 분명하게 한다. 완만한 구간을 골라 배치하며 굴곡이 심하거나 너무 짧은 선에 억지로 넣지 않는다. 숫자를 줌 비율만큼 거대하게 확대하지 않는다.
- 같은 카메라에서 배치가 결정적이어야 한다. 작은 이동마다 라벨이 불필요하게 튀거나 다른 값처럼 보이지 않게 한다. 차량·선택 표시·공개된 유닛 이름은 지도 라벨 위에서 읽혀야 한다.

### 4-3. 다방향 음영

- 기존 단일 방향 기울기 음영을 개선한다. **북서 계열 주광을 유지하면서 보조 방향을 섞는 부드러운 다방향 음영**을 우선한다. 모든 방위를 같은 비중으로 평균해 굴곡이 사라지는 방식은 피한다.
- 지도 좌표의 x=동쪽, y=남쪽과 실제 조명 방위의 변환을 확인한다. y축 부호 오류로 언덕이 분지처럼 읽히지 않아야 한다. 단순 언덕·골짜기의 합성 고도에서 방향을 검증한다.
- 음영 강도에 상한을 두어 어두운 사면의 정보가 검게 뭉개지지 않게 한다. 지표·건물 그림자와 합성해도 주요 등고선·도로·숲 경계가 남아야 한다.
- 표시 분석용 저역통과 처리는 허용하되 별도 파생 데이터에서만 한다. 실제 고도·경사·LOS·충돌·길찾기 조회는 바꾸지 않는다. 줌을 바꿀 때 사면의 밝고 어두운 방향이 뒤집히지 않게 한다.

## 5. 능선·골짜기 선 — 별도 구현 단계, 이번 완료 범위에 포함

이 항목은 단순 선 스타일 변경보다 검증이 필요하다. 먼저 3~4절의 바탕 표현을 확보하고 이어서 연결한다. 필수 항목을 완료하지 못한 상태를 전체 완료로 보고하지 않는다.

1. **고도 지형에서 추출한다.** `data/rasdorf_4km.json`의 게임용 높이장을 기준으로 주요 능선과 골짜기의 중심선을 분석한다. OSM 물길·숲 경계·등고선 굴곡·화면의 명암 경계를 그대로 복사하지 않는다.
2. 화면 픽셀 대신 **월드 좌표의 고정 분석 축척**을 사용한다. 다운샘플링과 평활화는 좁은 수m 요철을 제거하고 수십~수백m 지형을 읽기 위한 표현 처리다. 분석 간격·평활화 거리·선별 기준은 미터 단위로 기록한다.
3. 횡방향 지형이 양옆보다 높은 마루와 낮은 골을 구별하는 검증 가능한 방법을 선택한다. 곡률/지형 위치 분석이나 분수계·배수망 기반 방법을 사용할 수 있지만, 경사가 크다는 이유만으로 모든 사면을 선으로 표시하면 안 된다.
4. 짧은 노이즈 가지·평지의 임의 선·지도 경계의 가짜 선을 제거한다. 주요 흐름은 자연스럽게 연결하되, 연결을 위해 평지·반대 지형을 억지로 가로지르지 않는다. 확신이 낮은 곳은 생략한다. 단순한 선 길이/개수만으로 품질을 주장하지 않는다.
5. **능선:** 황갈색 계열 실선. **골짜기:** 저채도 청회색 파선. 두 선은 색뿐 아니라 선 패턴으로도 구별한다. 도로·수로보다 두껍거나 밝게 보여 새 도로처럼 읽히지 않게 한다. 골짜기 선은 실제 물의 존재를 뜻하지 않는다.
6. 축척에 따라 작은 가지를 생략하되 주요 선의 위치·종류가 바뀌지 않게 한다. 확대 시 선을 현재 화면 해상도의 벡터로 다시 그리고 저해상도 비트맵을 단순 확대하지 않는다.
7. 선은 **지형을 읽는 보조 표현**이다. 이동 경로·통행 가능성·LOS 경계·게임 판정 입력으로 사용하지 않는다. 수동으로 그린 선을 자동 분석 결과로 소개하지 않는다.
8. 반복 분석은 빌드 전에 수행하고 결과만 내장하는 방식을 우선한다. 파생 결과에는 최소한 `sourceMapHash`, 스키마/알고리즘 버전, 분석 간격·필터·선별 매개변수와 선 좌표를 기록한다. 같은 입력으로 재현 가능해야 한다.
9. 데이터가 누락되거나 해시가 다르면 잘못된 선을 그리지 않는다. 개발 검증은 명확히 실패시키고, 실행 화면에서는 기존 지도를 유지하며 개발자 진단을 남긴다. 사용자에게 내부 해시를 상시 표시하지 않는다.

봉우리·안부 기호나 자동 지명은 이번에 추가하지 않는다. 실제 지도에서 해석선의 타당성이 확보된 뒤 별도 작업으로 다룬다.

## 6. 데이터·렌더링·기존 기능 보존

- 원본 DEM·OSM, `data/rasdorf_4km.json`, 전장 메타데이터, 기존 고도·지표·길찾기 캐시와 등고선 원본은 보존한다. 표시 개선 때문에 원본을 재수집하거나 이동 캐시를 재베이크하지 않는다.
- 새 분석 데이터는 별도 파일로 만들고 기존 `sourceMapHash` 계약과 연결한다. 복제한 고도 데이터를 새 판정 기준으로 만들지 않는다. 빌드에 새 내장 스크립트가 필요하면 `build.py`의 삽입 경로도 함께 갱신한다.
- 표시 분석에는 기존 도구를 우선 사용한다. 추가 의존성이 필요하면 버전·설치·재생성 명령을 명시하고 기존 의존성과 격리한다. 실행 HTML에는 외부 CDN·API·지도 타일·폰트 다운로드 의존성을 추가하지 않는다.
- 지도 모드·등고선 상태·팔레트/분석 버전·카메라·화면 크기·DPR 등 실제 렌더링 입력을 캐시 키에 반영한다. 모드 전환·회전·리사이즈 후 이전 화면이 남지 않게 한다.
- 전체 높이장 분석이나 선 추출을 매 프레임·팬·핀치마다 실행하지 않는다. 고정 분석 결과를 재사용하고 현재 화면만 합성한다. 정지 화면에서는 캐시를 재사용한다.
- 유닛·경로·공개 접촉·선택 표시·시야 홀드는 기존 상위 표시 계층을 유지한다. 숨겨진 적 객체를 조회해 지도 라벨을 피하는 등의 새 정보 노출 경로를 만들지 않는다.
- 표시 모드가 시뮬레이션의 난수·시간·상태를 소비하거나 바꾸지 않게 한다. WIP11C 기준 UI·경계 기능과 아카이브의 게임 수치는 보존한다.
- 2-1절의 공개 정보 병합 보완이 필요하면 지형 렌더링 변경과 구분해 기록한다. 시뮬레이션 규칙 변경으로 확대하지 않으며, 모드별 상태 일치 비교는 공개 체력 수정이 포함된 동일 기준끼리 수행한다.

## 7. 검증·완료 기준

### 7-1. 데이터와 지형 해석

- **합성 고도:** 평지, 일정 경사면, 단독 언덕, 단독 골짜기, 교차 능선/안부, 평탄한 정상부, 작은 노이즈, 회전한 지형, 지도 끝을 포함한다. 평지·단순 경사면에서 가짜 망이 생기지 않고, 언덕과 골짜기가 서로 뒤집히지 않아야 한다. 회전·경계에서 방향 편향이나 비정상 연결을 확인한다.
- **실제 지도:** 숲 속 능선, 개활지 언덕, 마을 주변 사면, 낮은 골짜기를 포함해 최소 4개 고정 구역을 선정한다. 월드 좌표·카메라·줌을 기록하고 변경 전/일반/강조 화면을 비교한다.
- 추출선의 여러 지점에서 횡단 고도와 원래 등고선을 대조해 ‘양옆보다 높은 마루/낮은 골’인지 확인한다. 수로가 없는 마른 골과 수로가 있는 골을 구분하며, ‘OSM 선과 겹침’을 정답으로 삼지 않는다. 주요 오검출·생략 사례와 적용 축척의 한계도 기록한다.
- 같은 입력과 매개변수로 재생성한 파생 결과가 동일한지 검사한다. 원본 지도·고도·등고선·길찾기 데이터의 전후 해시를 대조하고 유지 여부를 기록한다. 파생 데이터의 해시 불일치·누락 처리도 검사한다.

### 7-2. 실제 화면과 입력

- Chromium 실제 DOM/canvas에서 **1440×900 및 844×390 가로**, DPR 1/2, 전체 지도 맞춤·중간 확대·최대 확대를 확인한다. 실제 게임 카메라와 줌 범위를 사용한다.
- 네 조합(일반/강조 × 등고선 켜짐/꺼짐), 팬·휠·핀치, 토글 연타, 리사이즈, 선택 없음, 일시정지·초기화, 시야 홀드/해제를 확인한다. 수평 넘침·클릭 관통·버튼 잘림·오래된 캐시·숫자 중복이 없어야 한다.
- WIP11C의 세로 차단 정책이 적용된 기준에서는 390×844 진입·가로 복귀도 확인한다. 모드 선택이 유지되고 기존 재생/정지 복원 정책이 유지되어야 한다. viewport 검증을 실제 휴대폰 검증으로 보고하지 않는다.
- 전체 지도에서 고저의 큰 흐름, 중간 확대에서 능선과 골짜기, 숲 안 사면의 연속성이 전보다 읽히는지 전후 화면을 검토한다. 다른 카메라·다른 시점의 스크린샷으로 개선을 주장하지 않는다.
- 흑백 화면에서도 고도 명도와 능선/골짜기 패턴이 구별되는지 확인한다. 유닛·경로·선택·시야 표시가 지형보다 먼저 읽혀야 하는 순간에는 해당 표시가 묻히지 않아야 한다.

### 7-3. 회귀·성능·실행 파일

- WIP11C 공개 체력 병합 수정의 포함 여부와 2-1절의 C05/C06 및 관련 회귀 결과를 먼저 기록한다. 이미 수정된 기준이면 ‘기존 수정 보존·재검증’, 빠진 기준에서 반영했다면 ‘이번 보완’으로 정확히 구분한다.
- 기존 지도·입력·시야·차량/Worker 및 실제 기준 브랜치의 Node 회귀 검사를 실행한다. 표시 변경으로 기존 판정 기대값이나 동결 기준표를 현재 결과에 맞춰 고치지 않는다.
- 같은 seed·고정 시간 간격·같은 게임 명령에서 지도 모드 전환 유무에 따른 코어 상태가 일치하는지 비교한다. 카메라/표시 상태 차이는 분리해 검사한다.
- 같은 기기·viewport·DPR·카메라 순서로 변경 전후 지도 재빌드 시간과 캐시 재사용을 측정한다. 30회 이상의 동일 팬/줌 재빌드에 대해 중앙값·p95를 기록하고, 정지 카메라에서는 120프레임 동안 불필요한 재빌드가 없는지 확인한다. 최초 로드와 재사용 비용을 구분한다. 눈에 띄는 입력 멈춤·매 프레임 분석이 남으면 원인을 개선하고 재검증한다. 이 측정을 실기기 FPS로 표현하지 않는다.
- 실제 기준 버전에 맞춰 빌드하고 `python3 scripts/package_release.py WIP11D`를 실행한다. 버전이 바뀌었다면 인자도 맞춘다. **버전 HTML = dist**, ZIP 안 HTML 한 파일·CRC·해제 바이트·SHA-256 일치를 확인한다. 이전 릴리스는 보존한다.
- 단일 HTML을 외부 통신 없이 실행해 새 지형 데이터가 내장됐는지 확인한다. 로컬 HTTP로 화면·Worker를 검증하고, 가능한 경우 `file://`도 확인한다. 브라우저 정책으로 막히면 정확한 오류와 미검증 범위를 남긴다.
- 실행한 테스트 수·실패·건너뜀·미실행과 브라우저/수동 확인을 구분한다. 화면 캡처만으로 분석 정확성이나 성능 검증을 대신하지 않는다.
