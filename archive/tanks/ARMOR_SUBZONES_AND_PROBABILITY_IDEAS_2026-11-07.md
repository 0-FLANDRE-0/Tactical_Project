# TACTICAL 1989 — 7구역 내부 세부 장갑면·확률 판정 아이디어 메모

> **기록일:** 2026-11-07 (KST)
> **상태:** **검토 중인 설계 아이디어 / 미확정.** 이번 대화에서 “대충 이런 식으로 해보면 어떨까”라고 논의한 내용을 보존한다. 확정 규칙·계산식·수치표·구현 지시서가 아니다.
> **기준 데이터:** [전차 32종의 현행 7구역 방호력](README.md) · [탄약 32종×3=96개 프리셋](../ammo/README.md)
> **범위:** TACTICAL의 RTS식 **물리 상태 + 확률 판정**을 전제로 하며 정밀 3D 장갑 충돌 또는 실제 탄착 좌표 추적을 목표로 하지 않는다.

## 1. 논의의 출발점: 단순 7구역을 유지할지, 내부를 다시 나눌지

현재 확정된 상위 장갑 구역은 총 7개다.

1. 차체 전면
2. 차체 측면
3. 차체 후면
4. 포탑 전면
5. 포탑 측면
6. 포탑 후면
7. 통합 상부장갑(차체·포탑 지붕)

**제안 방향:** 이 7개를 당장 폐기하거나 모두 별개의 신규 상위 구역으로 재편하지 않는다. 필요할 때만 각 구역 안에 **선택적 세부 피격면(subzone)** 을 두는 방식을 검토한다. 7구역만 사용하는 경량 모드와 내부 세분화 모드를 모두 지원할 수 있는지 살펴본다.

목적은 정면 전체를 하나의 균일한 방호력으로 볼 때 생기는 과도한 단순화를 완화하고, 차량별 형상·추가장갑 차이를 게임성으로 표현하는 것이다. 특히 소련 후기형 전차의 높은 정면 대표 방호력을 일률적으로 적용할 때의 밸런스 우려가 논의됐지만, **특정 진영의 수치를 임의로 깎기로 합의한 것은 아니다.**

## 2. 구역별 세부 구획 후보 — 전부 잠정

| 상위 7구역 | 내부 후보 | 현재 판단 |
|---|---|---|
| 차체 전면 | 상부 경사장갑판 / 하부 장갑판 | 차체 전면 경사 차이를 표현하기 위한 우선 검토 대상 |
| 차체 전면의 상부 장갑판 내부 | 조종수 해치 등 작은 특징 영역 | 상부 장갑판과 독립된 동급 구역이 아니라 *그 안에 포함된 하위 특징* 후보 |
| 차체 측면 | 전방부 / 후방부 | 이동·차체 방향과 상대 노출 차이를 표현하는 후보. 좌우 방향은 차체 방위로 구분 |
| 차체 후면 | 단일 유지 | 우선 세분화 필요성 낮음 |
| 포탑 전면 | 좌측 뺨 / 포방패 / 우측 뺨 | 좌우 비대칭 포탑과 포방패 특성을 선택적으로 표현할 수 있는 후보 |
| 포탑 측면 | 전방부 / 후방부 | 포탑 독립 회전과 노출 비중 차이를 반영하는 후보 |
| 포탑 후면 | 단일 유지 | 우선 세분화 필요성 낮음 |
| 통합 상부장갑 | 차체 지붕 / 포탑 지붕 | **기존 7번째 상위 구역 내부**에서만 나누는 구상. 현행 7구역 숫자 체계는 유지 |

- 포방패가 항상 다른 포탑 전면보다 약하거나 강하다고 단정하지 않는다.
- 좌·우 포탑 뺨은 데이터상 구분 가능하게 하되, 대칭 차량은 같은 기본값을 공유할 수 있어야 한다.
- 모든 전차에 구획별 별도 KE/CE를 강제 입력하지 않고, 차이가 있는 차량만 개별 설정하는 방식을 검토한다.
- 작은 특징 영역의 확률을 상위 면의 확률에 **중복 합산하지 않는다**.
- **이 표는 구획 후보 목록이지 32종 전차의 최종 세부 장갑 정의가 아니다.**

## 3. 장갑 경사·LOS 구상

- 각 장갑면에는 나중에 **대표 고정 경사각**을 둘 수 있다. 특히 차체 상부 경사장갑판과 하부 장갑판의 차이를 먼저 검토한다.
- 탄이 어느 방향에서 왔는지는 차량의 **차체 방위**와 **포탑 방위**를 각각 사용해 별도로 해석하는 방향이다. 차체와 포탑을 같은 방향으로 취급하지 않는다.
- 기존 시야 LOS(보이는가)와 장갑 LOS/입사 조건(선택된 장갑면의 상대 방호 특성)은 **서로 다른 개념**이다.
- 이미 확정된 KE(CE) 수치는 기준 정면 조건에서 장갑 구조와 경사 특성이 반영된 **게임용 RHAe 대표값**이다. 새 고정 경사각을 다시 통째로 곱해 **경사 효과를 이중 적용하지 않는 것**이 중요한 전제다.
- 상대 입사 변화에 따른 보정 방식, 장갑면별 기준각, 탄종별 경사 대응, 도탄·신관 등 세부 계산식은 아직 결정하지 않았다. 실제 장갑판의 세부 각도를 임의로 확정해 채우지 않는다.

## 4. 물리 상태를 입력으로 쓰는 계층형 확률 판정 구상

**핵심 원칙: 실제 탄착 좌표를 만들어 맞는 위치를 찾는 방식이 아니라, 계산한 게임 상태를 이용해 확률을 선택한다.**

검토한 개념적 흐름:

1. 지형·건물·숲, 거리, 차량 자세, 차체/포탑 방향과 운동 상태를 계산한다.
2. 사통장치·관측 효율·조준 안정화·포수 숙련도·탄약 게임 특성과 표적 운동 조건을 바탕으로 **명중 여부**를 판단한다.
3. 명중이 성립한 경우에만 차체/포탑 노출률과 상대 방향 등을 반영해 **기존 7구역 중 하나**를 확률적으로 선택한다.
4. 그 구역이 세분화돼 있다면 노출 비중과 조건별 가중치를 이용해 **내부 세부 피격면 하나**를 선택한다.
5. 선택된 장갑면의 기본 KE/CE, 입사 조건, ERA·BDD·D-Tech 등 게임 규칙을 적용하는 방식을 이후 검토한다.

**미확정 사항:** 단계의 정확한 결합 방식, 명중률 공식, 세부 구역 가중치, 구역별 노출 근사, 추가장갑 적용 순서 및 실제 피해 모델.

반드시 구별할 개념:
- **명중 확률:** 탄이 표적에 맞는가.
- **조건부 구역 확률:** *맞았다고 가정할 때* 어느 상위/세부 구역에 해당하는가.
- **방호·피해 결과:** 해당 구역의 게임 수치로 어떤 결과를 낼 것인가.

단순히 가중치를 정규화했다는 이유로, 원래 빗나갔을 공격을 강제로 표적에 맞힌 것으로 처리하면 안 된다. 또한 차폐된 면의 확률을 무조건 고정값으로 유지하는 방식은 피한다.

## 5. 이동 방향·리드와 피격 구역 편향에 대한 논의

예시 질문: **왼쪽으로 이동 중인 전차를 쏘면 움직이던 방향 쪽의 차체 측면 전방부 등에 맞을 확률이 달라질 수 있을까?**

- **가능성 있는 게임 요소**로 검토한다. 표적의 이동 속도·방향과 차체가 바라보는 방향은 분리한다. 후진·차체 선회 같은 경우도 있기 때문이다.
- 이동 중이라는 사실 하나만으로 '진행 방향 앞쪽 구역의 피탄 확률 상승'을 **상수 규칙으로 확정하지 않는다**.
- 표적 운동, 관측·추적 품질과 게임상 예측 편차가 **조건부 피격 구역 분포에 영향을 주는지** 추후 설계한다.
- 이동 효과를 명중 확률과 세부 구획 확률 양쪽에 중복 반영하지 않도록 역할을 분리한다.
- 실제 표적을 타격하기 위한 조준 해법이나 정밀 탄도 충돌 계산을 구현하려는 제안은 아니다.

## 6. 관측·사통·포수·탄약 확률과의 연결

장갑 구획을 세분화해도, 실제 전투 확률의 큰 부분은 **표적 관측/식별, 사통장치, 안정화, 포수 훈련 수준, 탄약의 게임상 성격** 등에서 결정된다는 문제의식이 있었다.

현재 논의 방향:
- 관측 가능성과 추적·조준 신뢰도를 무조건 한 번에 곱하는 단일 수치 대신 역할을 구분해 설계한다.
- 관측 효율의 불리함을 식별·추적과 최종 명중률에 이중 적용하지 않는다.
- 확률 모델이 먼저 검증된 후 세부 장갑면 확장 여부를 판단할 수 있게 한다.
- 세부 부위 확률만 복잡해져서 얻는 게임적 이득보다 자료 관리 비용이 커질 수 있으므로, **7구역만 쓰는 대안은 계속 열어 둔다**.

## 7. 실제 코드 WIP06과의 관계

2026-11-07 당시 [현재 코드](../../src/sim-core.js)를 검토했을 때:
- 주로 **차량 기동·경로 탐색·지형 기반 관측**이 구현된 상태이며, 주포 사격·명중·장갑 관통·피해는 아직 활성화되지 않았다.
- 차량에는 차체 방향과 포탑 방향이 있고 고정시간 갱신을 사용한다.
- `exposure()`는 차체 **6개**·포탑 **3개** 관측 표본의 보임 비율을 반환한다. 이것은 **현재 명중률이 아니며 세부 장갑면 확률도 아니다**.
- 노출 계산의 포탑 표본은 현재 차체 방위를 기준으로 잡고 있어, 향후 포탑 독립 방위와 세부 노출을 다루려면 별도 설계가 필요하다.
- `look-animation.js`의 포탑 둘러보기는 **화면 연출**로 원본 시뮬레이션 상태를 변경하지 않는다. 전투 판정에 이 연출값을 사용하면 안 된다.
- 현재 원본에는 M1A2가 시험용 차량으로 있어 **M1A2 한 차종으로 가상·통계적 모델을 먼저 검증할지** 의견이 나왔다. 이 역시 작업 승인·구현 착수는 아니다.

## 8. 추후 결정해야 할 질문

1. 7구역만 유지할지, 어느 구역에 세부면을 실제로 활성화할지?
2. 차체 전면 상/하부, 포방패·좌우 뺨, 상부 지붕을 어떤 확률 비중으로 취급할지?
3. 각 차량의 세부면에 경사각·기본 KE/CE를 언제, 어떤 자료/게임 기준으로 정의할지?
4. 차폐·방향·운동 상태를 부위 확률에 얼마나 반영할지?
5. 사통장치·관측·안정화·승무원 훈련·탄약의 확률 모델을 어떻게 검증할지?
6. 구획별 모델의 복잡도와 소련/서방 밸런스 간에 어떤 균형을 택할지?
7. M1A2 시험 모델로 먼저 시작할지, 기존 7구역만 쓰는 최소 전투 모델을 먼저 구현할지?

**관리 규칙:** 여기 적힌 항목을 '확정 게임 수치'로 취급하지 않는다. 승인 전에는 [전차 최신 기준표](README.md)의 7구역 KE(CE) 값을 덮어쓰지 않고, [탄약 기준표](../ammo/README.md)의 탄약·프리셋도 변경하지 않는다. 향후 결정이 확정되면 별도 확정 절로 옮기거나 상태를 변경한다.
