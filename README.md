## 실행과 조작

[실행 HTML ZIP](https://github.com/0-FLANDRE-0/Tactical_Project/raw/refs/heads/feat/wip09-hit-model/Tactical_v0.4_WIP09.zip)을 내려받아 압축을 푼 뒤 `Tactical_v0.4_WIP09.html`을 브라우저에서 연다. GitHub에서 HTML을 바로 열면 소스가 표시될 수 있다. 고도·지표·도로·건물·수목·벡터 등고선·길찾기 캐시가 모두 포함된 단일 파일이며, 실행 중 인터넷이나 외부 라이브러리를 요구하지 않는다. 모바일은 가로 화면을 권장한다.

- 전차 탭: 선택. 우측 전차 목록을 누르면 해당 전차로 확대한다.
- 지면 탭: 이동 지점 지정. 후진 버튼을 선택한 뒤 지점을 누르면 후진한다.
- 정지: 경로 취소 후 감속한다.
- 시야 버튼 홀드 또는 V 키 홀드: 선택 전차의 가시·차폐 영역을 표시한다.
- 드래그: 지도 이동. 핀치·휠: 확대/축소. 우측 맞춤 버튼: 전체 4km 지도 보기.
- 관측 표적 탭: 미식별 실루엣은 일반 정보만, 식별한 현재 접촉은 차종·부위 관측 비율을 표시한다. 흐린 잔상은 마지막 관측 위치다.
- 전차장/포수 선택 → 지점 경계(L) → 지도 탭. 이동 중에도 지정 월드 지점을 바라본다. 자동 경계 버튼으로 해당 명령 해제. Esc는 새 입력만 취소한다.
- 표적 패널의 포수 직접 지정과 인계 취소를 사용할 수 있다. 지정 전달과 포수 확보는 별도 상태다.
- 표적 탭 → 필요하면 포수 직접 지정 → 자체 확보/조준 완료 → **발사 버튼 또는 G**. 단발 명중/부위 결과와 시험탄 수를 표시한다. 맞아도 피해/파괴는 아직 없다.
- Space: 일시정지. R: 후진 모드. X: 정지. F: 전체화면. Home: 전체 지도.
- 전체화면 요청이 거절되거나 지원되지 않으면 지도 집중 모드로 전환한다.

건물·도로의 실제 높이/폭 태그가 없는 경우에는 종류에 따른 게임용 추정값을 사용했다. 작은 차고·창고·부속시설과 일부 주거 건물을 생략해 밀도를 낮췄다. 건물 외곽선을 옮기거나 전체 지형을 좌우 대칭으로 바꾸지 않았다.

작은 실개천은 감속해서 통과하며, 면 수역은 통행을 차단한다. 이는 게임 규칙이며 실제 도하 가능성이나 수심의 재현을 뜻하지 않는다. 나무는 숲의 시각적 표현이며 개별 줄기 충돌은 아직 계산하지 않는다. 숲은 밀도 기반으로 시야를 감쇠하고 이동 비용을 늘린다.

## 공통 판정 기준

게임용 고도와 선별한 구조물이 하나의 전장 데이터에 들어 있다. 화면·이동·관측은 이 고정 데이터를 공유한다. 이동은 연속 좌표이며 내부 길찾기만 16m 격자를 사용한다.

- 높이 조회: 공통 2m 높이장 보간.
- 지표 분류: 같은 벡터에서 생성한 4m 지표 아틀라스.
- 길찾기: 16m A*와 고정 연결 캐시. 실제 차량 반경과 건물 외곽선으로 연결 구간을 미리 검사한다.
- 경로 정리: 지형 비용을 고려해 경로를 줄이고 실제 충돌 조회로 재확인한다.
- 이동: 가감속·선회·후진·지표/경사별 속도. 정지·도착·충돌 대기를 처리한다.
- 관측: 지형·건물·숲 차폐. 차량 부위 관측은 2m 간격의 경로 표본과 실제 건물 외곽선을 사용한다.
- 홀드 표시: 지면 위 1.5m 표적 기준. 720개 기본 방위와 건물 윤곽 방향의 추가 가시선(총 최대 1,980개)을 따라 2m 간격으로 지형·지붕 수평선을 계산한다. 숲은 시선 높이에 따른 광학 깊이로 누적한다. 4m 거리 표본 사이의 가시 경계를 보간·연결해 벡터 폐곡선으로 표시한다. 25m 표시 격자는 제거했다.
- 능선이나 건물 바로 뒤가 가려져도, 더 먼 높은 지형이 다시 보이면 별도의 가시 영역으로 남는다. 숲 위를 지나는 시선도 구분한다.
- 시야 영역은 화면용 근사치다. 차체·포탑 노출 판정은 기존의 개별 가시선을 계속 사용한다. 경계나 얇은 구조물 부근은 두 판정의 표본 차이가 남을 수 있다.
- 차체·포탑: 각각 6개/3개 높이 표본. 관측 비율과 단발의 게임 노출 가중치에 사용한다.

길찾기 캐시는 전장 revision hash와 차량 반경·경사 한계·격자 규격 계약에 묶인다. 지도나 계약이 달라지면 다시 제작해야 한다. 고정 지도에서 매 실행마다 전체 연결을 재계산하는 비용을 없앴다.

## M1A2 제원과 상부 도안

기본형 M1A2를 대상으로 한다. 공개 제원·계열에서 가져온 값·외형 근사·게임 조정값을 구분했으며, 상세 근거는 `data/vehicles/README_KO.md`와 `M1A2.json`에 있다.

- 포 전방 전장 9.8298m, 차체 7.9248×3.6576m, 포탑 지붕 2.3749m. 차체 길이는 M1 계열 도면의 근사값이다.
- 도로 67.6km/h, 야지 48.3km/h 상한. 후진 40.2km/h는 같은 계열·SEP 교범에서 가져온 가정이다. 실제 속도는 지표·경사·선회·감속에 따라 달라진다.
- 평지에서 0→20mph(32.2km/h) 7.2초를 맞춘 단순 가속 모델이다. 질량·출력은 프로파일에 기록하되 정밀 구동계 물리를 주장하지 않는다.
- 관측점은 사용자가 지정한 **전차장 CITV 수준, 지면 위 2.65m**다. 광학축 높이는 공개 실측치를 확인하지 못해 외형 근사로 분류했다. 포수 조준경 시점으로 바꾸지 않는다.
- 관측은 주변 **200m/360°(실루엣까지만)**, 전차장 **2500m/90°**, 포수 **2000m/30°**다. 실제 선회는 전차장 50°/s, 포탑 40°/s이며 프로파일 게임 설정이다. 4km는 표시용 기하 조회 상한, 3km는 주포 참고 메타데이터이고 이번 시험 사격은 2km 한도다.
- 이동은 60% 종방향·40% 횡방향 경사를 구분한다. 60도/40도가 아니다. 차체 여유 반경 4.62m에 맞춰 길찾기 캐시를 다시 제작했다.
- 상부 외형은 미 육군 DVIDS 3055956 사진으로 장비 배치를 확인하고, USMC의 M1A1 공통 차체·포탑 도면과 동일 축척으로 비교했다. M1A1 도면을 M1A2의 정확한 세부 도면으로 취급하지 않는다.
- WIP05: 상부 외곽을 USMC A-3 평면도에 동일 축척으로 겹쳐 다시 그렸다. 포탑 전면은 포방패 옆이 거의 횡방향인 뭉툭한 면과 짧은 사선 측면으로 바꿨고(이전의 뾰족한 화살촉형 제거), 도면대로 좌측(장전수) 측면 사선이 우측보다 길다. 포탑 본체 길이 4.75m, 수납함 포함 폭 3.28m, 뒤 바스켓 포함 약 5.30m는 **외형 근사값**이다.
- WIP08A: 제공 HTML의 M1A2 형상·장비 배치로 갱신했다. 링 회전축은 차체 전방 0.66m, 도안 원점은 0.15m로 구분한다. 측면/후방 선회 중에도 포구와 발사 표시가 일치한다.
- WIP05: M256 포신에 열차폐 고정 링·배연기·포구 칼라·포구 기준 센서를 도면 위치대로 넣었다. 포구 위치는 공개 전장 9.8298m를 유지한다.
- 상부 궤도 주행부는 사이드스커트·펜더 아래에 모두 숨겼다. 전방 펜더 수납함, 좌측 터빈 흡기 그릴, 엔진 데크 흡기 그릴(사진 기준, 포탑 선회 시 노출), 후방 배기 그릴, 견인 고리, 버슬 랙, 해치·CITV·GPS·기관총·연막탄 발사기·패널·고정구를 벡터로 분리했다. CROWS/TUSK는 기본형에 추가하지 않았다.
- 차체와 포탑을 서로 독립된 변환으로 그린다. 장비 배치와 세부 체결구는 사진을 참고한 표현이며 장갑·충돌·피해 모델은 아니다.
- 최대 확대는 **32px/m**다. 차체는 월드 단위, 이름·선택 링·24px 여유 선택은 화면 단위다. 확대해서 차체 중심에서 24px보다 먼 부분을 눌러도 차체 내부라면 선택된다.
- 벡터 지도는 현재 화면 해상도에 맞춰 다시 그린다. 긴 시야 계산은 내장 Worker에서 처리하고, 지원하지 않는 환경에서는 같은 계산을 본문에서 실행한다. 빠른 전차 선택·초기화 후 이전 계산 결과가 새 전차의 시야를 덮지 않도록 했다.

단독 도안은 `data/vehicles/M1A2_top_view.svg`, 비교 화면은 `dist/qa/M1A2_comparison.html`이다. 비교 화면은 공통 차체 도면과 게임 도안을 같은 차체 길이·폭으로 정렬하고 1m 기준선을 표시한다. 실제 M1A2 사진도 함께 확인할 수 있다. 미 육군·해병대 사진/도면은 출처를 기록했으며, 실행 HTML에 원본 사진을 넣지는 않는다.

## 과거 검증 기록 (WIP04/WIP05)

아래는 기존 버전의 기록이다. WIP06에서 다시 실행한 항목과 실행하지 않은 항목은 상단의 버전 노트에서 구분한다. 과거 Chromium·모바일 viewport 결과를 현재 시선 연출 UI의 브라우저 검증으로 해석하지 않는다.

- 게임/지도 16개, 입력 16개, 시야·벡터 등고선 12개, 전차·비동기 시야 9개, 실제 자료 대조 7개: **60/60 통과**.
- WIP05(외형만 변경): 게임/지도·입력·시야·전차 JS 검사 53/53 재통과. 지도·고도 원본은 건드리지 않았으므로 실제 자료 대조 7개(GDAL 필요)는 WIP04 결과를 유지한다. 새 도안은 USMC A-3 평면도와 같은 축척으로 겹쳐 외곽·해치·포신 위치를 확인했고, Chromium에서 3~32px/m 확대 및 포탑 선회 상태를 확인했다.
- 가시선 검사는 평지의 원형 범위, 얇은 건물 그림자, 건물·능선 너머의 먼 고지 재노출, 숲의 감쇠·수관 위 관측, 건물 안뜰, 지도 경계의 폐곡선을 확인한다.
- 실제 지도 세 위치에서 4km 이내 개별 가시선과 비교한 4,550개 표본 중 4,522개 일치(위치별 약 99.1~99.7%). 영역 근사치와 개별 표본은 동일한 알고리즘이라고 주장하지 않는다.
- 벡터 등고선 정점 2,813개를 게임 고도와 대조했다. 높이 오차 최대 약 0.00031m(정점 반올림 포함). 선 사이 구간은 단순화 허용오차를 가진다.
- 실제 자료 대조에는 전체 고도 400만 표본의 편집·양자화 오차, 375개 건물의 원래 좌표·외곽선 보존, 원본 체크섬 검사를 포함한다.
- 실제 지도상의 개활지·마을 주변 경로 4건에서 도착과 충돌 0회를 확인했다.
- 동일 고정 시간 간격 결과, 후진, 감속 정지, 건물·수역 차단, 실제 숲 차폐, 실제 고저차의 차체/포탑 노출 차이를 확인했다.
- Chromium에서 벡터 나무·등고선·건물의 최대 32px/m 확대, 수정된 M1A2 실축척, 24px 이내의 여유 탭 선택, 이동 경로·실제 속도 갱신, 시야 홀드/해제를 확인했다.
- 844×390 가로 및 390×844 세로 viewport에서 수평 넘침 없이 표시됨을 확인했다. 가로 화면의 전차 선택·후진·시야 홀드를 확인했다.
- 실제 휴대폰의 멀티터치·메모리·발열·지속 프레임률과 네이티브 전체화면/방향 고정은 별도 실기기 검증 대상이다.

## 현재 범위

이번 버전은 실제 지도와 기동·관측·수동 단발 사격을 연결한 시험장이다. 표적 확보와 조준 완료를 구분하고 게임 명중/부위를 기록한다. 적 전술 AI·자동 사격·관통·장갑·피해·상세 장전·보병은 구현하지 않았다. 기본 적 표적은 정지 상태다.

명중과 조건부 부위 선택은 현재 관측 노출과 실제 방향을 사용하는 추상 게임 모델이다. 사통장치 수치는 시험용 튜닝이며 실차 성능 재현값이 아니다. archive의 차량/탄약/장갑 설계는 런타임에 자동 적용하지 않는다. 현재 확률식과 초깃값·35개 기준 사례는 WIP09 상태 문서에 기록했다. Node 211개·실제 Chromium 15개·구문 47개/5개를 통과했다. file:// 실행은 환경 정책으로 차단되어 같은 HTML을 로컬 HTTP로 검증했다.

## UI 갱신 성능 정리

목록 갱신에서 ID별 반복 검색을 한 번의 인덱스 구성으로 바꾸고, 같은 DOM 값의 재할당과 반복 하위 요소 검색을 줄였다. 초기화 시 같은 ID의 새 객체를 사용해도 이전 값이 남지 않는다. 시뮬레이션·관측 계산·입력 규칙은 변경하지 않았다.

- 새 UI 회귀 검사: `node --test tests/ui-cache.test.cjs`

이 측정은 목록 UI의 합성 마이크로벤치마크이며 게임 전체 FPS나 실기기 성능을 뜻하지 않는다. 기존 JavaScript 검사 53개와 새 검사 12개를 통과했다.

## WIP07A 관측 상태

화면용 시선 연출을 실제 관측으로 교체했다. 모션 줄이기·선택·카메라는 결과에 영향을 주지 않는다. seed가 같은 0.05초 스텝은 1×/2× 프레임 묶음에서도 같은 접촉 결과를 만든다. 미탐지는 숨기고, 미식별은 실제 외곽의 검은 실루엣, 식별은 정상 외형, 상실은 고정된 마지막 자세의 흐린 기억으로 표시한다.

전차장 독립 시야와 헌터킬러는 별도 프로파일 기능이다. 헌터킬러가 없어도 직접 지정과 포수 자체 관측이 가능하다. 포수 거리 밖 인계는 대기/만료하며 범위를 늘리지 않는다. [구현 문서](docs/OBSERVATION_WIP07A.md)에 정보 공개·기억·경계 우선·캐시 유효성·인계 상태와 모든 초깃값을 기록했다.

## WIP07A 보정

전차장은 전방 ±45°를 20초 주기로, 포수는 전방 ±15°를 12초 주기로 왕복 수색한다. 순간 시야각은 전차장 90°·포수 30°다. 포수는 자기 장비로 발견한 접촉을 직접 확인하고 유지하며, 전차장 단독 미식별 접촉 때문에 식별·인계 전에 돌아가지 않는다. 확보한 포수 표적은 새 자동 후보가 덮어쓰지 않는다. 전차장은 다음 후보를 저장하고 수색한다.

주변 탐지와 미완료 식별 감쇠를 분리했다. 팀 화면 정보와 선택 차량의 자체 관측·확보도 별도로 표시한다. 움직이는 표적의 건물·능선·숲 차폐, 기억 고정, 양 끝점/자세 변화의 캐시 무효화를 실제 코어로 검사한다. [현재 상태·출처·우선순위](docs/OBSERVATION_WIP07A.md), [작업지시서](docs/TACTICAL_WIP07A_OBSERVATION_CORRECTION_INSTRUCTIONS.md), [수정 전·후 및 검증 결과](TACTICAL_RELEASE_WIP07A.md)를 참조한다.

## WIP07B 최적화

32m 구역에 지형 보간 상한·건물 높이·숲 유무를 한 번 요약한다. 차폐와 숲 감쇠가 없다고 증명되는 구간만 건너뛰고 애매한 구간은 기존 2m 검사로 처리한다. 관측 주기·확률·9개 표본·광선 캐시·관측 출처와 표적 유지 동작은 바꾸지 않았다. 요약 자료는 코어당 265,625바이트다.

[알고리즘과 보수적 조건](docs/LOS_OPTIMIZATION_WIP07B.md), [원본 대조와 성능·전체 검증](TACTICAL_RELEASE_WIP07B.md), [3회 별도 프로세스 비교](tests/releases/WIP07B-comparison.json)를 참조한다. CPU 시간의 개선을 전체 FPS로 해석하지 않는다.
