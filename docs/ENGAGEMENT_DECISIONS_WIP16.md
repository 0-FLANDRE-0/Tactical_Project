# WIP16 적 AI 교전 판단·표적 선택·행동 안정화

WIP16은 WIP14 이동 임무와 WIP15 관측·장전·일시 이상 위에 작은 교전 판단 계층을 연결한다. AI가 명시적으로 활성화된 차량만 이 계층을 사용한다. 일반 `makeTank()` 차량과 수동 fixture의 기존 관측 자동 인계는 유지된다.

## 결정 순서와 소유권

고정 틱 순서는 이동 → 도착 비행체·피해·일시 이상 → 관측 → AI → 장전·조준·새 발사다. 관측 모듈은 실제 LOS/FOV·탐지·식별·인계와 `current/acquired`를 소유하고, AI는 자체 접촉 사본에서 목표 ID만 고른다. 사격 모듈은 포수 확보·정렬·조준·장전·실제 발사선·이동 조건을 마지막에 다시 검사한다.

AI 자동 표적은 observation의 별도 `ai` 출처로 전달한다. 동일 목표는 다시 지정하지 않아 조준과 속도 추정을 초기화하지 않는다. 사용자의 `manual` 지정은 즉시 우선하며 AI가 출처를 바꾸지 않는다. 수동 지정 취소 뒤에는 다음 고정 틱의 AI 판단에서 유효한 자동 표적으로 돌아간다. AI를 쓰지 않는 차량은 기존 전차장 후보 큐와 포수 자체 인계를 그대로 쓴다.

기존 발사선 검사가 차폐를 확인하면 그 결과만 AI에 전달한다. AI는 같은 기하에서 해당 후보를 2초 제외하고 대안을 고르며 후보별 LOS나 경로를 새로 계산하지 않는다. 관측자나 표적 위치·자세가 바뀌면 차폐 제외 기록을 무효화한다.

## 후보와 점수

자동 후보는 해당 차량의 자체 접촉 중 현재 관측·식별·적 확인이 모두 참이고 유효한 pose가 있으며 확인된 잔해가 아닌 대상이다. 거리는 관측 사본으로 계산하고 `min(주포 최대 사거리, 포수 최대 거리)` 이내만 허용한다. 팀 공유만 있는 접촉, 기억만 남은 접촉, 미식별 대상과 사거리 밖 대상은 제외한다.

점수는 다음 조정 가능한 시험식이다.

`1 - clamp(거리 / 유효 최대 사거리, 0, 1) + 포수 현재 관측 0.15 + 현재 표적 유지 0.15`

동점은 자체 최초 식별 시각이 빠른 순서, 안정된 접촉 key, 내부 대상 ID 순서로 결정한다. 식별 시각이 없으면 무한대로 취급한다. `lastSeen`의 작은 차이는 점수나 동점 순서에 쓰지 않는다.

| 시험 설정 | 값 |
|---|---:|
| 판단 주기 | 0.75초, 차량 ID별 결정적 위상 |
| 자동 표적 최소 유지 | 2.25초 |
| 전환 우위 | 현재 점수보다 0.20 초과 |
| 연속 우위 확인 | 같은 후보 2회 |
| 상실 유예 + 관측 대기 | 1.5초 + 2.5초 |
| 동일 차폐 기하 재선택 제한 | 2초 |
| 틱당 새 AI 경로 요청 | 2건 |
| 경로 실패 재시도 | 2초 |

현재 자동 표적이 유효하지 않으면 다른 유효 후보를 즉시 고른다. 유효한 현재 표적끼리 전환할 때만 최소 유지와 2회 연속 우위를 적용한다. 확인된 격파, 사용자 지정·취소, 유효성 상실은 최소 유지시간으로 지연하지 않는다.

## 교전과 기본 임무

`maintain`은 기본 경로를 유지하면서 선택한 표적을 인계한다. `halt`와 정차가 필요한 `auto`는 유효 표적을 선택한 뒤 기존 임무 ID·revision·경유점과 `active/blocked` 재개 상태를 보존하고 한 번만 제동한다. 표적이 바뀌어도 정차 상태를 해제하거나 정지 명령을 반복하지 않는다.

모든 유효 후보가 사라지면 1.5초 상실 유예와 2.5초 관측 대기 뒤 같은 임무·경유점으로 한 번 복귀한다. 재관측되면 기존 선택 흐름을 이어간다. 완료된 단일 이동 임무는 교전할 수 있지만 상실 뒤 부활하지 않는다. 확인된 잔해와 총탄약 0은 상실 대기를 기다리지 않고 자동 교전 정차를 해제한다.

장전 중이거나 사통 이상이 활성화돼도 총탄이 남아 있으면 표적과 임무를 보존한다. 전차장·포수 이상은 WIP15의 정상 관측과 조준 0.70배·오차 1.25배를 유지한다. AI는 `auto/hold`를 바꾸지 않으며 이동 정차 억제와 최종 발사 권한도 분리돼 있다.

## 정보 경계와 실행 비용

판단은 자기 위치·속도·프로파일·탄약/장전/일시 이상, 자체 관측 접촉 사본, 현재 임무·교전 상태만 사용한다. 상대 실체의 실제 좌표·HP·탄약·장전·이상·명령·비공개 격파 여부를 입력으로 받지 않는다. 자동 점수·대기·차폐 제외·임무 상태는 공개 snapshot, 효과와 적 UI에 들어가지 않는다.

AMD EPYC 9V74, Node v24.22.1의 별도 프로세스 측정에서 차량마다 현재 식별 후보 4개를 두고 모든 차량을 매 0.75초 판단에서 평가했다. 준비 100회 뒤 1,000회 측정 중 차량마다 실제 전환 1회를 만들었다.

| 순수 판단 | WIP15 main 중앙값 / P95 | WIP16 중앙값 / P95 |
|---|---:|---:|
| 50대 | 0.01461 / 0.02373ms | 0.08864 / 0.20502ms |
| 100대 | 0.02785 / 0.05789ms | 0.16871 / 0.30497ms |

100대 중앙값은 1ms 목표 안이다. 기본 5대 지도 시나리오 seed 7/17/27의 2초 준비·20초 측정에서 틱 중앙값의 중앙값은 0.27743→0.28426ms, P95의 중앙값은 0.55610→0.64123ms였다. 지도 결과는 선택 변화로 관측 후보와 전투 결과가 달라질 수 있으므로 순수 AI 증가로 해석하지 않는다. 세 seed 모두 경로 요청 3회·실패 0회였고 새 후보별 LOS·경로 탐색은 없다. 원자료는 `tests/releases/WIP16-*-benchmark.json`과 `WIP16-performance-comparison.json`에 있다.

## 재현과 한계

- 순수 선택·상태: `node --test tests/wip16-engagement.test.cjs`
- 실제 코어 연결: `node --test tests/wip16-core.test.cjs`
- 실제 Chromium: `node tests/wip16-browser.test.cjs`
- 순수/지도 성능: `node scripts/benchmark_wip16_engagement.cjs`, `node scripts/benchmark_wip16_map.cjs`

실제 Chromium fixture는 복수 표적의 AI 소유 인계, 이동 유지, 실제 정차, 상실 뒤 동일 경유점 단일 복귀와 공개 snapshot 경계를 확인한다. 기존 전체 앱, WIP15 반응, WIP12 효과 검사를 별도로 재실행한다.

엄폐 위치 탐색, 추격·우회·후퇴, 팀 집중사격, 전역 위협 지도, 숙련도·사기와 새 차종·탄종은 후속 범위다. 현재 점수와 시간은 실제 승무원 판단 성능이 아닌 게임용 초기값이다.
