# Tactical 관측과 식별 구현 준비안

검토 기준은 `0-FLANDRE-0/Tactical_Project`의 `main`, 커밋 `5eea28cf80deaa1ffdf9494090d3e2e3f621e636`, 배포 버전 `v0.4 WIP06`이다. 2026년 11월 6일 기준으로 소스와 기존 검사를 확인했다. 이 문서는 다음 구현을 위한 검토안이며 게임 기능이나 원격 저장소를 변경하지 않았다.

기존 지형·기동·차폐 계산은 재사용할 수 있다. 다음 작업의 중심은 실제 관측 상태, 탐지·식별 기록, 독립 시야 제어와 포수 인계를 고정 시간 간격의 시뮬레이션에 추가하는 것이다. 화면 표시와 클릭 처리에서는 이 기록을 읽도록 바꾼다.

## 1 대화에서 정한 게임 방향

여러 유닛을 지휘하는 전술 RTS를 전차부터 확장한다. 관측은 지형·건물·숲 차폐를 따르고, 표적을 발견하는 것과 정보를 식별하는 것을 구분한다. 전차장 관측 장비와 헌터킬러 기능의 차이가 수색과 표적 전환에 영향을 주게 한다.

| 항목 | 기준 설정 | 상태 |
|---|---|---|
| 기본 주변 관측 | 반경 200m, 전방위, 미식별 실루엣까지만 허용 | 사용자 제안에 따른 기준 |
| 전차장 관측 | 최대 2,500m, 포수보다 넓은 부채꼴 | 사용자 제안에 따른 기준 |
| 포수 관측 | 최대 2,000m, 실제 포탑 방향을 중심으로 한 부채꼴 | 사용자 제안에 따른 기준 |
| 포탑 선회 | 최대 40°/초 | 사용자 제안과 현재 프로파일 값이 일치 |
| 전차장 시야각 | 전체 폭 90° | 앞선 답변의 초깃값 제안 |
| 포수 시야각 | 전체 폭 60° | 앞선 답변의 초깃값 제안 |
| 전차장 독립 선회 | 최대 50°/초 | 앞선 답변의 초깃값 제안 |
| 방향별 관측 품질 | 시야 중심에 가까울수록 높음 | 사용자 요구 |
| 시간에 따른 관측 | 유효하게 관측한 시간이 길수록 발견·식별 가능성이 높아짐 | 사용자 요구 |
| 관측 높이 | 기존의 지면 위 2.65m를 초기 게임 기준으로 유지 | 기존 사용자 지정값 재사용 제안 |
| 고각과 부앙 | 후속 단계 | 앞선 범위 유지 |

200m 관측의 제한은 해당 관측 채널에 적용한다. 같은 표적을 전차장이나 포수가 관측하면 200m 안에서도 식별할 수 있다. 200m 안의 모든 표적이 무조건 보이는 규칙은 아니며, 이 채널에도 차폐와 탐지 조건을 적용한다.

## 2 표적 표시와 기억

| 현재 관측과 보유 정보 | 표시 | 공개 정보 |
|---|---|---|
| 미탐지 | 표시하지 않음 | 없음 |
| 탐지했지만 미식별 | 관측한 차체·포탑·포신 형상의 검은 실루엣 | 미식별 표적이라는 표시만 제공 |
| 식별했고 현재 관측 중 | 정상 외형과 색상 | 해당 식별 단계에서 허용한 정보 |
| 관측 상실 | 마지막 관측 위치의 흐린 잔상 | 마지막으로 확인한 정보와 관측 시점 |
| 기억 만료 | 잔상 제거 | 실시간 표적 정보 없음 |

관측 상실과 식별 지식은 별도 상태다. 한 번 식별한 차종을 잠깐 가려졌다는 이유로 즉시 잊게 할 필요는 없다. 다만 숨겨진 표적의 현재 위치·방향·상태가 기억 표시를 갱신해서는 안 된다. 잔상은 마지막 관측 당시 위치와 자세를 사용한다. 재관측 시 최근 기억의 유지 정도에 따라 빠른 재확인을 허용할 수 있다.

검은 실루엣은 기존 도안의 외곽을 재사용한다. 내부 패널선·질감·색상·이름·실제 ID·노출률·상세 패널은 숨긴다. 축소 상태의 표적 마커와 탭 선택에도 같은 정보 공개 규칙을 적용한다. 실루엣 형상 자체로 플레이어가 차종을 추측할 수 있는 것은 사용자가 선택한 표현 방식에 포함된다.

## 3 수색과 지정 경계

플레이어가 고르는 모드는 전차장과 포수 각각의 `자동 경계`와 `지정 경계`다. 자동 경계 내부에서 둘러보기, 미식별 표적 확인, 마지막 관측 지점 확인, 다시 둘러보기를 전환한다.

| 동작 | 전차장 | 포수 |
|---|---|---|
| 자동 수색 | 넓은 구역을 훑으며 수색 중심도 주기적으로 변경 | 진행 방향 또는 마지막 관심 방향 주변을 비교적 좁게 수색 |
| 실루엣 발견 | 시야 중심으로 가져와 식별 시도 | 직접 발견하거나 인계받은 표적을 확인 |
| 지정 경계 | 지정 지점 주변을 독립적으로 관측 | 실제 포탑을 돌려 지정 지점 주변 관측 |
| 관측 상실 | 마지막 위치를 잠시 확인하고 수색 재개 | 보유한 마지막 관측 위치를 확인한 뒤 대기 또는 수색 |

지정 경계는 월드 좌표의 지점을 저장한다. 차량이 이동하면 그 지점을 향한 방위를 다시 계산한다. 현재 구현의 고정 지도 방위와 동작이 다르다. 기존 5·10·30초 선택을 보존하려면 `해제까지` 선택을 추가하고, 기존 시간 선택은 선택 사항으로 둘 수 있다.

사용자 지정 경계는 자동 수색보다 우선한다. 지정 구역 안의 표적을 확인하는 것은 허용하되, 다른 방향의 실루엣 때문에 명령을 임의로 취소하지 않는다. 구역 밖 발견은 표시로 알린다. 입력 취소는 새 명령을 취소하는 것이며, 이미 실행 중인 경계 명령을 지우는 것과 구분한다.

자동 관심 방향의 근거는 실제로 발견한 실루엣, 마지막 관측 위치, 플레이어 관심 지점이다. 아직 발견하지 못한 적의 실제 좌표를 자동 수색의 목표로 사용하지 않는다. 같은 표적에 대한 최소 확인 시간과 짧은 관측 상실 유예를 둬서 시선이 매번 다른 표적으로 튀는 것을 줄인다. 구체적인 시간과 탐지·식별 속도는 게임 튜닝값으로 둔다.

## 4 헌터킬러와 장비 유무

기본 흐름은 수색 → 탐지 → 집중 관측 → 식별 → 포수에게 지정 전달 → 포탑 선회 → 포수의 표적 확보다. 포수가 확보하면 전차장은 다시 다른 방향을 수색한다.

`지정 전달`과 `포수 확보`는 다른 사건이다. 정보를 받았다고 포탑 방향이나 포수 가시선이 즉시 바뀌지 않는다. 이미 식별한 정보는 전달하되, 포수 자신의 시야·가시선·거리 조건을 다시 확인한다. 아직 사격 시스템이 없으므로 다음 관측 작업의 종료 상태는 표적 인계와 확보, 사격 준비 상태까지다.

| 프로파일 기능 | 게임 효과 |
|---|---|
| 전차장 관측 장비 활성 여부 | 별도의 전차장 관측 채널 사용 여부 |
| 전차장 시야의 독립 선회 여부 | 포탑과 다른 방향을 동시에 수색할 수 있는지 결정 |
| 헌터킬러 활성 여부 | 전차장이 식별한 표적의 자동 지정·포탑 유도 여부 |
| 전차장·포수의 거리·시야각·회전속도 | 수색 범위와 확인 지연에 영향 |

독립 시야가 있어도 헌터킬러는 별도로 끌 수 있어야 한다. 헌터킬러가 없을 때도 플레이어의 직접 지정과 포수 자체 관측은 사용할 수 있다. 독립 선회가 없는 장비는 해당 프로파일의 연동 방식에 따르게 하고, 존재하지 않는 독립 관측 부채꼴을 만들지 않는다.

전차장이 2,000~2,500m에서 식별하면 표적 정보와 지정은 전달할 수 있다. 포수의 2,000m 범위는 별도로 적용한다. 이 경우 `확보 대기`를 표시하고, 기다림이 무한히 지속되지 않게 취소·만료 규칙을 둔다. 기존 3,000m 주포 교전 기준은 비활성 메타데이터다. 이 값을 근거로 포수의 관측 범위를 자동으로 늘리지 않는다.

## 6 권장 상태와 처리 구조

### 상태 소유자

차량 프로파일에는 관측 채널의 활성 여부·독립성·거리·전체 시야각·높이·회전 한계와 헌터킬러 사용 여부를 둔다. 유닛에는 실제 전차장 방위, 포수와 전차장의 명령·수색 상태, 확인 중인 접촉, 인계 상태를 둔다. 포수의 실제 방위는 기존 `u.turret`을 그대로 사용해 중복된 실제 포탑 각도를 만들지 않는다.

관측 기록은 차량별로 관리한다. 기록에는 내부 접촉 키, 탐지·식별 단계, 현재 관측 여부, 누적 관측 효과, 마지막 관측 시각·위치·자세, 확인한 정보와 관측 채널을 포함한다. 초기화나 유닛 교체 후 이전 기록이 새 객체에 붙지 않게 한다.

화면의 아군 정보 공유는 기존 팀 단위 표시를 이어갈 수 있다. 다만 각 차량이 자체 관측했는지와 팀이 알고 있는지는 구분한다. 다른 아군이 표적을 안다는 이유만으로 해당 포수의 관측·확보 조건을 충족시키지 않는다. 현재 선택한 차량이나 카메라 위치는 관측 계산에 영향을 주지 않는다.

### 처리 순서

1. 이동과 실제 선회, 경계 명령의 목표 방위 갱신.
2. 거리와 방향을 이용해 관측 후보를 줄임.
3. 후보에 대해 지형·건물·숲 차폐와 부위 노출 조회.
4. 시야 중심에서의 각도, 거리, 노출과 유효 관측 시간을 이용해 탐지·식별 갱신.
5. 접촉 상태 변화에 따라 집중 확인·인계·재수색 전환을 예약.
6. 팀 표시용 접촉과 패널용 공개 정보를 구성.
7. 렌더러가 준비된 상태와 표시용 부채꼴을 그림.

새 표적을 발견했다고 같은 스텝 안에서 전차장 선회·포탑 선회·포수 확보까지 즉시 완료하지 않는다. 관측에 사용한 실제 방위와 화면 방위를 일치시킨다.

### 확률과 시간

관측 중심일수록 품질을 높이고 가장자리에서는 낮춘다. 완전히 가려진 동안에는 유효 관측을 쌓지 않는다. 짧은 단절에는 누적 효과를 서서히 줄이고, 오랫동안 놓친 표적은 단계적으로 기억을 만료시킨다.

확률은 시뮬레이션 시간에 따라 계산한다. 단순히 렌더링 프레임마다 같은 확률을 적용하면 고프레임에서 탐지가 빨라진다. 고정 스텝에서의 시간 정규화된 확률 또는 누적 관측 효과와 seed 기반 임계값을 사용할 수 있다. 탐지 난수는 카메라·UI·렌더링과 분리한다.

시야·범위 경계에 걸친 차량은 기존 부위 표본을 활용한다. 후보 제거에 표적 중심만 사용해서 실제로 보이는 앞부분까지 잘라내지 않도록 여유를 둔다. 숲의 누적 광학 깊이는 현재 `lineOfSight` 반환값에 이미 있으나 `exposure`는 이를 버리므로, 필요한 품질 요약을 보존하는 식으로 확장할 수 있다.

### 기하 차폐와 게임 관측의 분리

기존 `lineOfSight`는 기하학적 차폐 검사로 유지하고, 방향·관측 채널 거리·탐지 확률은 새 관측 판정에서 적용한다. 기존 4km 기하 조회와 200m·2,000m·2,500m 게임 관측을 구분한다. 전역 4,000m 값을 단순히 2,500m로 바꾸는 것으로 끝내지 않는다.

홀드 영역은 지면 위 1.5m 기준의 기하학적 가능 영역이다. 실제 차량의 부위 표본과 탐지·식별 확률을 대신하지 않는다. 표시 문구도 이 차이를 반영한다. 같은 위치의 기하 마스크는 재사용하고, 실제 회전하는 부채꼴과 중심 품질 표현을 화면에서 합성한다.

## 7 성능 확인과 구현 원칙

현재 `canTeamSee`와 같은 계산을 기존 지도상의 합성 정지 배치에서 측정했다. 한 번 준비 실행 후 9회 중간값이며, blue와 red를 같은 수로 배치했다.

| 총 유닛 | 아군과 표적 | 한 번의 표시 여부 판정 중 `exposure` 호출 | 계산 중간값 |
|---|---|---:|---:|
| 4 | 2 / 2 | 3 | 약 1.13ms |
| 20 | 10 / 10 | 34 | 약 9.75ms |
| 50 | 25 / 25 | 148 | 약 46.15ms |
| 100 | 50 / 50 | 218 | 약 56.63ms |

이는 관측 공개 여부 조회 루프만의 CPU 측정이다. 전체 게임 FPS, 브라우저 렌더링, 실제 휴대폰이나 다음 버전의 성능을 뜻하지 않는다. 초기 실전 배치나 모든 표적이 가려진 최악 조건의 측정도 아니다. 그럼에도 현재 방식의 매 프레임 재계산을 그대로 여러 관측 채널로 늘리기는 부담스럽다는 근거가 된다.

기존 전체 가시 영역 계산은 세 위치에서 약 294~447ms였다. 이 계산은 Worker에서 선택 차량의 홀드 표시를 위해 수행된다. 모든 전차의 탐지에 이 전체 영역 계산을 반복해서 사용하지 않는다.

권장 방식은 다음과 같다.

- 실제 선회와 명령 시간은 기존 20Hz 시뮬레이션 스텝에 통합.
- 탐지용 정밀 조회는 우선 10Hz를 초깃값으로 두고 차량별 작업을 분산. 결과는 렌더링과 패널에서 재사용.
- 후보 공간 인덱스와 거리·각도 선별을 먼저 적용하고 필요한 표적만 정밀 조회.
- 관측 높이와 표본 조건이 같으면 같은 차량·표적의 차폐 결과를 채널 사이에서 재사용.
- 이동·자세·지도 변경과 결과 유효기간을 기준으로 캐시를 갱신. 오래된 결과를 새 관측 시간으로 무조건 누적하지 않음.
- 표시용 기하 마스크는 위치와 높이가 같으면 재사용. 포탑이 돌아갈 때마다 전체 지형을 다시 훑지 않음.
- 선택 변경·초기화 뒤 늦게 도착하는 Worker 응답을 계속 차단.
- 관측 변경만으로 길찾기 캐시를 다시 제작하지 않음. 차량 반경·경사·지도는 이번 범위에서 유지.

## 8 WIP07 권장 작업 범위

다음 작업은 관측·식별·수색·포수 인계까지 하나의 기능으로 묶는다. 실제 발사·탄도·관통·피해·재장전과 고각은 이후 단계로 둔다.

1. 프로파일과 실제 선회 상태 추가. 전차장 독립 방위와 포탑 방위를 코어에서 관리하고 화면 연출의 방향 덮어쓰기를 제거한다.
2. 방향별 관측과 접촉 기록 추가. 주변 200m의 실루엣 제한, 중심 관측 품질, 시간 누적, 식별과 기억을 연결한다.
3. 자동 수색과 지정 경계 추가. 알려진 접촉만 확인하고 사용자 지정 구역을 지킨다.
4. 헌터킬러 인계와 포수 확보 추가. 기능 유무, 인계 취소·대기·관측 상실을 처리한다.
5. 실루엣·잔상·표적 패널·부채꼴·상태 표시를 접촉 기록에 연결한다.
6. 단일 HTML·데이터 내보내기·검사 로더·문서와 검증 결과를 새 계약에 맞춰 갱신한다.

새 관측 로직을 별도 파일로 나누면 `build.py`, HTML script 순서, 내장 Worker의 소스 목록, `tests/load.cjs`와 입력 검사 로더를 함께 변경한다. 기존 시선 연출만을 보장하는 검사는 실제 관측 동작을 확인하는 검사로 전환하되, 입력 취소·드래그·핀치·일시정지·선택 변경 회귀는 유지한다.

`scripts/export_vehicle_profile.cjs`와 `data/vehicles/README_KO.md`도 기존의 360° 통합 관측 설명을 새 구조로 바꿔야 한다. UI의 고정 4km 문구와 비활성 3km 주포 기준도 관측 장비별 값과 구분해 표시한다. 새 프로파일 수치는 게임 설정으로 기록한다.

| 장비 차이 | 독립 시야·헌터킬러 비활성 시 해당 기능이 실행되지 않음 |
| 거리 차이 | 2,000~2,500m 표적 인계가 포수 관측 거리 증가로 이어지지 않음 |
| 정보 공개 | 미식별 마커·클릭·패널·이름에 식별 정보가 나타나지 않음 |
| 관측 상실 | 잔상이 숨겨진 실제 표적의 이동·방향을 따라가지 않음 |
| 숨은 표적 | 자동 경계가 미발견 적의 실제 좌표로 돌아가지 않음 |
| 시간 재현성 | 동일 seed에서 렌더링 배치·1×와 2×·카메라·선택 변경에 관측 결과가 유지됨 |
| 접근성 | 모션 줄이기 설정이 실제 수색·관측 성능을 바꾸지 않음 |
| 초기화와 비동기 | 이전 접촉·명령·Worker 응답이 새 시나리오로 넘어오지 않음 |
| 실행 비용 | draw·패널 갱신에서 정밀 가시선 호출이 증가하지 않으며 50·100대 비용을 별도 측정 |

실제 Chromium과 모바일 viewport에서는 새 제어 UI, 실루엣, 부채꼴, 좌표 경계 명령, 오류 로그를 확인한다. 실제 Android의 터치·발열·지속 성능은 실기기로 따로 확인한다.
