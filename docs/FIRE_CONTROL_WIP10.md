# WIP10 게임 지연 판정 — 부분 구현

2026-11-07 KST. **업로드 지시서 전체를 구현한 버전이 아니다.** 발사/대기/결과 상태와 공개 정보·UI를 구현하고, 예측 발사 방향·실탄속/중력 비행·실제 지형 탄착은 제외했다. 화면의 비행과 효과는 고정 시간의 게임 연출이다. 원문과 Python은 저장소에 재배포하지 않았으며 [파일 크기·SHA-256·범위](WIP10_SOURCE_SCOPE.json)로 출처를 기록한다. 제공 WIP10 Python과 물리 기준표는 실행·검증하지 않았다.

시작은 WIP09 `04d6d2e85bd4e599332f03f0614989dbbc79990b`, 브랜치는 `feat/wip10-flight-impact`다. 최신 main `7117fbadabd0493248d328cb8b6fdfa8139d242e`를 `1a95ac5`에서 정상 병합했다. PR #4/#5는 시작 시 미병합이며 이번 작업도 별도 초안으로 검토한다. main 병합·공개 배포는 하지 않는다.

## 시간과 상태

발사 입력은 기존 포수 자체 확보·실제 정렬·거리·탄수·간격·새 LOS 게이트를 통과해야 한다. 승인된 고정 스텝에서 탄수 1발을 사용하고 단발 번호/간격을 갱신한다. `fired` 이벤트에는 결과나 부위가 없으며, 이때 결정용 난수는 호출하지 않는다.

게임 기한은 `fireControl.flightSeconds` 뒤다. 기본 **0.8초**로 거리·탄속·중력과 독립이다. 0.05초 스텝에서 기한에 처음 도달하면 판정한다. 같은 기한은 이벤트 ID 순서로 처리한다. 일시정지는 게임 시간과 대기 시간을 함께 멈춘다. 배속/프레임 묶음은 같은 시뮬레이션 시간에서 동일한 결과를 낸다.

비공개 비행 레코드는 발사 당시 포구·발사선 높이·프로파일 사본·이미 알려진 표적 자세·차체/포탑 확률을 보관한다. 사수 이동/선회/선택/명령 취소는 이미 시작한 대기를 바꾸지 않는다. 표적 삭제는 안전하게 빗나감으로 마치고, 새 장면은 이전 레코드/이벤트/조준을 공유하지 않는다.

기한에는 저장한 포구에서 현재 표적의 기존 차체/포탑 노출을 조회한다. 사수의 현재 포수 FOV나 포구 위치로 다시 발사 허가를 요구하지 않는다. **기존 광학 LOS 조회이며 탄체 경로 충돌이 아니다.** 저장된 두 확률 질량을 현재 노출 감소 비율만큼 낮추고, 전부 가려졌거나 삭제되면 0으로 처리한다. 노출이 늘어도 발사 때 확률을 넘지 않는다. 발사 후 이동에 따른 예측 오차나 새 가로/세로 편향은 계산하지 않는다.

기한에 기존 seed/사수 ID/단발 번호의 명중·구역 해시 두 개를 한 번씩 읽는다. 명중일 때만 두 번째 값을 구역 선택에 사용한다. 렌더링·패널·읽기·효과는 결정 스트림을 바꾸지 않는다. 내부 `errorBudget`과 WIP09 `sigma.man` 등 계수는 그대로다. WIP09 진단 `breakdown.tof`는 이전 확률 모델의 척도이며, 새 `fired.tof`는 **고정 게임 대기 시간**이다. 둘을 물리 비행 시간으로 해석하지 않는다.

## 조준과 이동 관측

`resetAim`은 준비/연속 조준만 비운다. 관측 벡터는 같은 표적의 새 자기 포수 위치 표본으로 갱신하며, 발사/발사 간격/잠깐의 정렬 실패/단순 조준 취소로 즉시 0이 되지 않는다. 표적 키가 바뀌거나 마지막 유효 표본 이후 `queryPeriod × 5`(기본 0.5초)를 넘으면 이동 관측을 비운다. 숨겨진 실제 속도는 읽지 않는다. 실제 지정 해제 후에는 다음 스텝의 표적 키 변경도 적용된다.

## 부위와 공개 정보

차체/포탑 각각 해당 직사각형의 길이·폭과 현재 방향으로 전/측/후의 투영 비중을 구한다. 상부는 계속 0이다. 명중 조건부 차체/포탑 비중은 기존 두 확률 질량에서 나오며 합은 1이다. 측면이면 해당 부위의 방향을 기준으로 좌/우를 덧붙인다. 차체와 포탑이 반대 방향이면 측면 이름도 달라질 수 있다. 장갑 구역이나 관통 판정은 아니다.

`impact` 공개 이벤트는 팀이 현재 관측하는 접촉이면 명중/빗나감·구역·좌우·게임 확률을 제공한다. 현재 관측하지 못하면 `result:'unobserved'`, 부위/좌우/최종 확률/효과는 모두 `null`이다. 숨겨진 명중과 빗나감의 공개 이벤트는 같으며 효과 유무로 결과를 유출하지 않는다. 내부 ID·실제 위치·비공개 레코드는 공개 snapshot에 넣지 않는다. `lastShot`도 정제한 공개 사본이다. 현재 공개 접촉의 위치만 효과 기준으로 사용할 수 있다.

개발 기록은 명시적으로 `recordFireEvents:true`인 검사 장면에서만 켠다. 기본 게임에서는 꺼져 있다. 이벤트와 개발 기록은 각각 최대 200건이며 외부 읽기는 사본이다. 활성 대기 목록에는 자기 단발의 ID/기한/남은 시간만 공개한다.

## 화면과 프로파일

실제 포구에서 알려진 표적 위치까지 진행하는 선/점은 판정을 예고하지 않는 중립색 화면 애니메이션이다. 결과 뒤 관측 중 명중은 접촉 위치에 섬광, 빗나감은 알려진 외곽 밖 화면 픽셀 먼지를 2초 표시한다. 월드 탄착 좌표나 높이, ground/building/beyond 종류를 생성하지 않는다. 효과용 해시는 판정 뒤 독립 키로 만들고 화면 효과만 제어한다.

`flightSeconds=.8`은 0.05~5초, `effectSeconds=2`는 0초 초과~5초의 유한 값으로 검증한다. `muzzleVelocity` 등 WIP09 설정을 실제 비행 시간에 연결하지 않는다. 시험탄은 42발 그대로이며 이력 상한 검사만 합성 차량 탄수를 105발로 설정한다. `node scripts/export_vehicle_profile.cjs`가 JSON과 필드 근거를 내보낸다. 차량/도안 레지스트리는 합쳐지지 않는다.

우측 패널은 현재 식별 접촉에만 예상 요약 한 곳을 표시한다. 비행 카운트다운과 결과 미확인은 아군 관측 HUD에 표시해 기억 표적의 상세정보를 열지 않는다. 기존 `hitSummary` 중복 요소를 제거했다. 미식별/기억은 오차·예상 부위·결과 상세를 숨긴다. 렌더링에서 노출을 재조회하지 않는다.

## 검증

새 `tests/game-flight.test.cjs`는 지연·발사 시 난수 미호출·단일 완료·기한 정렬·사수 이동/취소·관측 상실·숨겨진 명중/빗나감의 동일 공개 결과·노출 차단·표적 삭제·이력 상한·재현성·투영/좌우·벡터 유지와 초기화를 검사한다. 실제 Chromium에서는 비행 중 일시정지, 포구 일치, 모바일 HUD, 미관측 상세 숨김도 확인한다.

지도·기동·탐지·식별·9개 표본·시야 Worker·M1A2 외형은 유지한다. 새 런타임 모듈이 없으므로 build.py·HTML·내장 Worker·Node/입력 로더의 순서도 유지한다. 이전 LOS/관측 동결 원본과 WIP09 35행 기준표는 별도 회귀다. [검사 수·성능·산출물·미실행 항목](../TACTICAL_RELEASE_WIP10.md).
