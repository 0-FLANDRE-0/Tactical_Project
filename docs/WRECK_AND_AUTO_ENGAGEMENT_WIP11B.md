# WIP11B 영구 잔해·기본 자동교전

WIP11B는 WIP11A의 M1A2 (1998)·M829A2·HP 피해 경로를 유지하면서 두 부분을 연결한다. 격파 차량은 관측 대상에 남아 나중에 잔해로 식별할 수 있고, 한 번 확인한 잔해는 해당 팀에 영구 공개된다. 실행 시나리오의 양측 차량은 기존 관측·헌터킬러·포수 확보·조준·발사선 재검사를 거쳐 자동 단발을 수행한다. 이는 기존 표적을 사용하는 기본 게임 로직이며 전체 OODA나 정교한 위협 평가는 아니다.

## 관측자와 잔해 후보

`TacticalObservation.advance(observers, dt, now, candidates)`는 행동 주체와 관측 후보를 분리한다. 살아 있는 차량만 선회·관측·인계·사격을 수행하고, 격파 차량도 `candidates`의 공간 후보로 남는다. 탐지 거리, 채널 FOV, 10Hz 분산 조회, LOS, 노출 표본, 숲 감쇠와 탐지·식별 누적은 기존 규칙을 그대로 사용한다.

격파 사실은 단순 생전 식별 기록으로 공개되지 않는다. 관측자가 잔해를 실제로 다시 탐지하고 전차장이나 포수의 식별 가능한 광학 표본을 얻은 경우에만 자체 접촉에 `wreckConfirmed`가 생긴다. 주변 200m 채널만으로는 잔해를 식별할 수 없다. 확인된 잔해는 교전 임무·전차장 후보·포수 자체 확보 후보에서 제외된다.

`TacticalCore`는 팀별 `WeakMap<scenario, Map<contactKey,wreck>>`에 최초 확인 위치·차체/포탑/CITV 자세·표시 모델을 복사한다. 이 사본은 일반 접촉 기억과 지식 만료를 넘어서 유지되고, 반복 관측자와 조회가 같은 키를 중복 생성하지 않는다. 반대 팀에는 자동 공유되지 않으며 숨은 실제 객체를 렌더링 때 따라가지 않는다. 새 시나리오는 새 런타임 맵을 사용하므로 초기화 뒤 이전 잔해가 남지 않는다.

착탄 순간 실제 관측된 격파도 같은 사본 형식으로 즉시 들어간다. 미관측 격파는 내부 HP와 점유만 바뀌며 공개 결과·좌표·HP를 만들지 않는다. 같은 공개 기억 접촉이라면 숨은 실제 생존/격파 상태와 무관하게 지정 명령을 같은 방식으로 수락한다. 실제 발사는 이후 자기 포수의 재확보와 발사선 검사에서 막힐 수 있으며, 비공개 격파를 이유 문자열로 공개하지 않는다.

## 선택과 점유

잔해는 실제 유닛 객체와 기존 차량 반경을 유지해 이동을 막는다. 아군·적군 모두 지도 hit-test, 명단, 선택 순환, 직접 선택 API, 표적 지정과 자동 후보에서는 제외된다. 잔해를 누르면 지면 입력 규칙으로 넘어간다. 선택한 아군이 격파되면 다음 생존 아군으로 옮기고, 전부 격파되면 선택 없음 상태가 된다. 이 상태에서도 카메라, 확대, 일시정지와 초기화가 동작하며 시야 Worker·관측 UI·사격 단축키는 빈 선택을 안전하게 처리한다.

## 차량별 auto와 hold

사격 런타임은 프로파일과 분리된 차량별 `fireMode`를 가진다.

| 모드 | 동작 |
|---|---|
| `auto` | 준비 상태가 되면 `source: auto` 요청을 고정 스텝에서 한 번 만들고 공통 발사 경로로 보낸다. |
| `hold` | 자동 요청만 만들지 않는다. 관측·인계·확보·조준과 차폐 표적 전환은 계속하고, 발사 버튼/G의 `source: manual` 단발을 허용한다. |

`makeTank()`의 호환 기본값은 `hold`다. `createScenario()`는 생성한 양측 차량을 명시적으로 `auto`로 전환한다. 모드는 공용 동결 프로파일을 바꾸지 않는다. `auto → hold`는 아직 실행되지 않은 자동 요청만 지우며 수동 요청과 이미 날아가는 탄은 보존한다. 같은 스텝에 수동 요청이 먼저 있으면 자동 요청이 덮어쓰지 않으므로 탄수와 착탄당 피해는 한 번만 변한다.

자동과 수동은 동일한 `freshSight → estimate → flight → impact → combat damage` 경로를 쓴다. 팀 접촉만으로 요청하지 않으며 차량 자체 접촉의 식별, 포수 `acquired`, 자기 포수 현재 관측, 실제 포탑 정렬, 사거리, 탄수, 간격과 조준 완료가 모두 필요하다. 발사 직전 포수 광학과 실제 포구 발사선의 차폐를 다시 검사한다. UI·RAF·Worker와 상태 조회는 요청을 만들거나 명중/구역 난수를 소비하지 않는다.

## 표적 상실과 전차장 다음 후보

전차장은 현재 표적과 별도로 자신이 현재 관측·식별한 적만 안정 순서로 후보 목록에 둔다. 팀 공유만 있는 접촉, 미식별·만료 접촉과 확인된 잔해는 후보가 아니다. 포수가 확보한 A는 간격 대기·조준 중·새 인계 선회 중이라는 이유만으로 바뀌지 않는다.

A의 포수 관측이 기존 `lossGrace` 뒤에도 복구되지 않거나, 발사 직전 광학은 보이지만 포구 발사선이 차폐되면 `retarget()`가 유효한 전차장 후보 B를 찾는다. A 임무와 미실행 A 요청·조준은 정리하고 B를 `commander` 출처로 지정한다. B는 즉시 확보되지 않으며 실제 포탑 선회와 포수 재관측·확보·조준을 다시 거친다. B가 유효한 동안 A가 다시 나타나도 왕복하지 않는다. 후보가 없으면 기존 상실·만료 규칙을 유지한다. `hold`도 이 전환을 수행하지만 자동 발사는 하지 않는다.

## 고정 스텝 순서

`TacticalCore.step()`의 실행 순서는 다음과 같다.

1. 시뮬레이션 시간을 늘리고 각 유닛의 전투 상태를 초기화한 뒤 이동을 갱신한다.
2. 살아 있는 관측자와 전체 차량 후보로 관측·선회·접촉·인계 상태를 갱신한다.
3. 새로 실제 식별된 잔해를 팀별 영구 공개 사본으로 확정한다.
4. 사격 상태에서 표적 변경 리셋, 속도 추정, 조준 진행과 auto 요청 생성을 처리한다.
5. 수동 또는 자동 대기 요청 하나를 공통 `freshSight` 관문으로 실행한다.
6. 해당 시각에 도달한 비행을 `(impactAt, shotId)` 순으로 해결하고 내부 피해·격파와 허용된 공개 결과를 만든다.

같은 seed·고정 스텝·명령에서는 렌더링 묶음과 UI 조회 횟수와 무관하게 같은 결과가 난다. 이미 발사한 탄은 모드 전환, 지정 취소나 사수 격파 뒤에도 해결된다.

## 공개 정보와 UI

팀 접촉과 차량 자체 접촉은 계속 분리한다. 적 자동교전은 코어에서 같은 규칙으로 실행되지만 적의 내부 모드, HP, 실제 ID·좌표와 전역 발사 이벤트를 청색 UI에 추가 공개하지 않는다. `combatView`의 최근 피해는 내부 착탄 ID와 대상 ID를 제거한다. 공개 발사/착탄은 기존 팀별 정제 경로를 사용한다.

선택 차량 패널의 작은 버튼은 `자동 사격`과 `자동 사격 보류`를 전환하고 차량을 바꾸어도 각 런타임 상태를 유지한다. 확인된 잔해가 현재 표적이 되면 표적 패널을 닫는다. 개발 snapshot도 선택 팀의 허용된 접촉과 정제된 전투 상태만 제공한다.

## 성능 경계와 후속 범위

자동교전은 기존 10Hz 관측 후보·LOS 캐시와 현재 임무를 사용하며 적 전체를 추가로 전수 탐색하지 않는다. 자동 요청은 0.05초 고정 스텝 안에서만 평가한다. 실제 활성 auto 50/100대 fixture는 관측, 인계, 조준, 발사, 비행, 피해, 격파와 재표적을 함께 측정하며 렌더링과 길찾기는 제외한다. 결과는 `tests/releases/WIP11B-auto-benchmark.json`에 있다.

정교한 위협 점수, 자유사격/응사만/사격금지 ROE, 적 자율 이동·후퇴·엄폐, 실제 장전 절차, 탄종 선택·보급, 모듈·승무원·화재·유폭·수리와 비관통 근접피해 적용은 후속이다. WIP10부터 남은 미관측 빗나감 먼지 공개 정책도 이번 작업에서 확정하지 않았다.
