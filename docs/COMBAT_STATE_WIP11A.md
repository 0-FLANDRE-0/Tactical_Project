# WIP11A 피해·격파 상태

> 후속 WIP11B는 격파 차량을 관측 후보에 남겨 잔해를 나중에 식별하게 하고, 확인 잔해를 팀별 영구 공개 사본으로 유지하며, 양측 기본 자동교전을 추가했다. 현재 잔해·선택 규칙은 [WIP11B 구현 문서](WRECK_AND_AUTO_ENGAGEMENT_WIP11B.md)를 따른다. 아래는 WIP11A 당시 피해 경로의 기록이다.

WIP11A는 WIP10이 착탄 시점에 확정한 명중 여부, 차체/포탑 구역, 전·측·후와 좌우를 다시 추첨하지 않고 게임식 관통·HP 피해로 연결한다. 활성 시험 시나리오의 아군과 적군은 모두 불변 프로파일 `M1A2_1998`, 단일 탄약 `M829A2`를 사용한다. 기존 `M1A2`는 WIP10 기준표와 호환 검사를 위한 동결 프로파일이다.

## 데이터 경로

`src/vehicle-profiles.js`의 `M1A2_1998.combat`에는 최대 HP 1,450과 구역별 KE/CE 게임 방호값이 있다. WIP11A는 KE만 사용한다. `weapons.mainGun.ammunitionId`가 `M829A2`를 가리키며, `src/combat-state.js`의 불변 탄약 레지스트리가 다음 값을 소유한다.

- 10m: 입사각 0°/30°/60°에서 675/570/390
- 2,000m: 635/535/365
- 100% 피해 기준 405
- 피해 배율 기준점: `(0,.65)`, `(.071429,1.05)`, `(.142857,1.08)`, `(.714286,.65)`, `(.857143,.35)`, `(.93,.20)`

거리와 각도 표 안은 선형 보간하고 바깥은 끝값으로 고정한다. 관통력이 방호값 이상이면 `잔여 관통비=(관통력-방호값)/관통력`을 피해 곡선에 대입한다. 비관통 피해는 0이며 추가 탄속 피해 보정은 1이다. HP는 내부 실수로 유지하고 UI만 반올림한다. 이 값은 사용자 지정 게임 데이터이며 실장비 성능 검증값이 아니다.

`node scripts/export_vehicle_profile.cjs`가 `data/vehicles/M1A2_1998.json`, `data/ammunition/M829A2.json`, schema 2 차량 레지스트리를 같은 실행 데이터에서 만든다. 공유 프로파일과 탄약은 깊게 동결되고, 현재 HP·탄수·생존 상태는 유닛별 런타임에 있다.

## 착탄 연결과 처리 순서

`src/fire-control.js`는 같은 시각 착탄을 `impactAt`, 탄 ID 순으로 정렬한다. WIP10의 실제 위치·자세·차폐로 명중과 구역을 한 번 확정한 직후, 공개 이벤트를 정제하기 전에 `onImpactResolved`를 호출한다. `src/sim-core.js`가 대상 유닛을 찾아 `TacticalCombatState.apply()`에 넘긴다.

1. 고유 착탄 ID, 대상 상태와 프로파일을 검증한다.
2. 빗나감이면 피해 0으로 완료한다.
3. 명중이면 실제 구역 방향과 발사 원점으로 입사각을 구하고 게임 관통표를 조회한다.
4. 관통이면 피해 곡선과 기준 피해 405를 적용해 HP를 `[0,maxHp]`로 제한한다.
5. HP가 0이 된 첫 사건만 격파로 전이한다.
6. 그 뒤 팀 관측 여부를 조회한 기존 공개 규칙에 따라 공개 이벤트를 만든다.

실제 `<사수>-shot-<순번>` ID는 사수별 연속 순번과 아직 순서가 오지 않은 작은 집합으로 압축해 같은 콜백·조회가 반복돼도 피해가 중복되지 않는다. 합성/외부 ID는 최근 4,096개로 제한하고, 전투 결과 기록은 최근 200건으로 제한한다. 공개/진단 조회는 HP와 난수 상태를 바꾸지 않는다. 피해 계산은 새 난수를 쓰지 않으므로 WIP10의 hit/zone/표시 난수 스트림이 유지된다.

발사 시점에는 탄수만 줄며 HP는 유지된다. 발사 뒤 사수가 이동·선회·지정을 취소하거나 격파돼도 이미 생성된 비행은 남는다. 대상이 먼저 격파되거나 제거되면 이후 착탄은 `target-destroyed` 또는 `target-unavailable`로 안전하게 종료한다.

## 격파와 잔해

격파 유닛은 속도·경로·조준·관측 명령을 정리하고 새 이동, 정지, 경계, 지정, 사격 명령을 거부한다. 관측 후보와 관측자 목록에서도 제외한다. 유닛 객체와 위치는 시나리오에 남아 기존 동적 차량 점유 반경으로 통행을 막는다. 지도나 내비게이션 캐시는 다시 굽지 않는다.

적 격파가 착탄 순간 관측되었을 때만 해당 팀에 고정된 잔해 공개 사본을 만든다. 이 사본은 그 순간의 위치와 자세를 보존하며 숨은 실제 상태를 따라가지 않는다. 미관측 명중은 내부 피해를 적용하지만 공개 이벤트의 구역·방호·피해·HP를 `null`로 유지하고 새 잔해 좌표도 만들지 않는다. 적 기억 접촉은 기존 만료 규칙을 따른다.

선택 아군 패널은 형식, M829A2, 현재/최대 HP와 생존/격파를 표시한다. 현재 관측 중인 적에 대해서만 최근 공개 착탄의 관통·피해 결과를 보여 준다. 개발 snapshot은 아군 런타임과 팀 공개 접촉만 포함한다.

## 빌드와 Worker

페이지 순서는 차량 프로파일 → 차량 좌표 → 관측 → 전투 상태 → 사격 → 코어다. `tests/load.cjs`와 입력 검사도 같은 순서로 읽는다. 전투 상태는 시야 계산에 필요하지 않으므로 `visibility-client.js`의 내장 Worker 소스 묶음에는 넣지 않았다. Worker가 사용하는 코어 경로는 차량 생성·피해 함수를 호출하지 않으며 실제 Worker 검사가 이를 확인한다.

## 후속 범위

생존 차량의 모듈·궤도·승무원 피해, 화재·유폭·수리, ERA나 복합장갑 소모, 도탄·신관, 고폭/파편, 보병, 탄종 선택, 상세 장전·보급과 AI 자동 발사는 후속 작업이다. `upper`는 기존 명중 분배에서 0인 상태를 유지한다.
