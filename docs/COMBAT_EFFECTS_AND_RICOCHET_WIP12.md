# WIP12 사격 이펙트·고각 관통·도탄

WIP12는 전투 결과와 화면 표현을 분리한다. 명중·피격 구역·입사각·도탄·관통·피해를 고정 0.05초 시뮬레이션에서 먼저 확정하고, 그 결과로 최소 공개 효과 사건을 만든다. 파티클의 위치 흔들림, 텍스처, 품질, 줌, DPR, 렌더링 간격은 전투 API를 호출하지 않으며 판정을 바꾸지 않는다.

## 게임 판정

활성 범위는 양측 `M1A2_1998`과 `M829A2` 한 종류다. 기존 10/2000m 거리 노드와 0/30/60° 관통 표, 구역 방호, HP와 피해 배율을 유지한다.

- 0–60°는 기존 표의 이중 선형 보간을 그대로 사용한다.
- 60–90°는 해당 거리의 기존 60° 관통값에서 90°의 0까지 선형 보간한다. 75°는 60° 값의 절반이다.
- 90°를 넘는 입력은 방어적으로 90°에 고정하고 `angleClamped`를 기록한다. 관통값 0에서 나눗셈이나 음수 피해가 발생하지 않는다.
- M829A2 도탄 확률은 78° 0%, 80° 50%, 81° 100%이며 구간 안에서 선형 보간한다. 비교 규칙은 **`ricochetRoll < ricochetChance`**다. 따라서 80°에서 roll 0.5는 도탄하지 않는다.
- 유효한 명중에만 `shooterId:shotNumber:ricochet` 키의 독립 난수를 한 번 사용한다. 기존 `hit`과 `zone` 키의 결과·순서는 바뀌지 않는다.
- 선택된 전/측/후 면과 좌우, 착탄 시점의 실제 차체 또는 포탑 방향으로 기존 입사각 함수를 호출한다. 표시 탄착점이나 효과 방향으로 면을 다시 고르지 않는다.
- 도탄은 `reason: "ricochet"`, `penetrated: false`, `damage: 0`으로 끝난다. 표시용 튕김 탄광은 새 비행·충돌·피해·격파 사건을 만들지 않는다.

`TacticalCombatState.apply()`는 중복 ID를 평가와 난수 소비 전에 거른다. 같은 ID를 다른 도탄 roll로 다시 전달해도 HP와 기록이 바뀌지 않는다. 런타임 탄약 레지스트리와 [`data/ammunition/M829A2.json`](../data/ammunition/M829A2.json)은 같은 고각 한계와 도탄 데이터에서 생성된다.

## 공개 효과 사건

기존 상세 사격 사건은 계속 발사 팀으로 필터링하며, 미관측 명중의 구역·탄착점·방호·HP를 숨긴다. 그 옆에 `TacticalCore.effectEvents()`가 양 팀 공통의 표시 전용 사건을 제공한다. 효과가 드러내는 순간 위치·방향과 정성적 충돌 종류는 WIP12에서 의도한 공개 정보다.

| 종류 | 공개 필드 |
|---|---|
| 발사 | 불투명 순번 `id`, `kind`, 발생/만료 시각, 고정 `origin`, `heading`, 표시 거리·기간, `visualSeed` |
| 충돌 | 불투명 순번 `id`, `kind`, 발생/만료 시각, 고정 `position`, `effectClass`, 같은 표시 비행의 불투명 `flightEffectId`, 도탄 시 표시 방향, `visualSeed` |

효과 ID는 시나리오별 `fx-1`, `fx-2` 순번이며 내부 차량·발사 ID를 포함하지 않는다. `flightEffectId`도 이 공개 효과 순번만 가리키며 유닛이나 내부 사격 ID로 역참조하지 않는다. 렌더러는 미처리 비행의 표시 원점·시각·방향을 입자 수명과 분리된 제한형 연결 기록으로 보관한다. 착탄이 확정되면 살아 있는 예광을 찾거나, 화면 프레임 지연으로 예광 입자가 먼저 만료됐으면 그 기록에서 짧은 종단 예광을 복원한 뒤 종점을 충돌 `position`으로 교체한다. 사건을 먼저 연결하고 현재 시각의 만료 정리를 수행하므로 2배속·긴 화면 프레임도 연결을 잃지 않는다. 연결 기록은 처리 즉시 제거하고 처리 ID와 같은 1,024개 상한 및 사건 만료 시각으로 정리한다. 판정 시각·명중/구역/도탄 난수는 그대로이고, 임시 목표 거리에서 예광이 끝난 뒤 다른 지점에 충돌 효과가 생기던 표시 불일치만 없앤다. 사수/표적 객체나 ID, 이름·차종·프로파일, 팀, 현재 HP, 피해·방호 수치, 잔탄, 지정 정보는 없다. 반환값은 분리된 사본이다. 렌더러는 ID로 유닛을 찾지 않고 사건에 저장된 좌표만 사용하므로, 사수가 이동·선회·격파돼도 이미 발생한 섬광이 숨은 실제 위치를 따라가지 않는다.

효과 큐는 256개가 상한이고 각 사건은 시뮬레이션 시각 기준 만료 시 제거된다. 발사는 착탄 직후, 충돌은 3.2초 안에 만료한다. 숨은 적의 명중과 빗나감 모두 같은 경로로 충돌 효과를 낸다. 이 공개 효과로 접촉·식별·선택·지정·잔해를 새로 만들지는 않는다.

## 텍스처와 렌더러

[`assets/effects/wip12-effects-atlas.png`](../assets/effects/wip12-effects-atlas.png)은 저장소에서 직접 생성한 256×64 RGBA PNG다. 네 64×64 셀에 황백색 포구 섬광, 회백/회갈색 연기·먼지, 작은 충돌 불꽃, 짧은 예광을 담았다. [`scripts/build_effect_atlas.py`](../scripts/build_effect_atlas.py)는 Python 표준 라이브러리만으로 같은 atlas를 만들며, 제작 설명은 [`assets/effects/README.md`](../assets/effects/README.md)에 있다. 현재 PNG SHA-256은 `f70eb173ed14eb6d8ebc7927f408987a588777cd62216891ffac0ece2bf39340`이다.

`build.py`는 PNG를 data URL로 단일 HTML에 내장한다. `TacticalEffects`는 시작할 때 이미지 객체 하나를 만들고 256×64 디코딩 성공을 검사한다. 실패하면 기본 도형으로 효과만 대체해 게임 시작을 유지하지만, 실제 Chromium 검증에서는 `ready=true`, `error=false`를 필수로 확인한다. 프레임마다 이미지나 별도 캔버스를 만들지 않는다.

- 파티클 상한 384개, 처리한 효과 ID 상한 1,024개다. 새 사건을 넣기 전에 만료 입자를 시뮬레이션 시각으로 제거한다. 남은 예산이 부족하면 새 부가 입자를 생략하고, 핵심 입자가 들어올 때는 가장 오래된 부가 연기·먼지/불꽃을 먼저 제거한다. 핵심만으로 상한을 넘는 경우에만 가장 오래된 핵심을 제거한다.
- 핵심 포구·예광·충돌·도탄 탄광을 부가 입자보다 우선한다. 품질 설정은 부가 입자 일부를 그리지 않고, `prefers-reduced-motion`은 부가 연기·먼지·불꽃만 생략한다. 기본 상한에서 80발을 두 0.05초 프레임에 나눠 넣은 검사는 0.1초에 포구 80개와 예광 80개를 모두 보존하고 부가 입자 16개만 줄인다.
- 일시정지는 효과 시각도 멈춘다. 초기화는 입자와 중복 방지 기록을 지운다. 선택·카메라·줌 변경은 사건을 재생성하지 않는다.
- 화면 크기는 줌의 제곱근을 따르되 최소/최대 픽셀 크기로 제한한다. 예광은 이동하는 밝은 핵 주변의 짧은 구간만 그려 긴 레이저처럼 남지 않는다.
- 도탄 방향은 선택 면의 법선과 입사 방향을 반사한 표시 방향이다. 이후 약 85–130m의 짧은 화면 탄광으로 끝나며 코어의 비행 목록에 들어가지 않는다.

## 검증 결과

[`tests/wip12-effects-ricochet.test.cjs`](../tests/wip12-effects-ricochet.test.cjs)는 고각 보간, 도탄 경계, 좌우 측면과 차체/포탑 독립 방향, 통제 roll, 중복 ID, 최소 공개 사본, 시각 읽기 독립성, 확정 탄착 종점과 atlas/입자 우선순위를 검사한다. 실제 코어 seed 25는 관측·식별·지정·포수 확보·조준 뒤 발사한 첫 탄이 차체 전면 80.007942°에 명중한다. 도탄 확률 0.503971, roll 0.424939로 도탄하며 대상 HP는 1,450 그대로이고 효과 외 새 비행이나 피해가 없다.

[`tests/wip12-effects-browser.test.cjs`](../tests/wip12-effects-browser.test.cjs)는 정확한 `dist/index.html`을 Chromium에서 실행한다. 블루 팀 접촉이 0인 숨은 레드 사수의 포구·예광·도탄을 실제 앱 캔버스에서 확인하고, 0.05초 간격 15개 연속 프레임을 `tests/releases/WIP12-effects-frame-00.png`부터 보존했다. 별도 seed 70은 임시 목표 종점과 지면 탄착점이 107.982m 어긋나는 기존 조건을 재현한다. `tests/releases/WIP12-effects-seed70-frame-00.png`–`14.png`에서 연결된 예광의 최종 종점과 `miss-ground` 효과 좌표가 일치하며 렌더러 기록 오차는 0m다. 지연 회귀는 시뮬레이션 15.45초에서 2배속으로 전환하고 0.1초 화면 프레임 한 번으로 15.65초까지 진행한다. `WIP12-effects-seed70-delay-before.png`/`after.png`와 실제 Canvas `lineTo()` 기록에서 연결 1, 누락 0, 월드 종점 오차 0m, 화면 종점 오차 0px를 확인했다. 1440×900 DPR1과 844×390 DPR2에서 atlas 디코딩, 공개 필드, 일시정지, 품질/모션 설정 독립성, 초기화, 화면 넘침과 페이지 오류 0을 확인했다.

50대 양 팀 자동사격 브라우저 스트레스는 지연 프레임 수정 뒤 30초 장면을 효과 켬/끔 각 3회 교대 실행했다. 각 실행은 127발 발사·126발 착탄·17대 격파로 동일했고 최종 게임 상태 SHA-256도 같았다. 연결된 126개 비행은 누락 0, 종점 오차 0m였고 최대 동시 입자는 렌더러 누적 152/384, 효과 큐는 66/256이었다. 측정한 전체 앱 CPU 프레임 중앙값/P95는 끔 3.6/7.5ms, 켬 3.8/7.4ms였다. 이는 headless Chromium CPU 관측값이며 모바일 FPS·발열 보장이 아니다.

같은 WIP11E 50/100대 관측 fixture의 모든 최종 상태 SHA-256이 일치했다. WIP12 단일 실행의 이동 100대 중앙값은 15.847ms로 WIP11E 기록 15.929ms와 비슷했고 P95는 22.394ms 대 20.563ms로 더 높았다. 실행 잡음이 있는 단일 프로세스 비교이므로 상태 동등성과 중앙값 보존을 확인하는 근거로만 사용하며 꼬리 지연 개선을 주장하지 않는다.

## 범위 제한

도탄 후 추가 충돌·피해, 파편·모듈·승무원·화재, HEAT 신관, 새 탄종, 상부 피격, 실제 장갑/탄도 물리, 음향, 새 AI/LOS 변경은 구현하지 않았다. 효과가 숨은 사격의 발생 위치와 방향을 의도적으로 보여주지만 숨은 차량의 이후 이동이나 수치 정보까지 공개하지 않는다. 실제 휴대폰 지속 성능·발열과 물리 장비 성능은 검증 범위가 아니다.
