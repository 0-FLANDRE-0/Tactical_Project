# WIP11D 지형 판독성 구현

WIP11D는 기존 4×4km 라스도르프 지도와 게임 판정을 그대로 두고, 고저·사면·능선·골짜기를 읽기 위한 표시 계층을 추가한다. 일반 지도는 새 고정 고도 팔레트와 다방향 음영을 기본으로 사용한다. 지도 하단의 `지형`을 누르면 농경지·숲 내부 장식을 낮추고, 황갈색 능선 실선과 청회색 골짜기 파선을 더한다. 기존 `등고선` 버튼은 두 모드와 독립적이다.

## 공개 체력 선행 확인

작업 기준 `a037774a8348378563d1d3ddb7822a20eab19890`에는 WIP11C 수정이 이미 포함돼 있었다. `buildTeam()`은 위치·자세의 `lastSeen`과 식별 지식의 `knowledgeAt`을 따로 비교하므로, 오래된 아군 기억이 최신 공개 HP를 덮지 않는다. 같은 수정을 중복 적용하지 않고 C05/C06을 포함한 회귀를 다시 실행했다.

## 표시 규칙

- 고도 290/340/390/440/510m에 고정된 녹회색→황록색→황갈색 팔레트를 쓴다. 카메라나 줌에 따라 색 범위를 다시 정규화하지 않는다.
- 북서 주광 72%, 북동 보조광 18%, 남서 보조광 10%의 부드러운 음영을 합성한다. 일반 모드는 ±0.15, 지형 강조는 ±0.21로 제한한다.
- 10m 등고선은 0.75 CSS px, 50m 주요선은 1.7 CSS px다. 낮은 줌에서는 10m 선만 생략하고 50m 선과 높이 숫자는 유지한다. 숫자는 결정적 위치에 11.5px로 배치한다.
- 시야 홀드 중에는 지형 음영과 해석선 대비를 38%로 낮춘다. 관측 판정과 시야 경계 계산은 바뀌지 않는다.
- 캐시 키는 카메라·줌·화면 크기·DPR·등고선·지도 모드·시야 홀드·팔레트/파생 데이터 버전을 포함한다.

## 능선·골짜기 파생 데이터

`scripts/build_terrain_readability.py`는 게임용 2m 높이장을 읽되 새 표시 데이터만 만든다. 20m 블록 평균과 40m Gaussian 평활 뒤, 골짜기는 D8 하향 누적, 능선은 뒤집은 표면의 D8 누적으로 후보를 찾는다. 누적 120셀, 횡단 오프셋 60m, 60백분위 횡단 고저 0.5m 이상, 길이 180m 이상, 지도 끝 60m 제외를 적용한다. Chaikin 평활과 5m RDP 단순화를 거쳐 월드 좌표 벡터로 저장한다.

결과는 능선 47개, 골짜기 59개, 총 45,589.4m다. `data/terrain-readability.json`에는 지도 해시, 스키마·알고리즘 버전과 모든 미터 단위 매개변수가 들어 있다. `src/terrain-data.js`는 단일 HTML에 넣는 같은 데이터다. 해시나 스키마가 맞지 않으면 해석선만 끄고 개발자 오류를 남긴다.

```sh
/usr/bin/python3 scripts/build_terrain_readability.py
/usr/bin/python3 scripts/build_terrain_readability.py --check
python3 scripts/validate_terrain_readability.py
```

생성에는 NumPy 2.2.4와 SciPy 1.15.3이 필요하다. 비교 시트 생성에는 Pillow 11.1.0을 썼다. 실행 HTML은 이 라이브러리나 외부 통신을 요구하지 않는다.

## 실제 지도 검증

1440×900, DPR 1의 같은 카메라로 WIP11C 이전 화면, WIP11D 일반 지도, 지형 강조를 비교했다.

| 구역 | 월드 중심 (m) | 줌 | 확인 대상 |
|---|---:|---:|---|
| west-forest-ridge | 800, 1500 | 0.8 | 숲 속 능선과 사면 연속성 |
| open-hill | 1000, 3400 | 0.8 | 개활지 언덕과 주요 등고선 |
| rasdorf-slope | 2800, 1550 | 0.8 | 마을·도로 아래 사면 |
| south-east-valley | 3250, 3250 | 0.8 | 낮은 골짜기와 마른 골 |

[전후 비교 시트](../tests/releases/WIP11D-terrain-comparison.png), [흑백 강조 비교](../tests/releases/WIP11D-terrain-grayscale.png), 카메라와 각 PNG의 SHA-256은 [비교 기록](../tests/releases/WIP11D-terrain-comparison.json)에 있다. 네 구역에서 능선·골짜기 각 1개씩 원래/평활 횡단 고도와 10m 등고선 구간을 대조했고 8/8이 종류와 일치했다. 골짜기 59개 중 47개는 지도 수계 40m 안, 9개는 100m 밖의 마른 골이다. 수계 근접성은 추출 후 설명 자료일 뿐 선별 기준이나 정답으로 사용하지 않았다.

## 회귀와 성능

- Node 규칙·코어 208, 입력 42, 지도 16, 시야 12, 차량/Worker 9: 287/287 통과.
- 지형 합성/경계/회전/종류/재현성 7/7, 원본 자료 7/7 통과.
- 실제 Chromium 156에서 27/27 통과. 1440×900, 844×390 DPR 1/2, 390×844 세로 게이트와 내장 Worker를 확인했다.
- 같은 1440×900 DPR 1 카메라 36회 재빌드 중앙값/P95: WIP11C 6.25/9.30ms, WIP11D 일반 9.85/14.50ms, 지형 강조 9.95/12.50ms. 정지 120프레임은 세 조건 모두 불필요한 재빌드 0회였다.

이 시간은 headless Chromium의 지도 캐시 재구축 CPU 시간이며 전체 게임 FPS나 휴대기기 성능이 아니다. `file://` 실행은 환경 정책의 `ERR_BLOCKED_BY_ADMINISTRATOR`로 미검증이고, 같은 단일 HTML은 로컬 HTTP에서 검사했다.

## 보존 범위와 한계

원본 DEM/OSM, `data/rasdorf_4km.json`, `data/contours.json`, `data/map_manifest.json`, `src/battlefield-data.js`, 이동·LOS·관측·전투 상태는 바뀌지 않았다. 20m 분석과 40m 평활은 좁은 미세 지형을 의도적으로 생략한다. D8 방식은 넓고 평평한 분수계나 닫힌 함몰을 생략할 수 있다. 해석선은 표시 전용이며 이동·통행·LOS·사격 판정에 들어가지 않는다.
