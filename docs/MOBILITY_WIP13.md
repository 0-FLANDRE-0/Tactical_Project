# WIP13 경량 차량 구동

WIP13은 이동 명령과 실제 종방향 운동을 분리한다. `u.reverse`는 경로 요청이고 실제 위치 적분은 `u.drive.velocity` 한 값만 사용한다. `u.speed`는 관측·사격·UI 호환을 위한 절댓값이며 매 고정 틱에 실제 속도에서 갱신된다. 렌더러는 이 상태를 계산하거나 수정하지 않는다.

## 상태와 전환

`src/mobility.js`는 차량·지도와 독립된 고정 크기 상태를 가진다. 요청 방향, 연결 방향, 예약 방향, 부호 있는 속도, 현재 단수, 변속/유지/방향 대기 시간을 구분한다.

- 반대 방향을 요청하면 기존 범위를 끊고 `direction-brake`로 들어간다. 3m/s²의 유한 제동으로 현재 방향 속도를 0까지 줄인다.
- 실제 속도가 0.25m/s 이하가 된 뒤 0.18초 정차 확인을 거쳐 새 범위를 연결한다. 연결 시간은 0.28초다. 제동·대기 중 명령을 번복하면 이전 예약을 버린다.
- 정지 명령은 경로와 방향 예약을 지우지만 속도를 직접 0으로 쓰지 않는다. 충돌 안전 정지와 격파만 별도의 즉시 정지 경로다.
- 마지막 지점은 0.8m 위치 허용치와 0.18m/s 속도 허용치를 함께 만족할 때 완료한다. 도착 분기에서 속도나 위치를 순간 보정하지 않는다.

`sim-core.js`는 기존 경로, 노면·경사 상한과 충돌 검사를 그대로 사용한다. 현재 실제 진행 방향으로 목표 방위를 정하므로 고속 전진 중 후진 명령이 차체를 즉시 180도 돌리지 않는다. 정차·저속에서는 기존 30°/s 제자리 선회를 유지하고, 속도가 높으면 1.8m/s² 횡가속 한도로 각속도를 낮춘다. 포탑·전차장 관측 선회는 기존 독립 상태를 유지한다.

## 프로파일과 근사값

공통 계산에는 차량 상수를 넣지 않았다. `vehicle-profiles.js`의 `mobility.powertrain`이 질량·출력 기준과 다음 값을 소유하고 JSON 내보내기와 UI가 같은 프로파일을 사용한다.

| 값 | 적용 | 분류 |
|---|---:|---|
| 전진 범위비 | 5.877 / 3.021 / 1.891 / 1.278 | Tank_Project G4.62의 채택 참고 프로파일 |
| 후진 범위비 | 8.305 / 2.354 | 같은 참고 프로파일 |
| 효율 | 0.90 | 게임 근사 |
| 변속 / 최소 재변속 | 0.42초 / 1.20초 | 게임 근사 |
| 전진 상향 | 4.2 / 8.1 / 13.2m/s | 게임 변속표 |
| 전진 하향 | 3.4 / 7.1 / 11.8m/s | 히스테리시스가 있는 게임 변속표 |
| 후진 상향 / 하향 | 5.2 / 4.2m/s | 게임 변속표 |
| 기준 저속 가속 한도 | 1.645m/s² | 63,085.63kg·1,500hp 프로파일의 0→20mph 7.2초 끝점 보정 |
| 구름 감속 / 변속 중 구동률 | 0.035m/s² / 0.12 | 게임 근사 |

구동 가속은 현재 단수비에서 얻은 저속 구동력 한도와 `출력×효율/(질량×속도)`의 출력 한도 중 작은 값을 쓴다. 따라서 같은 구동표에서 질량 증가는 가속을 낮추고 출력 감소도 가속을 높이지 않는다. 단수는 구동력에 실제로 영향을 주며 변속은 속도를 직접 바꾸지 않는다. 기존 노면·경사 규칙은 목표 속도 상한으로 한 번만 적용하고 별도의 경사 저항을 중복 감산하지 않는다.

참고한 Tank_Project는 `724d3421a9bd01a43c1c074743edff121422135c`의 G4.62 HTML이다. `ENGINE_SPEC`, `X1100_RANGE_SPEC`, `TRANSMISSION_SPEC`, 방향 interlock과 `updatePowertrainDrive()`의 역할 분리를 읽었다. 240Hz 강체·궤도 접촉·유압·열 모델은 가져오지 않았다. 열람한 커밋의 저장소 루트에서 LICENSE/COPYING 파일을 찾지 못했으므로 코드를 복사하지 않고 상태 구조와 범위비만 출처와 함께 다시 구현했다. 범위비도 실측 기어 잇수라고 주장하지 않는다.

## UI와 성능

경로 영역은 `D1`–`D4`, `R1`–`R2`, 변속 중, `N → R/D`, 실제 전진/후진과 요청 방향을 표시한다. 후진 버튼은 계속 요청 입력이며, 전진 제동 중 화면을 실제 후진으로 표시하지 않는다.

구동 갱신은 0.05초마다 차량당 한 번의 고정량 산술만 수행하며 객체를 만들거나 지형·LOS를 조회하지 않는다. AMD EPYC 9V74 / Node 24.22.1에서 100대 순수 구동 중앙값은 0.01683ms/틱, P95 0.01792ms/틱이었다. 실제 지도 100대 전체 `C.step` 중앙값은 기준 0.6570ms, WIP13 0.5847ms였고 P95는 각각 1.2038/1.3061ms였다. 경로 탐색과 렌더는 이 Node 측정에서 제외했다.

실제 Chromium 1440×900에서 50대 이동 아군과 50대 정지 적군, 관측/LOS·UI·캔버스 렌더를 포함한 600프레임×3회 중앙값은 기준 20.6ms, WIP13 20.5ms였다. P95는 29.4ms와 29.6ms다. 새 궤적의 이동 거리와 관측 후보가 달라지므로 전체 프레임 차이를 구동 함수만의 효과로 해석하지 않는다. 측정 원자료는 `tests/releases/WIP13-mobility-benchmark.json`과 `WIP13-mobility-browser-benchmark.json`에 있다.

## 한계

이 모델은 자동 범위와 게임용 구동력만 다룬다. 엔진 회전수, 토크 컨버터 전체 맵, 좌우 궤도 접촉, 서스펜션, 열, 연료와 시동 절차는 없다. 현재 적 차량은 이동 AI가 없어 자동 이동하지 않는다. 0→20mph 한 점과 명목 최고속도를 맞춘 결과를 실제 전 구간 가속·제동 성능 검증으로 확대하지 않는다.
