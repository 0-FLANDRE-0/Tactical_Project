# 시선 연출

## 사용법

- 기본 상태에서는 아군 포탑 도안이 좌우로 움직이고, 선택된 전차의 하늘색 시선 커서는 더 넓게 움직인다.
- 지도 위 `방향 지정` 또는 L을 누른 뒤 바라볼 방향을 탭한다. 방향은 그 순간의 지도 방위로 저장하며 지점을 계속 추적하지 않는다.
- 5초, 10초, 30초 중 유지 시간을 고른다. 기본값은 10초다. 유지 중 차체가 돌아가거나 이동해도 시선의 지도 방향은 유지된다.
- 시간이 끝나면 부드럽게 좌우 둘러보기로 돌아온다. `둘러보기`로 바로 해제할 수도 있다.
- 지정 대기 중 Esc, 버튼 재클릭, 전차 변경, 이동/후진 모드 선택, 창 포커스 해제는 방향 입력을 취소한다. 드래그·핀치는 지도를 조작하며 방향을 확정하지 않는다.
- 일시정지나 숨겨진 탭에서는 연출과 남은 시간이 멈춘다. 게임 배속을 따른다. 초기화하면 모든 시선 연출 상태를 지운다.
- 운영체제/브라우저의 모션 줄이기를 사용하면 자동 흔들림과 전환 애니메이션을 생략한다.

## 구현 범위

이 기능은 화면용 포즈 애니메이션이다. `look-animation.js`의 WeakMap에 별도 상태를 보관하고, 그림을 그릴 때만 복사한 객체의 포탑 방향을 사용한다. 원본 유닛의 차체/포탑 상태, 이동, 관측·차폐 판정, 표적 상태와 명령은 수정하지 않는다. 시선 커서는 화면 픽셀 크기의 방향 표시이며 관측 부채꼴이나 사거리 표시가 아니다.

움직임 폭·주기·전환 시간은 시각 연출값이며 실제 장비 성능을 나타내지 않는다. 자동 탐지, 위협 대응, 표적 획득, 사격 기능은 이 변경에 포함하지 않는다.

이 변경은 PR #1의 `perf/ui-update-cache` 위에 쌓았던 PR #2다. 두 PR은 main에 병합되었으며, WIP06은 병합 커밋 `4eaedbe6dd1d7eb4f2799b3b629ac9a6aa419402`를 기준으로 버전 파일을 정리했다.

## 검증

```sh
python3 build.py
node --check src/look-animation.js
node --check src/app.js
node --test tests/look-animation.test.cjs tests/ui-cache.test.cjs
node tests/input.test.cjs
node tests/map.test.cjs
node tests/visibility.test.cjs
node tests/vehicle.test.cjs
```

- 기존 검사 65개와 새 검사 28개를 합쳐 93개 통과.
- 새 순수 모듈 검사 14개: 좌우 움직임, 더 넓은 커서, 지도 방향 유지, 만료 경계, 늦은 프레임, 재지정, 해제, 객체 교체, 초기화, 잘못된 입력, 각도 경계, 원본 불변성, 시간 정지, 모션 줄이기.
- 새 입력/프레임 검사 14개: 방향 탭 시 이동 방지, 반복 클릭, L/Esc, 포커스·탭 변경, 선택 변경, 해제/초기화, 드래그, 이동 모드, select 키 입력, 포인터 중간 취소, 후진 단축키, 일시정지, 숨겨진 탭과 만료.
- 포인터를 누른 채 Esc로 취소한 뒤 손을 떼도 이동 명령이 발생하지 않도록 회귀 검사를 추가했다.
- 구문 검사와 단일 HTML 빌드 통과. 시뮬레이션·관측·Worker·차량 프로파일·지도 소스는 PR #1과 동일하다.

브라우저 시각 검사는 실행하지 못했다. Chromium 시작 시 실행 환경이 `socket()`을 허용하지 않아 종료되었으며, 승인된 실행 경로에서도 같았다. 따라서 실제 DOM 렌더링·모바일 배치·실기기 터치는 미검증이다. 입력/프레임 검사는 가짜 DOM과 렌더러를 사용한다. GDAL 원본 자료 검사는 실행하지 않았다.
