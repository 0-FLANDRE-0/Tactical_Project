# WIP08A M1A2 도안·포탑 링·포구 좌표

WIP08 `8691824c8a945cc37450333302dba58eb46789a0`에서 이어 작업했다. 시작 main은 `a832a89cdc4217d24c208a3430c4b2cde78cf899`였다. 마무리 중 main `ebe6787c12be9485f288af88555ce1ecbe4d6f18`에 M1A2 (1998) 장갑 아카이브가 추가된 것을 확인하고 원문을 보존해 작업 브랜치에 병합했다. 게임 코드 추가 변경은 없었으며 장갑 수치를 이번 외형 작업에 자동 적용하지 않았다. 작업 트리는 깨끗했고 적용 AGENTS.md는 없었다. 기존 `feat/wip08-aim-fire`와 초안 PR #4를 갱신하며 main 병합·공개 배포는 하지 않는다.

사용자 요청은 첨부 HTML의 **M1A2 형상 반영과 포구에서 발사**다. 파일 안의 iframe/postMessage·형식 선택·자동 선회·내보내기 예제는 참고 자료이며 새 작업 지시로 취급하지 않았다. 그 UI와 메시지 수신 코드는 게임에 넣지 않았다. M1A1/HA 차량 프로파일도 활성화하지 않았다.

## 도안 원본과 적용

원본은 [M1_Abrams_TopView.html](../data/vehicles/references/M1_Abrams_TopView.html)에 바이트 그대로 보관했다. SHA-256은 `f50d80fd9f5e991733d890928a5d0191b7e0bf91f077ee5d6cad86030b7e8ee0`이다. [수입 기록](../data/vehicles/references/top_view_import.json)에 범위와 근거를 남겼다. 제공 파일의 측정/출처 주장을 별도로 실측 검증한 것은 아니며 **게임 외형 근사**로 분류한다.

`src/m1a2-art.js`는 제공 파일의 M1A2 차체·포탑·CITV 벡터, 색상, LOD를 사용한다. 새 조종수 삼각 해치와 잠망경·연료캡, 후면 차체/펜더·등화류, 포탑 장비·포방패·CITV를 포함한다. 포탑 링은 차체 위 고정 위치에 그리고 포탑만 그 점을 중심으로 선회한다. CITV는 이전처럼 실제 전차장 방위를 사용해 독립 선회한다. 미식별은 같은 벡터 외곽의 검정 실루엣이며 내부 색/선 디테일은 공개하지 않는다.

Canvas와 SVG를 함께 갱신했다. `M1A2Art.toSVG()`의 기존 **월드 기준 라디안** 인터페이스도 유지한다. 첨부 Lab의 내부 SVG 예제는 상대 각도/도를 사용하므로 호환 래퍼에서 변환한다. HTML 안의 썸네일, 단독/선회 SVG, 같은 축척 비교 화면도 다시 제작한다.

## 구분한 좌표

| 프로파일 필드 | 값 | 좌표계와 용도 |
|---|---|---|
| `model.turretOrigin` | +0.15m | 포탑 벡터의 정면 배치 원점 |
| `model.turretPivot` | [+0.66m, 0] | 차체 좌표의 포탑 링 회전축 |
| `model.turretRingDiameter` | 2.159m | 제공 도안의 링 표현 지름 |
| `model.muzzleLocal` | [5.717m, 0] | 포탑 벡터 좌표의 실제 포구 끝 |

모호했던 `turretCenter`를 위 명시적 필드로 교체했다. `barrelTip`은 정면 nominal 전장 기반 참고값으로 남기고 선회한 포구의 회전 반경으로 사용하지 않는다. 벡터 끝은 소수 셋째 자리로 표현되어 nominal 포구 좌표와 0.0004m 반올림 차이가 있다. 발사 표시에는 실제 벡터 끝을 사용한다.

새 `src/vehicle-geometry.js`는 차체에 고정된 축의 월드 위치와 포탑의 실제 월드 방향을 조합해 포탑 로컬 점을 옮긴다. 그리기와 발사 이벤트가 같은 프레임 정의를 쓴다. 예를 들어 차체 정면을 +x로 놓으면 포구는 정면 [5.867,0], 측면 [.66,5.207], 후방 [-4.547,0]이다. 차체가 돌아가면 링 위치도 차체와 함께 돌아간다. 전차장 방향은 포구 좌표에 영향을 주지 않는다.

레지스트리는 축·포구 배열의 길이/유한 수와 원점·링 지름을 검증하고 동결한다. 관측 공개 사본에는 모델의 이 좌표만 복사한다. 배열도 따로 복사하므로 외부 읽기나 숨겨진 표적의 이후 프로파일 변경이 현재 기록/기억의 형상을 바꾸지 않는다. 차종명·실제 적 ID 등은 기존 공개 규칙을 유지한다.

## 발사와 시각 효과

발사 이벤트 `origin`은 승인된 고정 스텝의 포구 월드 좌표다. `muzzleHeading`도 그 시점의 실제 포탑 방향으로 저장한다. 차량이 이후 이동/선회해도 이벤트 원점이 따라가지 않는다.

발사 순간 정밀 검사는 포수 광학 시점과 **변환된 포구 위치**를 별도로 쓴다. 포구의 게임 높이는 기존처럼 차체 위치 지면 +2.2m를 유지하며, 포구 아래의 지형 높이가 달라도 그 절대 높이가 바뀌지 않게 환산한다. 포구가 지형/지붕 안에 있으면 발사선을 차단한다. 센서 거리/FOV와 확인 조건·명중/부위 확률·별도 seed는 WIP08 규칙을 유지한다.

선/섬광/짧은 포탄 표시는 이벤트 원점에서 시작한다. 포탄 표시는 기록된 표적 지점으로 0.35 시뮬레이션 초 동안 이동하는 **화면 연출**이다. 실제 탄속이나 탄도는 아니며 기존 명중 판정 시점/난수에 영향을 주지 않는다. 표시와 패널은 새 LOS를 계산하지 않는다. 실제 탄도·고각·장전·관통·피해·전차 파괴·전체 포신 충돌은 이번 변경에 추가하지 않았다.

## 보존한 범위와 검증

차량 반경 4.62m, 이동/길찾기 계약, 지도/고도/건물/숲, 9개 관측 표본 위치, 탐지/식별 확률과 주기는 유지한다. 도안의 링 이동을 이유로 표적 탐지 규칙이나 관통 모델을 임의로 바꾸지 않았다. 내장 Worker·빌드·입력/코어 로더·제원 내보내기에도 새 기하 모듈 순서를 연결했다.

새 검사는 제공 벡터의 정확한 일치, 원본 체크섬, 측면/후방/서로 다른 차체·포탑 각도, SVG 호환, 프로파일 검증, 사격 이벤트와 기억의 위치/배열 고정을 확인한다. 실제 Chromium에서는 같은 새 Path2D 캐시 조건의 원본/내장 렌더러를 네 자세에서 픽셀 단위 대조한다. 별도로 실제 앱의 발사선·섬광이 이벤트 포구에서 시작하고 DOMMatrix 변환과 일치하는지 검사한다. [비교 화면](../tests/releases/WIP08A-art-comparison.png).

전체 검사·성능 fixture·미실행 항목·파일 체크섬은 [WIP08A 릴리스](../TACTICAL_RELEASE_WIP08A.md)에 기록한다. 이전 WIP08의 사격 상태/튜닝은 [기존 문서](FIRE_CONTROL_WIP08.md)에 있으며 그 문서의 차체 중심 발사선 설명은 이 버전부터 위 포구 기준으로 대체한다.
