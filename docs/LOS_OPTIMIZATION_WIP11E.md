# WIP11E — 9표본 LOS 공통 경로 조회 공유

WIP11E는 관측 규칙을 바꾸지 않고 `exposure()`가 차체의 같은 평면 위치에서 높이만 달리해 쏘는 두 광선의 정적 조회를 공유한다. 작업 브랜치는 `feat/wip11e-los-optimization`, 시작 main은 `a01ae8bd8965f5b035acdcfa40087cf6fe8c3c7d`, 게임 코드 비교 기준은 WIP11D `a668f9b21340db09fe2459190bb34337ef7d2690`이다.

## 구현

- WIP11D `src/sim-core.js`를 검사 전용 fixture로 그대로 보존하고 SHA-256 `8ee5cc9f4374db0afcffaf9ae49df9e6c818a089fd72a7f1319f29c994788ee8`을 로더에서 확인한다. 이 fixture는 빌드와 Worker에 들어가지 않는다.
- 차체 열마다 x/y가 정확히 같은 아래·위 높이 두 표본이 모두 캐시 미스일 때만 공통 경로를 사용한다. 일부만 미스면 누락된 표본 하나를 기존 공개 `lineOfSight()`로 계산한다.
- 공통 경로는 관측자/표적 지면 높이, 원래 2m 수평 격자의 위치, 지면 보간, 건물 버킷·후보·다각형 내부 여부, 숲 밀도를 공유한다.
- 각 높이는 광선 높이, 32m 구역 건너뛰기, 첫 차폐 사유, 숲 광학 깊이, 종료 위치를 독립적으로 유지한다. 한 광선이 끝나도 다른 광선에 필요한 원래 격자는 계속 검사한다.
- 차체 6개 뒤에는 기존 포탑 3개를 기존 순서로 단일 광선 처리한다. 반환 표본 좌표·높이·부위·열/행, 노출 집계, 논리 `rayQueries`와 `rayCacheHits` 의미를 유지한다.
- 범위 밖이나 비유한 입력은 검증된 단일 광선 두 번으로 폴백한다. 공개 `lineOfSight()` 계약과 6m preview 경로는 바꾸지 않았다.
- 진단은 기본 비활성이다. 별도로 켰을 때 공통 묶음·논리 광선·세밀 높이 표본·피한 높이 읽기·건물·숲 조회 수를 센다. 시간 측정은 진단을 끈 상태에서 실행했다.

## 정확성 대조

`tests/los-shared-path.test.cjs`는 고정 WIP11D 코어와 현재 코어를 직접 비교한다.

- 실제 지도 공개 LOS 12,000건의 `visible`, `reason`, `forestDepth` 완전 일치.
- 실제 지도 노출 2,000건, 논리 광선 18,000개의 9개 표본 전체와 메타데이터·집계·순서 완전 일치. 진단으로 공통 경로가 실제 실행됐음을 확인했다.
- 전체/부분/만료 캐시, 관측자·표적 이동, 차체·포탑 독립 회전, 눈높이 변경, 이전 반환 객체 불변을 대조했다.
- 평지·능선 접선·건물·낮은 벽·숲 합성과 한 높이만 건물에 막히는 직접 공통 helper 검사를 포함했다.
- 기존 `tests/los-optimization.test.cjs`의 별도 WIP07A oracle도 실제 지도 LOS 12,000건과 노출 1,000건을 계속 통과한다. 새 WIP11D 대조 건수와 중복 합산하지 않는다.

seed 407의 고정 관측 fixture는 기준/현재의 최종 시나리오 JSON, 접촉, 탐지·식별·기억, 기존 관측 통계와 상태 SHA-256을 모든 프로세스에서 바이트 단위로 비교했다. 네 사례 모두 일치했다.

## 성능

Node v24.22.1, AMD EPYC 9V74 환경에서 기준과 현재 코어를 별도 새 프로세스로 순차 실행하고 순서를 교대했다. 양쪽은 같은 파싱된 지도 객체와 같은 모듈 의존성을 받는다. 각 5회, 준비 20스텝 뒤 0.05초 고정 스텝 100개를 측정했다. 수치는 렌더링이나 전체 FPS가 아닌 시뮬레이션 스텝 CPU 시간이다.

| 사례 | 기준 중앙값 / P95 | WIP11E 중앙값 / P95 | 중앙값 / P95 변화 |
|---|---:|---:|---:|
| 정지 50대 | 2.819 / 5.122ms | 2.662 / 5.785ms | 5.57% 개선 / 12.95% 악화 |
| 정지 100대 | 8.219 / 16.391ms | 7.542 / 13.067ms | 8.23% / 20.28% 개선 |
| 이동 50대 | 4.430 / 5.981ms | 3.755 / 5.309ms | 15.25% / 11.24% 개선 |
| 이동 100대 | 18.463 / 22.637ms | 15.461 / 19.633ms | **16.26% / 13.27% 개선** |

정지 50대 P95는 5회 중앙 집계에서 0.663ms 악화됐다. 실행별로는 기준보다 3회 느리고 2회 빨랐으며 최대값은 12.671→11.649ms로 낮아졌다. 다른 기본 3사례, 고정 장면 5종, 실제 Chromium의 대표 이동 사례에서는 같은 P95 퇴행이 반복되지 않았다. 작은 정지 사례의 꼬리 지연은 남은 측정 한계로 기록한다.

진단용 별도 실행 한 번에서 공통 묶음 285,807개와 논리 광선 571,614개를 처리했고, 세밀 높이 표본 13,737,643개에서 높이 읽기 12,455,579회를 피했다. 논리 광선 수나 관측 통계가 줄었다고 계산하지 않았다. 강제 GC 뒤 프로세스 힙 중앙값은 초기화 후 기준 29,950,504바이트, 현재 29,965,536바이트, 전체 fixture 뒤 기준 21,271,392바이트, 현재 21,401,336바이트였다. 이는 할당 횟수나 장기 메모리 보장이 아닌 프로세스 관측값이다.

고정 배치는 기준/현재 결과가 모두 정확히 일치했다.

| 배치 | 2,000회 노출 중앙값 개선 |
|---|---:|
| 실제 서부 사면 | 10.01% |
| 실제 마을 | 20.83% |
| 합성 숲 | 23.64% |
| 합성 접선 능선 | 27.03% |
| 합성 조기 건물 차폐 | 30.59% |

실제 Chromium 156.0.8078.79의 WIP11D/WIP11E 단일 HTML 비교는 이동 50대 중앙값 11.11%(P95 1.39% 악화), 이동 100대 중앙값 14.71%(P95 15.09% 개선)였다. 정지 10대 중앙값은 브라우저 타이머 해상도에서 양쪽 0.3ms였다. 최종 상태 SHA-256은 각 사례에서 일치했다.

원시값은 `tests/releases/WIP11E-los-comparison.json`, `WIP11E-los-scenes.json`, `WIP11E-browser-benchmark.json`에 있다.

## 범위와 한계

32m 요약, 2m 세밀 격자, 10Hz 분산 관측, 9표본 수, 센서·탐지·기억·팀 공유·전투 규칙은 그대로다. 전체 높이장 캐시, 근사 양자화, Worker 이전, GPU/WASM, 지도 렌더링 변경은 도입하지 않았다. 실제 Android/iOS 기기, 지속 발열과 장시간 프레임률은 측정하지 않았다.
