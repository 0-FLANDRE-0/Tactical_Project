## 3. 조정 가능한 초기 시험 계수

아래 확률·증감량·회복률은 **이번 지시서의 초기 게임 튜닝 제안**이다. 사용자가 실측 제원이나 최종 밸런스로 확정한 값이 아니다. 우선 이 값으로 구현하고 프로파일에 모아 단위·한계·근거를 기록한다. 검증 결과로 변경하면 최종 값과 이유를 완료 보고에 남긴다.

| 계수 | 초기 시험값·의미 |
|---|---|
| 피로 지연 `F` | 0~5초. 연속 4발째와 이후 실제 발사마다 +0.35초 |
| 동요 지연 `S` | 0~5초. 일반 비관통 +0.25초, 근접 비관통 +1초, 관통 +2.5초 |
| 동요 회복 | 시뮬레이션 1초당 0.25초 감소, 0에서 정지. 장전 중에도 회복 |
| 피로 회복 | 장전 완료·장전탄 유지 상태에서 기다리는 동안 1초당 0.25초 감소 |
| 연속 사격 해제 | 장전 완료 후 발사 없이 6초 연속 대기하면 연속 발수 0. 장전 중 시간은 이 대기에 포함하지 않음 |
| 순간 장전 기준시간 | `T = clamp(5.98 + F + S, 5.98, 14)`초 |
| 근접 비관통 HP 피해 발생 | 해당 범위에서 유효 피격당 30%. 미발생이면 HP 피해 0 |
| 포탑 일시 이상 발생 | `p = 0.02 + 0.18 × clamp(D / 405, 0, 1)`. 전체 일시 이상 발생 확률 2~20% |
| 이상 종류 | 발생한 사건 1개당 사통 50%, 전차장 관측 25%, 포수 관측 25%. 독립된 세 확률을 모두 중첩 추첨하지 않음 |
| 이상 지속시간 | 종류별 동일하게 3~8초 균등 추첨. 피해량은 발생 확률에만 반영 |
| 같은 종류 재발 | `until = max(oldUntil, now + duration)`. 남은 시간 최대 8초, 기존 시간에 단순 가산하지 않음 |

`D`는 해당 피격에서 실제 피해 발생 여부까지 판정한 **잔여 HP로 자르기 전의 계산 피해량**이다. 근접 비관통 피해가 발생하지 않거나 도탄이면 D=0이다. 이 식은 전체 사건의 확률이며, 사통만의 확률은 그중 50%다. 확률은 낮은 잔여 HP 때문에 낮아지지 않아야 한다. 격파된 차량에 복구 사건을 예약하지 않는다.

## 4. 장전 상태·피로·동요

### 4.1 장전과 탄약 보존

- 차량별 장전탄 유무, 장전 작업 진행률 0~1, 연속 발수, 피로 F, 동요 S, 실제 대기 시간을 관리한다. 상태 갱신은 기존 0.05초 고정 틱·시뮬레이션 시각을 사용한다.
- 초기 총탄수 42발에는 장전탄 1발이 포함된다. **장전탄 + 작업 중 예약탄 + 저장탄 = 초기 탄수 − 실제 발사수**를 항상 만족시킨다. 작업 중 예약탄을 따로 두지 않는 설계도 가능하지만 재고에서 정확히 한 번만 이동해야 한다. 42발에 별도 장전탄 1발을 더하지 않는다.
- 실제 발사 성공 때만 장전탄·총탄수·연속 발수를 한 번 변경한다. 요청 거절·대기·표적 변경은 탄약이나 피로를 소비하지 않는다. 마지막 탄 발사 뒤 빈 장전이 반복되거나 탄약이 재생되지 않는다.
- 발사 뒤 탄약이 남으면 자동 장전을 시작한다. 표적이 없거나 사격 금지/일시 이상이어도 정상 장전은 계속하며, 장전된 탄은 유지한다. 취소·새 명령·표적 전환으로 재장전 보상을 얻거나 진행률이 초기화되지 않는다.
- 이번에는 단일 시험탄의 저장 재고까지만 관리한다. 아카이브 §12의 즉응/준즉응/예비탄 용량·이전·안전 판정은 후속이며 42발 전체를 역사적 즉응탄 용량으로 설명하지 않는다.

### 4.2 진행 중 속도 변화

- 각 틱에서 `progress += dt / T`로 작업한다. 피격은 남은 작업 속도를 바꾸며 진행률을 되돌리거나 장전 전체를 다시 시작하지 않는다. 일시적인 사통/관측 이상 자체는 장전 작업을 중단하지 않는다.
- `T <= 14`인 속도 하한을 유지하여, 피격이 반복되어도 한 번의 연속 장전 작업은 14초 안에 끝난다. 틱 경계의 준비 판정은 한 틱 이내 양자화를 허용한다. 5.98초가 화면상 약 6.00초가 되는 이유를 기록한다.
- 조준과 장전은 동시에 진행할 수 있다. 기존 1초 시험 간격이나 장전 중 매 틱 조준 초기화가 남아 기본 주기에 불필요한 시간이 순차 가산되지 않게 한다. 정상 추적·조준 리셋 규칙은 보존한다.
- 장전 지연 때문에 길어진 장전 자체를 휴식으로 보지 않는다. 그렇지 않으면 지연이 생기자 연속 발수가 저절로 끊겨 피로가 사라진다. 장전 완료 뒤 대기에서만 §3의 피로 회복·연속 발수 해제를 적용한다.
- 피격 분류는 HP 감소 여부와 분리한다. 기존 판정에서 관통이면 관통 동요, 비도탄 비관통 중 게임 부족량이 0 초과 15 미만이면 근접 동요, 그 밖의 비관통이면 일반 동요다. 근접 피해 추첨이 실패해도 근접 동요는 발생한다. 과관통도 관통 동요를 적용한다.
- **도탄은 HP 피해 0을 유지하고 최초 실제 피격의 일반 동요만 적용**한다. 표시용 반사 궤적에는 두 번째 피해·동요·이상 판정을 만들지 않는다. 빗나감·지형/건물 탄착은 차량 동요를 만들지 않는다.

## 5. 게임 HP 피해 규칙 연결

- 기존 M829A2 기준 피해 **405**와 관통 후 보간 곡선·과관통 감소를 그대로 사용한다. 과관통을 별도 사건으로 다시 추첨하거나 감소 배율을 두 번 곱하지 않는다. 동률 관통·고각/도탄·선택 면·장갑 데이터도 유지한다.
- 아카이브 §7-F의 근접 비관통 HP 시험값은 원래 A1 기록이었다. **이번 사용자 요청에 따라 A2 단일 시험 구성에도 새 시험 규칙으로 채택**한다. 과거 §9에서 이미 A2 확정값이었다고 기록하지 않는다. 405/380 비율로 자동 확대하지 않는다.
- 기존 판정이 **비도탄 비관통**이고 유효한 양의 관통력 입력일 때, 게임 내부의 부족량 `Δ = 방호력 − 유효 관통력`을 사용한다. `0 < Δ < 15`에서 §3의 발생 확률을 한 번 추첨한다. 발생 시 아래 시험 HP를 선형 보간한다. 실물 단위의 신규 제원이나 탄도식을 추가하지 않는다.

| 게임 부족량 Δ | 발생했을 때의 차량 HP 피해 |
|---|---:|
| 0에 오른쪽에서 접근 | 120 |
| 5 | 80 |
| 10 | 35 |
| 15 이상 | 0 |

- Δ=0은 기존 관통 경로다. Δ≥15, 무효 입력, 도탄·빗나감에서는 근접 HP 피해가 없다. 아카이브 §2의 오래된 10~15 미정 문구보다 후속 §7-F의 선형 시험안을 이번 작업 기준으로 삼는다.
- 기존 내부 실수 HP·피해 반올림 정책을 보존한다. 차량 HP는 0 아래로 내려가지 않으며, 새 비관통 피해로도 기존 격파·행동 중지·잔해 처리가 정확히 한 번 작동해야 한다.
- 미정인 추가 탄속 피해 보정은 계속 1이다. 현재 관통 곡선을 수정하거나 실제 잔여 운동에너지·내부 파편·승무원 피해 모델로 확장하지 않는다.

## 6. 포탑 장비 일시 이상과 관측·사격 연결

- 기본 대상 구역은 기존 `turretFront`·`turretSide`·`turretRear`다. 통합 `upper` 구역 전체를 포탑으로 가정하지 않는다. 새 세부 구획을 만들어 임의로 분류하지 않는다.
- 살아 있는 차량의 **실제로 처리된 포탑 피격마다 한 번만** §3의 확률·종류·지속시간을 판정한다. 비관통·도탄도 D=0 기본 확률을 가질 수 있다. 차체 피격에는 이 포탑 이상 추첨을 하지 않는다.
- **전차장 관측 이상:** 해당 전차장 채널의 새 탐지/식별·확인 갱신을 잠시 중단한다. 포수·기존 주변 관측 등 독립된 정상 채널까지 전부 끄지 않는다.
- **포수 관측 이상:** 해당 채널의 관측/확보를 잠시 중단하고 기존 공통 포수 확보 조건에 따라 발사를 막는다. 정상 전차장 관측은 계속할 수 있다.
- **사통 이상:** 해당 차량의 조준 작업을 잠시 멈추고 새 발사를 금지한다. 유효한 기존 조준 진행률·장전탄·장전 진행률은 보존하되, 표적 변경·관측 상실 같은 기존 리셋 조건은 계속 적용한다. 이미 발사된 비행체는 취소하지 않는다.
- 채널 이상 시작 때 해당 채널의 이전 `current/acquired`가 계속 신선한 관측으로 인정되지 않게 한다. 기억은 기존 유예·감쇠·만료 규칙으로 처리한다. 복구 때 과거 캐시만으로 즉시 확보를 선언하지 않고 정상 새 관측으로 재확인한다.
- 경계·기본 이동·AI 임무·플레이어 표적 명령과 `auto/hold`는 보존한다. 기능 복구는 정상 관측/발사 흐름으로 돌아갈 뿐 새 이동 명령을 내거나 취소된 임무를 재생하지 않는다. WIP14 정차/재개 로직과 장비 타이머가 서로 임무 소유권을 빼앗지 않게 한다.
- 반복 피격은 종류별 복구시각을 §3대로 갱신한다. 서로 다른 종류는 각각 만료한다. 새 유효 피격이 계속되면 이상이 유지될 수 있지만, 마지막 피격 이후에는 최대 8초 안에 복구한다.
- 수동/자동·아군/적군 모두 같은 장전·관측·사통 발사 조건을 사용한다. 큐에 들어온 요청도 실제 탄약 소비 직전에 재검사하며, 거절 시 발사 번호·탄약·판정 난수·비행체·사격 효과를 생성하지 않는다.

## 7. 사건·정보 공개·실행 비용

- 새 근접 피해·이상 발생·종류·지속시간 추첨은 실제 착탄 판정에 묶인 결정적 난수 영역을 사용한다. 명중/구역/도탄/연출 난수와 분리하고 UI 조회·프레임 수·테스트 순서로 결과가 바뀌지 않게 한다.
- 기존 발사 ID 중복 방지 안에서 HP·동요·이상을 함께 한 번 적용한다. HP 피해가 0인 유효 피격도 반응 사건은 한 번만 처리하고, 이미 격파된 표적·중복 콜백은 재추첨하지 않는다.
- 동작 순서는 고정 틱의 어느 단계에서 회복·착탄·관측 중단·AI·발사 조건을 반영하는지 명시한다. 적어도 이상이 반영된 뒤 같은 틱의 새 발사가 통과하는 순서 오류를 방지한다.
- 아군 선택 UI에 장전 진행/잔여 예상시간, 피로·피격 동요, 관측/사통 대응 상태와 남은 시간을 간결하게 표시한다. 변화 가능한 잔여시간은 예상치로 표시하고 조준·장전·이상 대기를 구분한다. 새 수동 수리/승무원 조작은 요구하지 않는다.
- 적의 실제 장전탄·탄약 재고·피로·동요·이상 타이머·숨은 HP를 공개 snapshot·선택 UI·사격 효과·공개 로그에 추가하지 않는다. 식별된 적 HP도 기존 최신 관측 사본을 따르며 기억 중 숨은 피격으로 갱신하지 않는다. 여러 아군의 최신 관측 병합 회귀도 유지한다.
- 미관측 적의 발사/피격 연출은 WIP12 계약대로 유지한다. 새 내부 장비 이상을 이유로 적 실체·이름·차종·잔해를 드러내지 않는다. UI용 사본은 내부 가변 상태를 참조하지 않는다.
- 차량당 작은 상태와 상수 시간 연산을 추가한다. 렌더마다 재계산·별도 타이머·전체 차량 쌍 순회·새 LOS/경로 요청을 도입하지 않는다. 일시정지는 진행·회복·이상 만료를 모두 멈추고 배속은 시뮬레이션 시간에만 반영한다.
- 새 모듈이 필요하면 실제 앱·단일 HTML·Worker·테스트 코어·독립 스크립트의 로드 경로를 모두 연결한다. 프로파일 내보내기와 JSON·검증기도 동기화하고 계수를 여러 파일에 따로 하드코딩하지 않는다.
