## 2. 사건 계약과 무기별 규칙

1. 기존 착탄/피해 처리가 확정한 `applied`, 명중·관통/근접 비관통·도탄, 실제 선택된 `zone`, 탄종과 사건 ID를 소비한다. HP 처리 뒤 살아 있는 차량에만 신규 사건을 판정한다. 빗나감·중복/무효 착탄·잔해·격파된 차량에는 적용하지 않는다.
2. 구역은 `hullFront/hullSide/hullRear/turretFront/turretSide/turretRear/upper`다. 피격 차량 기준의 기존 결과를 그대로 사용한다. 추가 구역 재추첨이나 표시용 탄착 좌표로 구역을 다시 정하지 않는다. 현재 `upper`는 차체·포탑 지붕 통합 구역이며 별도 행으로 유지한다.
3. **무기 계열 + 탄종의 명시적 효과 정책 ID → 피격 결과·구역별 기본률 → 피격 차량의 사건 종류별 감수성 계수 → 범주 선택 → 해당 구역 대상 가중치 → 상태 적용** 순서다. 상태 적용/회복 코드는 공통화해도 전차포 계산식을 다른 무기에 자동 상속하지 않는다.
4. 이번 활성 정책은 `tank-ke/M829A2` 전용이다. 다른 전차포 탄종·HEAT/HEP/고폭탄·기관포·미사일·폭발/파편은 독립 정책 또는 명시적 비활성 설정을 요구한다. 알 수 없는 정책 ID·불완전한 활성 설정은 로드 단계에서 거부한다. 기존 역사/비활성 프로파일에는 명시적 호환 비활성 경로를 둔다.
5. 판정 단위도 정책 데이터로 명시한다. 이번은 **실제 명중 착탄 1건당**이며 발사 순간/프레임/주기별 추첨이 아니다. 다른 무기의 발당·점사·폭발 사건 단위는 후속이다. 테스트용 다른 정책을 넣어 전차포 기본값으로 폴백하지 않음을 입증한다.
6. 아래 세 신규 범주 중 **한 착탄에서 최대 하나**만 선택한다: 새 일시 이상 / 한 명의 경상 / 한 명의 중상. 범주별 독립 추첨으로 여러 신규 사건을 만들지 않는다. 기존 WIP15 반응은 별도로 한 번 유지되므로 함께 발생할 수 있다. 이를 전체 효과가 한 종류로 제한된다고 보고하지 않는다.
7. `p_i = 기본률[정책][피격결과][구역][범주] × 차량감수성[범주]`다. 현재 M1A2 시험 계수는 모두 1. 각 값은 유한·0~1, 합은 1 이하여야 하고 나머지가 사건 없음이다. 잘못된 합계를 자동 정규화/클램프로 숨기지 않는다. 선택 순서와 `[이전 누계, 다음 누계)` 경계를 고정한다.
8. HP 감소량에 비례하는 공통 확률식을 새로 만들지 않는다. 과관통의 HP 감소 배율을 신규 확률에 다시 곱하지 않으며, 현재 정책에서 과관통은 관통 행을 사용한다. 미래 M919의 낮은 HP 피해·높은 일시 이상 성향은 독립 정책에서 정할 수 있어야 한다. WIP15의 기존 계산 피해 기반 확률식은 그대로다.

## 3. 현재 M829A2용 초기 시험표

**다음 수치는 확정 제원이 아닌 WIP18 플레이테스트용 제안이다.** 차량 감수성 1에서 명중 1회 기준의 최종 범주 확률이다. 앞선 대화의 공통 8/6/1% 예시는 이 구역별 표로 구체화하며 모든 무기에 적용하지 않는다.

| 실제 피격 구역 | 근접 비관통: 새 일시 이상 | 관통: 새 일시 이상 | 관통: 경상 | 관통: 중상 |
|---|---:|---:|---:|---:|
| 차체 전면 | 1.5% | 5% | 3% | 0.5% |
| 차체 측면 | 2.5% | 7% | 5% | 1% |
| 차체 후면 | 3.5% | 10% | 3% | 0.5% |
| 포탑 전면 | 1.5% | 4% | 4% | 0.5% |
| 포탑 측면 | 2.5% | 6% | 7% | 1% |
| 포탑 후면 | 3% | 8% | 5% | 1% |
| 통합 상부 | 2.5% | 6% | 5% | 1% |

- 일반 비관통·도탄의 **신규** 범주는 모두 0, 근접 비관통의 경상/중상도 0이다. WIP15의 기존 비관통 동요·포탑 이상까지 0으로 바꾸지 않는다.
- 근접 여부는 기존 비도탄 `nearNonPenetration` 분류를 쓰며 근접 HP 피해 추첨 성공 여부를 신규 사건의 조건으로 삼지 않는다. 관통 여부는 기존 판정 결과다.
- 예: 차체 측면 관통은 일시 이상 0.07, 경상 0.05, 중상 0.01, 사건 없음 0.87이다. 경상이 난 뒤 중상을 다시 추첨하지 않는다.

범주가 당첨된 뒤 사용하는 **현재 M1A2용 게임 가중치 제안**이다. 백분율 합은 각 대상 열 묶음마다 100이다. 경상·중상은 초기에는 같은 인원 분포를 쓰되 데이터상 따로 바꿀 수 있게 한다.

| 구역 | 기동계 / 포탑 구동 | 조종수 | 전차장 | 포수 | 장전수 |
|---|---|---:|---:|---:|---:|
| 차체 전면 | 100 / 0 | 70 | 10 | 10 | 10 |
| 차체 측면 | 100 / 0 | 40 | 20 | 20 | 20 |
| 차체 후면 | 100 / 0 | 55 | 15 | 15 | 15 |
| 포탑 전면 | 0 / 100 | 5 | 20 | 50 | 25 |
| 포탑 측면 | 0 / 100 | 5 | 30 | 30 | 35 |
| 포탑 후면 | 0 / 100 | 5 | 20 | 25 | 50 |
| 통합 상부 | 50 / 50 | 25 | 25 | 25 | 25 |

- 이 분포는 실제 내부 좌표·파편 추적이나 실차 약점 자료가 아니다. 인원 구성/기능 대상은 차량 프로파일 소유다. 존재하지 않는 장전수 등을 자동 생성하지 않는다. 활성 사건의 대상 합계 0, 없는 역할에 양의 가중치, 음수/NaN 등은 설정 오류로 거부한다.
- 통합 상부에서 기능 대상이 선택되는 것은 상부 사건의 대상 가중치이지 차체/포탑 피격 구역의 재추첨이 아니다. 원래 구역·관통·HP 결과를 변경하지 않는다.

## 4. 신규 일시 기능 이상

| 상태 | 시험 효과 | 시험 수명 |
|---|---|---|
| 기동계 일시 이상 | 양방향 유효 구동력 0.65배 | 6~10초 |
| 포탑 구동 일시 이상 | 실제 포탑 선회 속도 상한 0.60배 | 6~10초 |

- 구동력 저하는 실제 구동 계산에 적용한다. 현재 속도를 곧바로 0.65배로 바꾸거나 전후진 부호·기어를 바꾸지 않는다. 기존 제동·후진 interlock·정차/도착·충돌·정적 nav 계약을 보존하고 기본 최고속도 제원은 덮어쓰지 않는다.
- 포탑 구동 이상은 실제 포탑 각도 변화에 적용한다. 조준 진행률/오차를 다시 낮추는 사통 이상으로 구현하지 않는다. 포수 장비 방향·도안·정렬 검사·포구/발사 효과가 실제 포탑 자세와 일치해야 한다. 전차장의 독립 장비를 포탑 구동과 함께 묶어 느리게 만들지 않는다.
- 기간은 해당 사건의 별도 결정 난수로 정한다. 같은 종류 재발은 `max(기존 종료, 현재 시각+새 기간)`이며 시간을 더하지 않는다. 여러 착탄에서 서로 다른 종류가 생기는 것은 허용한다. 종료 시 그 상태의 기여만 제거한다.
- HP를 추가로 깎거나 이동/경계/지정/AI 임무를 취소하지 않는다. 격파 차량은 회복 사건으로 되살아나지 않는다. 사망한 차량의 상태 갱신·표시는 기존 격파 처리와 함께 정리한다.

## 5. 승무원 상태와 능률

- 현재 M1A2에는 조종수·전차장·포수·장전수 각 1명의 `정상/경상/중상`을 둔다. 기존 프로파일의 인원수 `crew:4`는 유지하고 역할 정의와 단차별 부상 상태는 별도로 둔다. 별도 인체 HP·장기/부위·출혈·사망·무력화·대체 인원 모델은 만들지 않는다.
- **이번 시험 회복 정책:** 부상 등급은 해당 전투/시나리오 동안 유지하고 reset에서 정상으로 초기화한다. 시간만으로 치료하거나 중상을 경상으로 낮추지 않는다. 영구 캠페인 기록은 아니며 치료·회복 방식의 최종 확정을 뜻하지 않는다. 장비의 타이머 회복과 승무원 부상을 구분한다.
- 새 부상은 `max(기존 등급, 새 등급)`이다. 경상이 반복됐다는 이유로 자동 중상으로 올리거나, 중상 뒤 경상이 당첨됐다고 회복시키지 않는다. 이미 같은/더 높은 부상인 대상이 선택되면 상태 유지로 기록하고 다른 사람/사건을 재추첨하지 않는다.

| 역할 | 경상 시험 계수 | 중상 시험 계수 |
|---|---|---|
| 조종수 | 구동력 0.85, 차체 선회 상한 0.90 | 구동력 0.65, 차체 선회 상한 0.75 |
| 전차장 | 독립 관측 장비 실제 재지향·선회 속도 0.85 | 같은 속도 0.65 |
| 포수 | 조준 진행률 0.85, 오차 표준편차 1.10 | 조준 진행률 0.65, 오차 표준편차 1.30 |
| 장전수 | 장전 작업 효율 0.85 | 장전 작업 효율 0.65 |

- 조종수 계수는 전후진 구동과 차체 선회에 적용하되 제동을 약화시키거나 이미 적분한 이동을 되돌리지 않는다. 전차장은 자동 탐색과 지정 지점 재지향 양쪽의 실제 각속도를 한 번 낮춰 표적 전환을 늦추며 명령 인계 지연 큐를 새로 만들지 않는다. 관측 거리/FOV·증거 임계값·LOS 표본 수/정밀도는 바꾸지 않는다.
- 포수 부상은 정상 자체 관측·지정·확보와 발사 자격을 보존하고 조준 작업/오차만 낮춘다. 전차장·포수의 부상 때문에 기존 명령을 취소하거나 적 정보·관측 시각을 조작하지 않는다.
- 장전 작업 시간은 기존 `기본+피로+동요`와 장전수 효율을 반영한 뒤 **최종 14초 상한**을 적용한다. 예: `min(14, 기존 작업 시간/장전수 효율)`. 정상 상태의 기본 5.98초와 기존 피로 규칙을 보존한다. 진행률은 현재 작업 속도로 이어가며 부상/타이머 변화로 완료된 작업을 되돌리거나 탄약을 다시 소비하지 않는다.
- 자동장전 차량·장전수 없는 차량의 실제 플레이 도입은 후속이다. 이번 인원 스키마를 모든 차량에 4인·장전수 존재로 고정하지 않는다.

## 6. 중첩·코어 연결·결정성

- **동일 능력 채널의 능률 계수는 더 큰 불이익 하나만 적용**한다. 속도/효율/진행률 계수는 최솟값, 오차 표준편차 계수는 최댓값을 쓴다. WIP15의 기존 피로+동요 시간 합산은 기준 장전 작업으로 유지하고 이 규칙을 이유로 해체하지 않는다. 서로 다른 능력 채널은 각자 적용한다. 기존 사통의 발사/조준 차단은 우선하며 능률 계수가 차단을 해제하지 않는다.
- 예: 구동 이상 0.65와 조종수 경상 0.85는 0.5525가 아니라 0.65다. 관측 이상 0.70/1.25와 포수 경상 0.85/1.10은 0.70/1.25다. 관측 이상 종료 뒤 부상이 남으면 0.85/1.10이 유지돼야 한다. 타이머 종료 때 모든 계수를 무조건 1로 덮어쓰지 않는다.
- 기본 차량 프로파일을 전역으로 수정하지 않는다. 단차 상태와 별도 유효 계수 계층을 사용하고 변경/만료 시 갱신한다. 실제 적분·장비 선회·조준/장전·명중률 예상 UI가 같은 유효값을 사용해야 한다.
- 기존 틱 순서(이동 → 도착 탄/피해/반응 → 관측 → AI → 장전·조준·발사)를 유지한다. 착탄 이전 이동을 소급 변경하지 않고 구동 저하는 다음 이동 갱신부터, 착탄 뒤 관측 장비·조준·장전은 해당 소비 단계부터 적용한다.
- 명중·구역·관통/도탄·근접 피해·WIP15 반응 난수 키/결과를 밀어내지 않는다. 신규 범주·대상·수명은 사건 ID/seed에 묶인 별도 키를 쓴다. UI 조회·렌더·배속 묶음·Worker 완료 순서는 난수를 소비하거나 상태를 바꾸지 않는다.
- 같은 착탄 ID를 다시 전달해도 신규 상태·기간·통계가 중복 적용되지 않는다. 기존 `applied=false`도 존중하고, 신규 처리 경로 자체의 중복 보호를 시험한다. 로그 순서와 처리 상한을 명시한다.
- 발사 때 기록한 오차/능률은 비행체에 고정한다. 비행 중 사수 부상·고장/복구가 이미 발사한 포탄을 바꾸지 않는다. WIP16의 표적 소유권·halt 무발사 검사·정차 첫 발·차폐 재확인·임무 복귀는 보존한다.
- 새 파일을 만들면 실제 페이지·오프라인 HTML·내장 Worker·Node·테스트 팩토리·직접 코어를 조립하는 생성/벤치마크 경로를 모두 연결한다. 선행 전역 초기화에 의존하지 않는다. 무상태 Worker 계산에 승무원 사건 추첨을 넣지 않는다.

## 7. 표시·정보 경계·성능

- 선택/명단의 아군에 일시 구동/포탑 이상과 남은 시간, 승무원 역할별 정상/경상/중상을 간결하게 표시한다. 기존 장전·사통/관측 상태와 원인을 구분하고 UI 조회가 사건을 생성하지 않게 한다.
- 적의 실제 부상·고장·잔여 시간·확률/난수·내부 대상 ID는 접촉/표적 패널·공개 snapshot·이펙트에 추가하지 않는다. 실제 기동/포탑 동작의 변화는 자연스럽게 보일 수 있다. 비공개 로그와 플레이어 공개 사본을 구분하고 기존 마지막 관측 HP/기억 규칙을 유지한다.
- 포탑 구동 이상/전차장 부상 때문에 관측 범위 자체를 줄이거나 시야를 강제로 끄지 않는다. 상태 알림을 위해 적에게 매 프레임 LOS/피해 검사를 추가하지 않는다.
- 피격 때 O(1) 선택과 작은 상태 갱신, 기존 틱에서 소수 상태의 만료/계수 소비로 구현한다. 장비/승무원별 물리 엔진·파편 추적·추가 전체 지도/유닛 쌍 순회를 넣지 않는다.
- 같은 환경·seed·배치·유닛 수에서 main/신규 비활성/신규 활성의 틱·상태 갱신 중앙값/P95와 추가 할당/상주 상태를 측정한다. 전투 결과 변화로 생존 차량 수가 달라진 수치를 순수 상태 처리 비용으로 해석하지 않는다. 50/100대의 상태 갱신과 실제 기본 앱 측정을 구분한다.
