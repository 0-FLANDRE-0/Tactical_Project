M830에 KE의 근접 분류를 억지로 만들지 않는다. 기존 WIP15의 피격 동요/관측·사통 반응과 A2 정책·난수 키는 보존한다.

## 3. 차량별 초기 재고와 보존 계약

**현재 M1A2 전용 초기 게임 시험안:** 장전탄 1발을 포함해 42발이다. 아래 보관 칸 용량은 실제 탄약고 제원이 아닌 구현/플레이 검증용이다. 다른 차량·기존 M1A1 프리셋으로 확정하거나 전파하지 않는다.

| 상태/구획 | M829A2 | M829A1 | M830 | 합계/이번 보관 용량 |
|---|---:|---:|---:|---:|
| 장전 완료 | 1 | 0 | 0 | 1 / 1 |
| 즉응 보관 | 7 | 4 | 6 | 17 / 17 |
| 준즉응 보관 | 8 | 6 | 4 | 18 / 18 |
| 예비 보관 | 2 | 2 | 2 | 6 / 6 |
| **총계** | **18** | **12** | **12** | **42** |

- 탄종 ID·비음수 정수 수량·구획 용량·장전칸 0/1·총량·지원 탄종·초기 작업 없음·적용 차량 ID를 로드 단계에서 검증한다. 신규 설정을 다른 ID로 단순 복제해 자동 활성화하지 않는다. 기존 미참여 프로파일은 명시적 호환 경로로 동작한다.
- 총 잔탄은 **구획에서 사용 가능한 탄 + 현재 작업이 예약/운반 중인 탄 + 장전탄**의 합으로 계산한다. 탄종별로도 같은 보존식을 만족해야 한다. 장전칸을 저장탄에 중복 포함하거나 준비·보충 시작 때 탄을 소비한 것으로 세지 않는다.
- 작업 시작 시 원구획의 탄 1발을 예약해 사용 가능한 재고에서 빼고, 작업 토큰이 그 탄을 소유한다. 완료 시 장전칸 또는 즉응 구획으로 옮긴다. 취소 시 같은 탄을 원구획으로 반환한다. 예약한 반납 자리와 용량도 보장한다.
- 실제 발사 성공 때만 장전칸의 탄 1발과 총 잔탄이 감소한다. 거절·조준·선택·준비/장전·보충·pause·차량 전환·중단 재개는 총량을 바꾸지 않는다. 격파/reset은 기존 생명주기에 맞춰 작업을 정리한다.
- `fireControl.ammo` 같은 기존 총탄 인터페이스는 이 재고의 파생 조회값으로 정리한다. 독립 가변 총탄 카운터와 구획 재고를 따로 감소시키지 않는다. 코어 내부 발사 사건의 `ammoRemaining`도 실제 발사 후 합계다. 공개 연출 사건으로 옮길 때 적의 잔탄 등 비공개 상태는 제외한다.

## 4. 다음 탄종 선택과 장전 작업

- 선택은 **다음 장전탄**이다. 이미 장전된 탄은 그대로이며, 준비/장전이 시작된 작업의 탄종도 완료까지 고정한다. 중간에 선택을 바꿔 다른 탄으로 변환하거나 진행률을 얻지 않는다. 변경된 선호는 다음 새 장전 작업에 적용한다. 강제 탈탄은 이번에 없다.
- 선택 UI는 `자동 / M829A2 / M829A1 / M830`을 제공한다. 자동의 초기 우선순위는 A2→A1→M830인 **M1A2 시험 설정**이다. 재고 전체에서 해당 우선순위의 사용 가능한 탄종을 고르고, 그 탄종 안에서 즉응→준즉응→예비 순으로 가져온다. 자동이 정답 탄종을 적의 숨은 장갑/상태로 골라주는 전술 AI를 새로 만들지 않는다.
- 수동 선호 탄종이 없으면 다른 탄으로 조용히 바꾸지 않고 `선택 탄종 없음`을 표시한다. 장전된 탄은 그 선택과 무관하게 기존 사격 조건으로 사용할 수 있다. 현재 자동/보류 사격 모드를 탄종 선택이 변경하지 않는다.
- 한 차량의 장전수 작업은 하나다. 작업 상태는 탄종·원구획·목적·예약탄·단계·진행률을 갖는다. 실제 장전이 보충보다 우선이며 준비와 장전을 동시에 진행하지 않는다.

| 장전용 공급 위치 | 추가 준비 작업의 정상 기준 시간 [시험] | 이후 장전 |
|---|---:|---|
| 즉응 | 0초 | 현재 장전 작업 |
| 준즉응 | 3초 | 준비 뒤 현재 장전 작업 |
| 예비 | 10초 | 준비 뒤 현재 장전 작업 |

- 현재 장전은 기본 5.98초+기존 피로/동요와 장전수 효율을 반영하고 **장전 단계의 최종 14초 상한**을 유지한다. 추가 준비는 별도 작업이라 전체 발사 준비는 14초를 넘을 수 있다. 14초를 전체 준비 시간으로 다시 잘라 구획 차이를 없애지 않는다.
- 추가 준비와 보충의 진행 속도에는 해당 장전수 효율을 한 번 적용한다. 기존 피로/동요의 초 단위 가산은 기존 장전 단계에 유지해 준비 단계에 다시 더하지 않는다. 부상/피격으로 작업 속도가 바뀌어도 완료한 진행률을 되돌리지 않는다.
- 실제 준비/장전은 이동·부대 선택 변경으로 취소하지 않는다. 이번에는 공급 구획 때문에 별도의 정차 필수 조건을 추가하지 않는다. 움직임으로 멈추는 것은 아래의 비전투 자동 보충 작업이다.
- 플레이어와 적 AI는 같은 재고·예약·작업·사격 자격을 사용한다. 준비/장전 대기를 총탄 소진으로 오인하지 않는다. 진짜 총탄 0은 WIP16처럼 교전을 해제하고 원래 임무로 한 번 복귀한다. 수동 선택탄만 소진된 상태도 무한 halt/표적 재지정 루프를 만들지 않으며 선호 명령을 보존한 채 실행 불가 사유를 처리한다.

## 5. 즉응탄 자동 보충

- **초기 시험 조건:** 실제 속도 0.10m/s 이하, 장전칸에 탄이 있음, 실제 사격/명중 피격 후 10초 이상 경과, 자체 현재 관측된 적 위협 없음, 즉응 구획에 빈자리와 보충 대상 부족분이 있음, 다른 준비/장전 작업 없음. 비공개 적 위치/실제 사거리/실제 생존 상태로 안전 여부를 판단하지 않는다.
- 즉응 목표 구성의 초기값은 위 즉응 보관 7/4/6이다. 다음 선호 탄종의 목표 부족분부터, 이후 설정된 A2→A1→M830 순서의 부족분을 보충한다. 해당 탄종의 준즉응을 먼저, 없으면 예비를 사용한다. 다른 탄을 버리거나 가득 찬 즉응 구획의 탄을 임의 교환하지 않는다.
- 정상 기준 **준즉응→즉응 4초/발, 예비→즉응 8초/발**의 게임 시험값이다. 한 발씩 예약/이전하고 완료한 탄만 목적 구획에 들어간다. 장전수 효율은 한 번 반영한다.
- 이동·현재 위협·피격 등 조건 이탈 시 보충을 일시 중단한다. 해당 예약탄과 부분 진행은 유지하고 재개 조건 충족 뒤 이어간다. 이 동안에도 총량이 맞아야 한다. 사격 후 실제 준비/장전이 필요해지면 보충을 선점 취소해 탄을 원구획에 반환하고 보충의 부분 진행을 폐기한 뒤 실제 장전 작업을 시작한다.
- 작업 소유자는 단차 상태다. 선택/패널 변경이 다른 차량의 보충을 멈추거나 옮기지 않는다. 게임 일시정지 시 모든 작업/타이머가 멈추고 reset은 초기 장전/재고/선호로 복원한다. 외부에서 새 탄을 생성하는 재보급은 이번에 넣지 않는다.

## 6. 우측 패널 전면 재구성과 지도 조작 이전

**사용자 최신 지시의 필수 배치:** 우측 상단은 조작 영역, 그 아래는 선택 유닛 정보다. 기존 우측 내용을 그대로 둔 채 아래에 새 UI를 덧붙이지 않는다.

| 영역 | 이번 구성 |
|---|---|
| 우측 상단 명령 | 지도 표시/확대·축소/맞춤, 이동/후진/정지, 시야 홀드/경계, 사격 자동·보류/지정·취소/단발, 다음 탄종 선택 |
| 그 아래 선택 유닛 정보 | 이름·형식, 현재 HP/속도·기동/교전 상태, 현재 장전탄/다음 선호·작업 단계/남은 시간·탄종/구획별 잔량, 고장/기간, 승무원 역할별 정상/경상/중상 |
| 선택 정보 안의 표적 문맥 | 기존 공개 가능한 현재 관측/기억·포수 확보·표적 상태를 간결하게 제공. 적 접촉과 선택 아군의 내부 정보를 혼동하지 않음 |

- 기존 `tank-profile` 전차 그림, `vehicle-specs`/`vehicleSpecs`/`profileTitle`의 고정 상세 제원·출처 설명, 큰 분대 카드 목록과 장황한 도움말/정적 지표 블록 등 구형 우측 구조를 제거·재구성한다. 선택 정보에는 현재 운용에 필요한 상태를 둔다. 정적 치수·중량·엔진 출력·관측 제원 카탈로그를 다시 채워 넣지 않는다.
- 지도 위 `map-tools`의 `terrainMode/zoomIn/zoomOut/fit`, `dock`의 `move/reverse/stop/sight/guardMenu/contours`, 경계 설정 `guardPopup`과 내부 입력/버튼을 우측 명령 영역으로 실제 이동한다. 경계 설정은 그 영역 안에 펼치는 방식으로 처리한다. 지도에 숨은 복제 버튼·동일 ID를 남기지 않는다. 기존 우측 교전 버튼도 새 명령 영역에 정리한다.
- 헤더의 일시정지·배속·전체화면은 기존 전역 조작 위치를 유지할 수 있다. 지도에는 유닛/지형·표적/경계 시각화와 비조작 범례·축척·알림을 남길 수 있다. 기존 하단 dock용 빈 공간은 재조정한다. 출처/라이선스는 푸터·문서 등에서 보존한다.
- 지도 클릭으로 아군 선택과 적 접촉 지정을 유지한다. 필요하면 선택 정보 제목에 작은 아군 선택 콤보를 둬 빠른 전환을 제공하되 기존 큰 카드 목록을 그대로 복원하지 않는다. 선택 유닛이 없으면 명확한 빈 상태를 보여주고 유닛 명령만 비활성화한다. 지도 도구·초기화는 계속 사용 가능해야 한다.
- 상단 명령은 접근 가능하게 유지하고 아래 선택 정보는 독립적으로 스크롤할 수 있게 한다. 좁은 가로 화면에서는 버튼 줄바꿈/그룹 접기를 사용해 정보 영역을 전부 밀어내지 않는다. 다른 위치의 지도 위 부유 메뉴로 되돌리지 않는다.
- 기존 전체화면 폴백/집중 모드의 `.sidebar` 숨김을 그대로 두면 안 된다. 전체화면/집중 모드에서도 우측 명령과 선택 정보에 접근할 수 있어야 한다. 세로 화면의 입력 차단·일시정지/가로 복원은 유지한다.
- 새 우측 클릭·스크롤·select·경계 설정 입력이 지도 이동/사격/경계 지점 지정으로 통과하지 않게 한다. 시야 버튼의 홀드 해제는 pointerup/cancel/blur/선택/reset/방향 전환에서도 정상 처리한다. 단축키는 입력 필드 편집을 방해하지 않는다.
- 제거한 DOM을 갱신하는 `updateVehicleSpecs`, roster 관련 루프·핸들러·CSS를 정리한다. 숨은 구형 요소를 유지해 테스트만 통과시키지 않는다. 기능 API·선택/사격/경계 로직은 새 구조에 연결하고 관련 UI 테스트를 실제 새 의도에 맞게 갱신한다.
- 상태 문구에는 `WIP15 대응`, `WIP18` 같은 구현 버전 접두사나 내부 정책 ID를 넣지 않는다. 사용자가 현재 행동을 판단할 수 있는 이름/원인/남은 시간을 표시한다.

## 7. 유닛 위 짧은 상태 문구와 정보 경계

- 해당 **아군**에 실제 활성 상태가 있을 때만 화면 고정 크기의 작은 문구를 표시한다. 예: `사통장치 이상 4s`, `포탑 구동 이상 6s`, `준즉응탄 준비 3s`, `예비탄 준비 8s`, `즉응탄 보충 5s`. 정상 상태와 모든 평상시 장전을 나열하지 않는다.
- **승무원 정상/경상/중상·역할별 피해·부상 타이머는 유닛 위에 표시하지 않는다.** 승무원 피해는 우측 선택 유닛 정보에만 둔다. 기존 명단 요약이 남는 경우에도 부상을 지도 문구로 옮기지 않는다. 전투 중 부상 유지라는 WIP18 정책은 바꾸지 않는다.
- 문구는 최대 2줄, 초기 우선순위는 사통 차단 → 기동/포탑 구동 이상 → 관측장비 불안정 → 탄 준비/보충이다. 전체 상태는 우측에서 확인한다. 일시 중단된 보충은 가짜 초 감소 대신 `즉응탄 보충 대기` 등으로 구분한다.
- 남은 시간은 실제 작업 효율과 시뮬레이션 시간을 사용한다. 양수는 올림한 초 단위, 만료 시 문구 제거. 카메라 확대/축소와 무관한 화면 픽셀 크기로 유닛명·HP와 겹치지 않게 배치하고 화면 경계를 처리한다. 가독성 때문에 전장 단위 글자를 크게 확대하지 않는다.
- 적의 실제 재고·선호·고장·부상·내부 작업/타이머는 지도 문구·선택 정보·팀 접촉·공개 효과/사격 사건에 추가하지 않는다. 기존 관측 HP/기억 스냅샷 경계를 유지한다. 렌더는 상태 조회만 하며 LOS·재고 변경·사건/난수 추첨을 실행하지 않는다.

## 8. 결정성·실행 연결·성능

- 재고·선호·작업은 코어가 소유하고 0.05초 고정 틱으로 갱신한다. HUD/Canvas/DOM/조회 횟수·배속 프레임 묶음·Worker 완료가 작업이나 사건을 진전시키지 않는다. 시간에 `Date.now`/렌더 delta를 쓰지 않는다.
- 기존 착탄 → 관측/AI → 준비/장전/조준/발사 순서를 점검해 같은 틱의 피격·작업 완료·격파·사격이 한 번씩 처리되게 한다. WIP16 halt의 무발사 검사에서는 탄약/작업/발사 번호/효과를 소비하지 않는다.
- 구획 확장 미참여 프로파일의 M829A2 42발 호환 fixture에서는 기존 단일 저장탄/장전 경로와 판정·명중/구역/도탄·WIP15/WIP18 난수·행동을 보존한다. 구획별 공급/혼합 재고/새 탄종으로 바뀐 전투 전체가 이전과 같다고 주장하지 않는다.
- 새 모듈은 페이지·단일 HTML·내장 Worker·Node 로더·테스트 팩토리·지도 생성/독립 벤치마크의 필요한 경로에 명시 연결한다. ammo/차량 내보내기를 같은 데이터 원천에서 재현하고 Worker에 불필요한 단차 재고 사본이나 추첨을 넣지 않는다.
- 작업은 단차당 최대 1개, 고정 소수 탄종/구획의 작은 상태로 구현한다. 새 매 프레임 전체 지도·LOS·적 쌍 순회·대량 DOM/문자열 재생성·유닛 위 DOM 노드 대량 생성은 피한다. UI 캐시와 화면 내 그리기를 사용한다.
- 같은 조건의 baseline/신규 상태 갱신·기본 앱 틱/렌더 비용과 50/100대 작업/문구의 중앙값·P95·상주 상태를 측정한다. 코어 비용과 UI/렌더, 실제 모바일 미실시 범위를 구분한다.
