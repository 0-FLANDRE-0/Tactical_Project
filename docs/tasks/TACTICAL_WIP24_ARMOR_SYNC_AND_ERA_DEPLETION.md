## 3. 실행 데이터 동기화

### 3.1 M829A2

| 거리 | 0° KE | 30° KE | 60° KE |
|---|---:|---:|---:|
| 10m | **630** | **530** | **365** |
| 2,000m | **600** | **505** | **345** |

- 거리/각도 사이는 기존 공통 **선형 보간**을 사용한다. 개별 중간거리 표는 미확정이므로 만들지 않는다. 예: 1,005m의 0/30/60°는 **615 / 517.5 / 355**다. 10m 미만/2km 초과 끝값 고정, 60~90° 관통력 선형 연장과 발사 사거리 제한은 기존 정책대로 유지한다.
- 기본 피해 **405 HP**, 초속 **1,680m/s**, 기존 120mm APFSDS 피해 곡선·도탄각·근접 비관통·M1A2 피격/사고 정책은 바꾸지 않는다. M829A1/M830/3BM42 관통력·기본 피해·탄속과 125mm 곡선도 이번 동기화로 바꾸지 않는다.
- 이는 순수 KE 관통력 하향이다. 아직 미정인 **M829A2 Anti-ERA 감쇄율을 보상 수치로 넣거나 ERA 추가 KE를 완전히 무시하지 않는다.** 소모율에도 별도 가산하지 않는다. A3/A4·독일 현대 날탄을 함께 지급하지 않는다.

### 3.2 현재 두 차량의 기본장갑

단위는 게임용 **KE(CE)**다. ERA 추가 방호를 기본장갑에 미리 합산하지 않는다.

| 구역 | M1A2_1998 | T80U_1989 |
|---|---:|---:|
| 차체 전면 | 390(720) | 500(690) |
| **차체 측면** | **90(130)** | **75(85)** |
| 차체 후면 | 40(40) | 40(40) |
| 포탑 전면 | 720(1150) | 575(740) |
| 포탑 측면 | 340(630) | 305(390) |
| 포탑 후면 | 55(55) | 70(70) |
| 상부 | 40(40) | 45(45) |
| 최대 HP | **1,450** | **1,400** |

- 실제 변경은 기존 M1A2_1998 차체 측면 **120(280) → 90(130)**, T80U_1989 **115(120) → 75(85)**다. 나머지도 표와 대조해 동기화하고, 무근거한 HP/정면/포탑 장갑 보정으로 전투 시간을 맞추지 않는다.
- 차체 측면은 **단일 `hullSide` 구역**이다. 상·하부나 좌·우별 추가 구역/피복 상태를 새로 쪼개지 않는다. 선택된 차체/포탑 면과 입사각으로 기존 공통 판정을 수행하고 장갑 경사/LOS를 다시 곱하지 않는다.
- `M1A2` 호환 기준 프로파일에 새 전투/ERA 설정을 억지로 추가하거나 모든 차량에 M1A2 장갑을 공통 적용하지 않는다. M1A2_1998의 승무원/모듈/탄약고 반응 소유권, T-80U 3인 구성과 해당 피해 비활성 상태를 유지한다.
- 다른 전차/IFV의 최신 측면 수정은 각 정본에서 확인하되 **현재 런타임에 없는 차량은 아카이브 데이터 상태로 유지**한다. 국가별 공통 측면 상수나 전차 32종 신규 등록으로 범위를 확대하지 않는다. 완료 보고에 ‘이번에 코드 반영한 프로파일’과 ‘라이브러리만 존재하는 차량’을 구분한다.

### 3.3 T-80U 초기 K5 설정

| 구역 | 초기 피복률 | 추가 KE / CE |
|---|---:|---:|
| 차체 전면 | 90% | +215 / +560 |
| **차체 측면** | **50%** | **+110 / +560** |
| 차체 후면 | 0% | 0 / 0 |
| 포탑 전면 | 95% | +215 / +560 |
| 포탑 측면 | 45% | +215 / +560 |
| 포탑 후면 | 0% | 0 / 0 |
| 상부 | 45% | +215 / +560 |

따라서 K5가 적용된 차체 측면 방호는 **KE 185 / CE 645**다. K5 측면 KE만 +110이며 포탑 측면/상부 등을 함께 절반으로 낮추지 않는다. 초기 피복률은 WIP23과 같고, 이번부터 남은 피복률이 소모된다.

## 4. 공통 Kontakt 소모 정책

아래는 **현재 피복률에서 빼는 고정 %p**다. 현재 값에 비율을 곱하는 방식이 아니며, 직격 블록과 주변 탈락/연쇄 반응을 합한 최종 손실량이다.

| 탄종 계열 | K1 피복 지점 | K5 피복 지점 | K1 빈 지점 | K5 빈 지점 |
|---|---:|---:|---:|---:|
| HEAT / ATGM | 25%p | 32%p | 12.5%p | 16%p |
| APFSDS / APDS | 12%p | 24%p | 0%p | 0%p |
| HEP / HESH | 32%p | 40%p | 16%p | 20%p |
| HE / HE-FRAG | 40%p | 52%p | 20%p | 26%p |

- 내부 피복률을 0~1로 저장하면 K5 날탄 피복 손실은 **0.24**, K1 HEAT 빈 지점 손실은 **0.125**다. 피복/빈 지점 손실은 **배타적**이며 양쪽을 합산하지 않는다. `after=max(0,before-loss)`로 0 하한을 지킨다.
- ERA 종류와 소모 정책은 공통 데이터로, 초기 피복/부위별 추가 방호는 차량 프로파일로 둔다. 차량명/진영으로 K5를 추정하거나 T-80U 전용 손실 계산을 복제하지 않는다. K1 기본 추가 방호 **KE +5 / CE +380**도 공통 설정/fixture에서 검증한다.
- 탄약의 ERA 상호작용 계열을 **명시적으로 연결**한다. M829A2/M829A1/3BM42는 APFSDS, M830은 HEAT다. 기존 KE/CE 방호 선택 필드만으로 APDS·HEP·HE·ATGM을 추측하거나 `HEAT-MP` 이름에 HE가 들어간다고 HE 계열 손실을 적용하지 않는다.
- K1/K5 × 네 소모 그룹의 전체 표와 빈 지점 규칙은 공통 정책 함수로 검증한다. 현재 없는 APDS/ATGM/HEP/HE의 실제 탄약·신관·피해를 새로 구현할 필요는 없다. 테스트용 그룹/프로파일을 실전 레지스트리에 등록하지 않는다.
- 미등록 ERA 종류·계열, 비유한/범위 밖 피복률, 음수 손실/추가 방호, 잘못된 구역을 검증한다. 미지원 정책에 기본 손실을 임의 적용하지 않는다. ERA가 없는 M1A2에는 ERA 상태를 만들지 않는다.

## 5. 판정 순서와 차량별 상태

### 5.1 피격 한 번의 처리

1. 기존 착탄 ID 중복 검사와 표적 존재/생존·입력 검증을 먼저 통과한다. 명중 여부·피격 구역은 기존 공통 결과를 사용하고 ERA를 위해 다시 추첨하지 않는다.
2. **기존 도탄 우선 순서를 유지**한다. 이번 구현 정책에서 도탄 확정 탄은 ERA 미반응으로 처리해 피복 추첨/소모를 하지 않는다. 정본 소모표가 미확정 도탄·미기폭 특수 반응까지 확정한 것으로 확대하지 않는다. 새로운 신관 실패 확률은 넣지 않는다.
3. 유효 직격이면 **착탄 직전 그 차량·그 구역의 잔여 피복률**을 읽는다. 현재 값이 0이면 피복 방호/소모는 0이다. 잔여 피복이 있으면 기존 결정적 착탄 ID 기반 난수를 **한 번만** 뽑고 `roll < coverage_before`로 피복 지점 여부를 정한다. 동률은 빈 지점이다.
4. 피복 지점이면 이번 탄에 해당 구역 ERA 추가 KE/CE를 한 번 적용한다. 빈 지점이면 기본장갑만 사용한다. 이 **소모 전 방호**로 기존 관통·잔여 관통력·피해를 계산한다.
5. 같은 결과에서 탄종/ERA 종류에 맞는 손실을 정한다. 피복 지점에서 ERA가 반응하면 **관통·비관통 모두** 소모한다. 빈 지점은 폭발성 네 계열의 해당 표 값만 적용하고 APFSDS/APDS는 0이다. 다른 구역은 변하지 않는다.
6. 착탄 처리에 묶어서 **피복률을 한 번 갱신**하고 기존 HP/피격 반응/사고/격파 절차를 완료한다. 기존 처리 순서·중복 방지를 보존하고 재진입/중복 콜백으로 추가 소모하지 않는다. 순수 미리 계산 함수는 상태를 직접 바꾸지 않는다.

**순서 예시:** T-80U 포탑 전면 95%에서 날탄이 피복 지점에 맞으면 **이번 탄에는 KE 790**을 적용하고 그 뒤 71%가 된다. 다음 탄은 71%로 추첨한다. 새로 낮아진 피복률이나 다음 탄의 결과를 첫 탄 방호에 역적용하지 않는다.

### 5.2 독립 런타임 상태와 수명

- 초기 피복률/추가 KE·CE를 갖는 **불변 프로파일**과 차량마다 달라지는 **현재 잔여 피복률**을 분리한다. 같은 T-80U가 여러 대 있어도 피복 상태를 공유하지 않는다. 프로파일/공통 정책/내보낸 초기 JSON을 피격 때 수정하지 않는다.
- 현재 `initUnit`·`evaluate`·`apply`·ERA 추첨 경로가 정적 `profile.combat.era.zones[zone].coverage`를 반복 읽는다. 모두 일관된 현재 상태를 사용하도록 연결한다. **0을 초기값으로 되돌리는 `remaining || initial` fallback을 금지**한다. 초기화/상태 조회를 반복해도 피복률이 회복되면 안 된다.
- 비행탄은 발사 당시 탄약/오차를 유지하되 **피격 차량의 ERA는 착탄 시 최신 상태**를 사용한다. 같은 틱의 여러 탄착은 기존 `impactAt`/착탄 ID 순서로 처리하고, 뒤 탄은 앞 탄이 갱신한 피복률을 읽는다. 발사 시 남은 피복을 탄에 동결하지 않는다.
- 중복 착탄, 빗나감, 도탄, 표적 부재/기격파, 거부된 발사 요청, UI/로그/상태 조회만으로는 소모하지 않는다. 별도 무한 `processed` 목록을 만들지 않고 기존 유계 중복 처리 계약을 재사용한다.
- 격파 후 피복 상태는 마지막 값으로 정지한다. reset/새 시나리오는 새 차량의 초기 피복으로 시작한다. 기존 시나리오 차량을 다시 만들지 않는 동안 관측 상실/재발견·표적 변경·부상 회복·장전 완료가 피복을 복원하지 않는다.
- 일시정지/배속/렌더 빈도/유닛 선택·패널 열기와 소모량은 무관하다. 이번에는 수리/자동 회복·재장착 명령이 없다.

### 5.3 기존 피해·관측·장전과의 경계

- ERA 소모는 피복 방호의 수명이며 추가 HP 피해가 아니다. 비관통 ERA 반응을 이유로 표적/주변 차량에 폭발·파편 피해를 주거나 별도 명중/모듈 추첨을 추가하지 않는다. 통합 손실량에 주변 탈락이 포함됐으므로 다른 구역 소모도 추가하지 않는다.
- 장갑이 약해져 관통 가능성이 올라가도 기존 **과관통 곡선 때문에 관통 후 HP 피해가 줄어드는 구간**이 있을 수 있다. 관통률과 HP 피해를 구분해 검증하고 결과를 맞추려고 곡선/기본 피해를 보정하지 않는다.
- T-80U **6초 자동장전·장전탄 포함 13발·정지 사격·WIP22 관측/선회**, M1A2의 수동장전·피로/동요·부상·사고, 사격 불허 시 탄약/샷 번호/판정 난수 불변을 보존한다. ERA가 줄었다고 T-80U에 기존 M1A2 반응을 자동 상속하지 않는다.
- ERA 피복 감소는 지형/모델 실루엣 변화가 아니다. LOS·노출 표본·길찾기·시야 원뿔을 매번 무효화하거나 재생성하지 않는다. 차량당 작은 7구역 상태와 착탄당 상수 시간 갱신으로 처리한다.

## 6. 게임 표시·정보 경계·검증 장면

- 기존 기본 전투/방호시험/관측시험/정지 교전시험에서 같은 공용 피해 경로와 최신 프로파일을 쓴다. 정상 T-80U를 비소모로 남겨 두는 숨은 시나리오별 예외를 만들지 않는다. 관측/발사 기능 마스크는 WIP23대로 유지한다.
- 정지 교전시험의 양측 자동사격을 유지해 **ERA 적용 → 소모 → 빈 지점/기본장갑 관통 → HP 감소**가 정상 관측/조준/발사로 이어지는 실제 지형 사례를 제출한다. seed/배치·시각·공격탄·구역·소모 전후·피해를 기록한다. 피복 지점에 매번 맞도록 RNG를 강제한 fixture는 이 실제 흐름 증거와 구분한다.
- 새 대형 UI는 만들지 않는다. **선택한 아군 중 ERA 장착 차량에만**, 기존 선택 정보 영역에서 구역별 남은 피복률을 작게 확인할 수 있게 한다. ERA 없는 M1A2는 해당 항목을 숨긴다. 아군 T-80U/팀 교환 fixture로 실제 페이지 표시를 검증한다. 소모 자체는 지속 작업이 아니므로 유닛 위에 상시 일곱 줄이나 장전 작업 글자를 덧붙이지 않는다.
- **적 내부 잔여 피복률·ERA 추첨값/소모 전후·정확한 추가 방호는 정상 아군 패널/접촉/공개 피해 기록에 노출하지 않는다.** 현재 보이는 적이라도 이번에는 정확한 ERA 잔량 공개 기능을 추가하지 않는다. 숨은 적의 HP·기억 자세·현재 관측값 병합 규칙도 보존한다.
- 기존 포구·예광·피격/도탄 효과는 유지한다. ERA 소모를 위해 개별 블록 렌더/별도 물리를 만들지 않는다. 필요한 반응 효과를 표시해도 확정된 결과를 표현할 뿐이며 피해/소모를 재실행하지 않고 기존 효과 예산과 고정 월드 위치·정보 경계를 따른다.
- 내부 검증 기록에는 `eraType`, `coverageBefore`, `coverageAfter`, 실제 손실, 피복 여부/추첨값·적용 보너스·구역·공격탄을 남긴다. API 이름은 저장소 관례를 따르되 공개 사본과 분리하고 조회는 깊은 복사/불변으로 제공한다.

- **기존 검사를 변경할 때 원인을 구분한다.** M829A2·차체 측면·ERA 수명은 의도적으로 바뀌므로 WIP21의 비소모 반복 피격 기대값과 WIP23의 정상 상호 교전에서 ‘T-80U 생존하며 무조건 13발’ 기대값을 그대로 강제하지 않는다. 13발 보존/소진·6초 장전 자체는 상대 사격 보류 등 사수가 생존하는 별도 fixture에서 유지 검증한다. 정상 교전은 생존 기간의 발사/재고·격파 정리를 검증한다.
- 작성 기준과 신규를 같은 seed로 기존 네 시나리오 각각 90초 이상 비교한다. 관통·피복·피해 및 그에 따른 격파/AI/관측 차이는 의도된 원인으로 설명한다. 관측시험의 기존 최초 보류·무발사 구간, 지도·기동/선회·관측 절차·사격 불허 자원 보존 등 변화 없는 계약을 별도 비교한다. 기대값만 새 출력으로 덮거나 기존 검사를 삭제해 통과시키지 않는다.
- 전체 Node/Python 및 실제 Chromium 회귀를 실행한다. 실제 페이지의 반응/피해와 아군 ERA 표시를 캡처하고 정상 관측 모델이 화면 안에 보이게 카메라를 맞춘다. 단독 도안 미리보기/콘솔 결과만으로 게임 연결을 입증하지 않는다.
- 같은 환경에서 기존/신규 틱·렌더 중앙값/P95, 착탄 수·생존 유닛 수·LOS query/ray 수와 피복 상태 메모리를 기록한다. 격파 시각이 달라 생기는 비용 차이와 ERA 자체 비용을 구분한다. 렌더/패널 조회만으로 소모/LOS 조회가 늘거나 처리 이력이 무한 누적되면 안 된다.
