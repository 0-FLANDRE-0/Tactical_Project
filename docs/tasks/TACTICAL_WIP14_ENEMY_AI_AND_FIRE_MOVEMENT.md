- 현재 코어 순서는 이동 → 관측/인계 → 사격이다. 새 AI가 어느 시점의 관측을 읽고 언제 명령을 적용하는지 명시하고, 실제 이동 뒤의 속도로 최종 발사 조건을 검사한다.

## 3. 기본 임무와 교전 반응의 분리

### 3.1 기본 이동 임무

- 차량별 기본 임무는 최소한 **지정 지점으로 이동**과 **정해진 여러 지점의 순찰**을 표현한다. 순찰의 반복 방식과 종료 조건을 데이터로 명시한다.
- 임무 ID/갱신 번호, 제한된 경유점 목록, 현재 순번, 활성/일시 중단/완료 상태를 실제 이동 path/goal과 분리한다.
- AI가 새 경유점을 선택하면 기존 명령/경로 탐색 경로를 사용한다. x/y/heading/속도를 직접 덮어쓰거나 표시용 좌표만 움직이지 않는다.
- AI가 없는 차량은 임무 없이 정지하거나 기존 플레이어 명령으로 이동한다. 일반 `makeTank()`나 과거 관측 fixture에 임의 AI를 자동 부착하지 않는다. 정상 게임 시나리오에서 적의 임무를 명시적으로 설정한다.
- 내부 교전 정차와 명시적 임무 취소/새 명령을 구분한다. 명시적 새 이동·정지·초기화 이후 오래된 AI 경로나 예약 명령이 다시 살아나지 않게 한다.

### 3.2 교전 중 이동 정책

기본 임무와 별도로 다음 의미의 정책을 둔다. 코드상의 이름은 조정할 수 있으나 기존 사격 모드 `auto/hold`와 혼동하지 않는다.

| 정책 | 식별된 자체 접촉에 대한 동작 |
|---|---|
| 이동 유지 | 기본 경로를 계속 따라가고 기존 자동교전을 수행한다. 차량 자체가 기동간 사격 불가라면 발사 제약은 그대로 적용된다. |
| 정차 교전 | 기본 임무를 보존한 채 제동한다. 실제 정차·조준·발사 조건을 만족하면 교전하고, 접촉 상실 뒤 관측 대기를 거쳐 임무를 재개한다. |
| 성능 기준 자동 선택 | 기동간 사격 불가 차량은 필요한 교전 정차를 선택한다. 가능한 차량은 기본 임무의 이동 유지/정차 선호를 따른다. 이번 최소 선택 규칙을 명시하고 더 정교한 상황 판단의 확장점으로 둔다. |

- 현재 M1A2의 기동간 사격을 허용하되 모든 M1A2 AI를 무조건 정차시키지 않는다. 반대로 기동간 사격 가능이라는 이유로 정차 교전 정책 자체를 금지하지 않는다.
- 단순 상태 전이로 **임무 이동 → 교전 정차/관측 대기 → 임무 재개**를 표현한다. 이동 유지 정책은 접촉 때문에 기본 이동을 매번 취소하지 않는다.
- 정차 계기는 차량 자체의 현재 식별·적군 확인 접촉을 기준으로 한다. 미식별 주변 실루엣·표시용 사격 효과를 새 탐지 채널로 사용하지 않는다.
- 접촉을 잃으면 즉시 이동/정차를 반복하지 않도록 짧은 상실 유예·관측 대기를 둔다. 기존 관측 기억과 현재 관측을 구분하고 값은 게임용 설정으로 문서화한다.
- 사격 간격 대기·조준 진행·잠깐의 차폐만으로 매번 정차 정책과 임무를 새로 만들지 않는다. 같은 목표/정책은 유지하고 실제 상태 전이에서만 명령을 낸다.
- 탄약 소진 등 자기 차량이 알 수 있는 사격 불가 상태의 기본 처리도 정해 영구적인 재명령 반복을 막는다. 숨은 표적의 실제 생존/HP 변화로 임무 종료를 판단하지 않는다.
- 재개 시 원래 임무·경유점 순번·목적지를 사용한다. 변경된 장애물 때문에 필요하면 현재 위치에서 경로를 다시 구하되 매 틱 처음부터 재계획하지 않는다.
- 격파 차량은 판단·명령·예약 경로에서 즉시 제외하고 기존 잔해 점유를 유지한다. 초기화 시 AI·임무·대기/재시도·명령 큐를 함께 정리한다.

## 4. 차량 성능과 공통 발사 조건

**차량이 할 수 있는 일과 AI가 선택한 행동은 별개다.** 제한을 적 AI에만 넣거나 기존 `fireMode`로 차량 성능을 대신하지 않는다.

1. 차량 프로파일에 기동간 사격 가능 여부와 정차 사격에 필요한 실제 속도 허용치·필요한 정차 유지 조건을 명시한다. 명칭·단위·범위 검증과 JSON 내보내기를 연결한다. 값은 게임용 시험 설정이며 새 실차 사통 성능 인증값이 아니다.
2. 현재 등록 M1A2/M1A2_1998에는 기동간 사격 가능 설정을 적용하고 기존 이동 사격 오차를 유지한다. 정차 필수 동작은 별도 **합성 시험 프로파일**로 검증한다. 이를 실제 M1A2 성능 변경이나 새 정식 차종 추가로 기록하지 않는다.
3. 기동간 사격 불가 차량은 실제 종방향 속도의 절댓값과 정차 유지 조건을 공통 사격 경로에서 확인한다. 이동/정지 버튼 상태나 요청 속도가 0이라는 사실만으로 발사를 허용하지 않는다.
4. 이 성능 제약은 아군/적군 및 수동/자동 발사에 동일하게 적용한다. 발사 요청 후 다시 움직인 경우도 **최종 탄수 소비/발사 직전**에 거부해야 한다.
5. 거부된 요청은 탄약·사격/착탄 난수·발사 번호·비행체·피해·발사 이펙트를 소비/생성하지 않는다. 기존 관측·식별·포수 확보·정렬·사거리·발사선·조준·사격 간격 관문을 그대로 유지한다.
6. 정차 교전을 선택한 AI도 제동 중 먼저 쏘고 나중에 멈추는 방식이 되지 않게 한다. 그 정책의 자동사격 일시 억제와 차량 자체의 기동간 사격 가능 여부를 구분한다.
7. 일시적인 이동 정책 때문에 사용자의 기존 `auto/hold` 설정을 덮어쓰거나 `hold` 차량을 임의로 자동사격으로 전환하지 않는다. 교전 대기가 끝나면 자신의 임시 억제만 해제한다.
8. 정차 판정/유지 시간은 시뮬레이션 고정 틱과 실제 속도로 갱신한다. 일시정지·2배속·프레임 묶음에 따라 발사 조건이 달라지지 않게 한다. 단순 제동 요청 때 조준·관측 기억·표적 속도 추정을 매번 불필요하게 초기화하지 않는다.
9. 기동간 사격 가능 차량도 임무 설정에 따라 정차를 선택할 수 있다. 이동 중 정확도가 낮으면 정차하는 등의 정교한 확률 문턱은 후속이다. 이번에는 기존 미리보기 계산을 추가 난수나 새로운 전수 LOS 없이 연결할 수 있는 구조만 확보한다.

## 5. AI가 사용할 정보와 공개 경계

- AI는 자기 차량의 상태·임무와 **자체 관측·식별·기억 정보**를 입력으로 사용한다. 적 전체 실체 목록을 읽어 가장 가까운 실제 위치를 추적하는 구조로 만들지 않는다.
- 접촉 소실 후 살아 있는 상대의 숨은 현재 좌표·HP·격파·잔탄·현재 명령을 계속 읽지 않는다. 필요한 기억은 마지막 유효 관측의 사본이며 새 위치로 몰래 갱신하지 않는다.
- 팀 공유 기반의 새로운 전술 판단은 이번 필수 범위가 아니다. 기존 포수 자체 관측·전차장 인계 규칙은 계속 사용한다.
- 기존 경로 탐색/충돌의 월드 점유 처리는 물리 기능으로 유지한다. 이를 통해 AI 판단에 비공개 상대 좌표를 새로 제공하지 않는다.
- AI의 새 판단을 이유로 자체 LOS/노출을 다시 전수 계산하지 않는다. 현재 관측 결과와 기존 사격 게이트를 재사용한다.
- 적의 임무/예정 경로·AI 상태·실제 ID/위치·비공개 현재 HP는 기본 UI, `__TACTICAL__` snapshot, 공개 디버그 통계에 추가하지 않는다. 관측되지 않는 적의 실제 이동이 청색 선택·명단·경로선으로 보이지 않아야 한다.
- WIP12의 사격/피격 효과 공개와 유닛 공개는 계속 구분한다. 이펙트를 봤다고 접촉·모델·체력·잔해를 자동 공개하지 않는다.
- AI 내부 검사에 필요한 정보는 분리된 Node 검사나 비공개 브라우저 fixture에서 주입/기록한다. 정식 실행 HTML에 적 실체를 반환하는 검사 전용 API를 남기지 않는다.

## 6. 갱신 주기·경로 요청·성능

- 이동 물리·관측·사격의 기존 고정 스텝을 유지한다. 새 AI의 일반 행동 판단은 **0.5~1초 정도의 저주기**에서 시작하고 주기·설정 근거를 명시한다.
- 차량별 결정적 위상을 두어 많은 차량이 같은 틱에 동시에 판단하지 않게 한다. 사망·명령 취소와 최종 발사 안전 조건은 느린 AI 판단을 기다리지 않는다.
- AI는 동일한 목적지/정책의 이동·정지 명령을 반복하지 않는다. 임무 진척·상태 변경·실제 경로 차단처럼 의미 있는 사건에서만 필요한 명령을 낸다.
- AI 경로 요청은 처리 예산·차량별 재시도 간격·보류/실패 상태를 갖게 한다. 기존 충돌 후 재계획과 중복 요청을 조정하고, 경로가 없으면 잠시 대기 후 제한적으로 재시도한다.
- 보류된 경로/명령은 임무 갱신 번호와 차량 생존 상태를 재확인한 뒤 적용한다. 초기화·새 명령·격파 뒤 오래된 결과를 적용하지 않는다.
- 새 Worker·전역 비동기 탐색이나 별도 대형 경로 탐색 알고리즘은 필요하지 않다. 기존 경로 기능의 호출량과 프레임 집중부터 제어한다.
- 벽시계·RAF 횟수·객체 순회 중의 전역 Math.random을 판단 기준으로 사용하지 않는다. 난수가 필요하면 전투·시각 난수와 분리된 AI용 키/seed를 쓴다. 정해진 경로의 최소 AI에는 난수가 필수는 아니다.
- 같은 고정 틱·seed·명령/관측 조건에서는 결정과 명령이 재현되어야 한다. 1배속/2배속·UI 조회·화면 밖 렌더 생략이 AI를 다르게 실행하지 않게 한다.
- 순수 판단은 고정 입력의 AI 50/100대 묶음으로 측정한다. **100대 한 번 판단의 중앙값 1ms 이내를 경량 목표**로 두되 경로 탐색/LOS/물리/렌더 제외임을 명시한다.
- 실제 지도에서도 총 틱/프레임·AI 판단·길찾기 요청/방문 셀·LOS/관측 비용의 중앙값/P95와 단발 집중을 기록한다. 판단은 가벼워도 길찾기 폭주가 있으면 완료로 처리하지 않는다.
- 비교는 같은 배치·준비 운동·측정 시간·반복 수로 한다. WIP13은 적이 정지하므로 전체 비용의 단순 전후 차이를 AI 판단 비용이라고 주장하지 않는다. 순수 판단 비교와 전체 게임 비용을 분리하고 이동/생존 차량 수·거리·접촉·발사 수도 기록한다.

## 7. 정상 시나리오와 검증

### 7.1 정상 실행에서 확인할 모습

- 기본 게임에 유효한 경로를 가진 이동 적을 명시적으로 배치한다. 적어도 한 차량은 **접촉·교전 중에도 이동을 유지**해 실제 움직이는 표적을 검사할 수 있어야 한다.
- 다른 차량/분리된 명시적 시나리오에서는 **정차 교전 후 원래 임무 재개**를 확인할 수 있게 한다. 임무는 사전에 정한 지도 지점이며 숨은 아군 실체 좌표를 초기 목적지로 자동 지정하지 않는다.
- 기존 정지 적/AI 없는 fixture도 지원한다. 기존 검사 때문에 정상 게임의 AI까지 비활성화하거나 이동을 그림으로만 재생하지 않는다.
- 순찰 경로는 실제 지도에서 출발·경유·종료/반복과 충돌 없이 통과 가능한지 검증한다. 매 결정 때 새 임의 목표를 뽑아 차량이 방향을 계속 바꾸는 방식은 사용하지 않는다.
- 기존 정보/조작 영역에서 필요한 아군 상태만 설명한다. 적 AI의 예정 경로를 보여주는 새 패널은 추가하지 않는다.

### 7.2 필수 검사

| 범위 | 확인할 결과 |
|---|---|
| 적 실제 이동 | 청/적 동일 구동 경로, 실제 x/y·속도·차체 자세 변화, WIP13 제동·선회·도착 유지 |
| 임무 | 지점 이동·반복 순찰·경유점 진척·경로 실패의 제한된 재시도, 중복 명령/길찾기 억제 |
| 이동 유지 | 관측·자동교전과 실제 이동이 동시에 계속되는 구간을 기본 게임 루프로 재현 |
| 정차 교전 | 유효 자체 접촉으로 제동, 실제 정차 후 발사, 임무/순번 보존, 상실 유예 후 한 번 재개 |
| 정책과 성능 | 동일 M1A2의 이동 유지/정차 선호 구분, 합성 기동간 사격 불가 프로파일의 자동 정차 선택 |
| 공통 발사 제한 | 양 팀·수동/자동의 이동 중 거부, 실제 정차 후 허용, 요청 후 재이동 거부, 탄수/난수/효과 부작용 없음 |
| 기존 모드 | 교전 일시 억제와 기존 auto/hold 분리, hold 자동 발사 없음, 새 명령이 AI 예약보다 우선 |
| 관측 제한 | 접촉/기억이 같고 비공개 상대 위치만 다른 비충돌 조건에서 동일 AI 판단. 숨은 HP/격파 변화로 반응하지 않음 |
| 움직이는 표적 | 자기 관측에서 속도 추정, 표적 상실/재확보·포탑 추적·게임 사격/피격/도탄 효과 연결 |
| 수명과 결정성 | 격파·초기화·명령 번복·오래된 경로 요청 무효화, 1배속/2배속·일시정지·프레임 묶음 동등 |
| 공개 정보 | 미관측 이동/AI 상태 비공개, 적 사격 효과는 기존대로 표시, 실제 관측에 따른 접촉/HP/잔해 규칙 유지 |
| 다수 차량 | 판단 분산, AI/경로 요청 예산과 기존 LOS 정밀도·캐시·관측 주기 유지, 전체 비용과 이동 실적 함께 기록 |

- **실제 Chromium 앱**에서 이동하는 적 관측·기동 중 자동교전과 정차 교전/재개를 각각 재현한다. 새 모듈만 따로 실행하거나 snapshot의 플래그만 보고 완료로 처리하지 않는다.
- Node/합성 시험은 이동 정책·정보 경계·공통 발사 조건을 분리해 검사하고, 실제 지도·브라우저 검사도 함께 수행한다. 시험용 적 실체 주입 경로는 배포 API와 분리한다.
- 정지/동일 자세의 기존 판정 기준은 유지한다. 실제 궤적과 사격 시각이 달라지는 이동 장면의 전투 결과 변화는 그 원인을 기록하고, 이전 seed의 모든 결과가 그대로여야 한다고 요구하지 않는다.
- 기존 관측·경계·임무 인계·공개 HP/잔해, WIP12 예광 연결/입자 우선순위·도탄 추가 피해 없음, WIP13 양방향 제동 중 방위 유지 회귀를 보존한다.

## 8. 완료 산출물

- 새 AI/정책/프로파일 필드를 단일 HTML 빌드·Node 로더·실제 Worker 구성에 맞게 연결한다. 오프라인 단일 HTML에서 누락된 모듈이나 외부 요청이 없어야 한다.
- 최종 빌드 뒤 기존 전체 Node 검사와 실제 브라우저·필요한 지형/소스 검증을 완료한다. 이미 통과한 범위를 매 문서 수정마다 무조건 반복하지 말고 마지막 구현 상태의 필요한 검증을 완결한다.
- AI 판단/명령·경로 요청·발사 정차 조건·경유점 진척을 재현 가능한 작은 기록으로 남긴다. 구현 문서에 상태 전이·실행 순서·프로파일/근사값·판단/경로 예산·한계를 적는다.
- 버전·실행 파일·문서는 WIP14로 맞추고 이전 릴리스를 보존한다. dist와 배포 HTML 일치, ZIP 단일 HTML·CRC·해제 바이트·체크섬, 반복 패키징 바이트 일치를 검사한다.
- 완료 보고에 기준/최종 commit, 실제 이동/정차/재개 사례, 검사 결과, 다수 차량 성능·경로 요청 수, 정보 공개 검증과 한계를 적고 검토 가능한 구현 PR을 준비한다.
- WIP14 지시서는 완료 시 archive/instructions에 원문을 보존하고 목차·진행 메모를 갱신한다. 구현 중에는 이 파일을 유일한 원본으로 사용한다. 실행하지 않은 검증을 통과로 적지 않는다.
