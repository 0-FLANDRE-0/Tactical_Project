# WIP21 — T-80U(1989) 모델·장갑 통합과 피격시험

> 2026-11-14 KST. **지시서 등록 / 구현·검증 대기.** 사용자 승인 범위: 수정한 T-80U 모델을 게임에 연결하고 장갑·피격 결과까지만 적용한다. ERA는 방호만 적용하며 폭발·소모·손상은 구현하지 않는다. 아래 최소 피격시험 구성은 이번 단계의 구현 범위다.

## 1. 시작점과 목표

- 저장소 `0-FLANDRE-0/Tactical_Project`. 작성 시 최신 main은 **`33294a5d77a1ba40fef7578e87e087f9cfb242f3`**이다. 작업 시작 시 main을 갱신하고 이 커밋의 수정 모델을 포함하는 새 작업 브랜치에서 구현한다. 후속 main 변경이 있으면 확인·통합하며 과거 변경을 다시 적용하지 않는다.
- WIP20 게임 시스템 위에 **`T80U_1989` 피격용 차량 프로파일 + T-80U 도안**을 추가한다. 기존 기본 전투는 유지하고, 배포 HTML에서 선택 가능한 **T-80U 방호시험 시나리오**를 제공한다.
- 시험에서는 M1A2(1998)가 기존 M829A2/M829A1/M830으로 정지한 T-80U를 사격한다. T-80U는 정상 관측·표적 지정·명중·도탄·관통·HP 감소·격파·잔해 처리에 참여한다. T-80U의 주포 발사, 이동 AI/기동 성능, 자동장전, 탄약고·승무원·장비 피해는 이번 범위가 아니다.
- 코드는 이번 최소 기능을 지원하는 만큼만 확장한다. 새 차량을 에이브람스 ID로 위장하거나 M1A2 프로파일 전체를 복사해 동작시키지 않는다. 지시서 자체를 구현 완료로 기록하지 않는다.

## 3. T-80U(1989) 장갑·HP 확정 적용값

단위는 게임용 mm RHAe, 표기는 **KE / CE**다. 장갑판 실측 두께가 아니다. 최대 HP **1,400**. ERA는 Kontakt-5 **KE +215 / CE +560**을 사용한다.

| 피격 구역 | 키 | 기본 KE / CE | 고정 피복률 | ERA 적용 시 KE / CE |
|---|---|---:|---:|---:|
| 차체 전면 | `hullFront` | 500 / 690 | 90% | 715 / 1250 |
| 차체 측면 | `hullSide` | 115 / 120 | 50% | 330 / 680 |
| 차체 후면 | `hullRear` | 40 / 40 | 0% | 40 / 40 |
| 포탑 전면 | `turretFront` | 575 / 740 | 95% | 790 / 1300 |
| 포탑 측면 | `turretSide` | 305 / 390 | 45% | 520 / 950 |
| 포탑 후면 | `turretRear` | 70 / 70 | 0% | 70 / 70 |
| 통합 상부 | `upper` | 45 / 45 | 45% | 260 / 605 |

- 후면 두 구역은 ERA 미장착 0%다. 상부는 별도의 45%를 사용하고 전면/측면 피복률을 상속하지 않는다. 상부 피격 기회는 기존 7구역 선택 규칙을 보존하고 새 상부공격 무기나 8번째 구역을 추가하지 않는다.
- 기본장갑과 ERA 보정·부위별 피복률을 **T80U_1989 프로파일의 분리된 데이터**로 둔다. 다른 차량이나 모든 장갑에 K5 보정을 전역 적용하지 않는다. 이번 미사용 T-80U(1985)와 다른 전차를 추가 등록하지 않는다.

## 4. 이번 ERA 방호 규칙

**장착 상태·피복률은 전투 내내 고정이다.** 실제 블록 좌표 충돌이 아니라 기존 확률식 피격 구역에 대한 한 번의 피복 판정이다.

1. 기존 경로로 명중 여부, 7구역/측면 방향, 입사각, 도탄을 확정한다. 빗나감과 도탄에는 ERA 피복 판정을 실행하지 않는다.
2. 도탄하지 않은 명중이고 해당 구역 피복률이 0보다 크면 `eraRoll < coverage`로 **한 번만** 판정한다. 0% 구역은 추가 난수 없이 기본장갑을 쓴다. 순수 검사에서는 피복률 1의 처리와 경계도 검증한다.
3. `최종 방호력 = 기본장갑[kind] + (피복 성공 ? K5 추가 방호[kind] : 0)`을 계산한다. KE/CE는 공격탄의 분류를 참조한다. 피복률을 방호력에 평균 가산하거나 모든 전면을 항상 K5 적용으로 처리하지 않는다.
4. 최종 방호력을 기존 관통 비교, 잔여 관통 비율/과관통 피해, 근접 비관통 피해의 입력으로 사용한다. ERA 적용 뒤 관통이 실패하면 기본장갑만으로 다시 관통시키지 않는다.
5. 피복 결과와 최종 방호력을 그 착탄의 고정 판정 결과에 남긴다. 중복 처리·조회·렌더·기억 사본 생성에서 재추첨하지 않는다. 매 피격 후 피복률 감소, 블록 손실, 지속 상태, 새 폭발/파편 피해·추가 도탄은 없다.

- 원래 장갑 경사는 대표 방호력에 포함돼 있다. **기존 탄약 입사각/도탄 경로를 유지**하며 방호력에 새 LOS/cos 배율을 추가해 경사를 이중 적용하지 않는다.
- 난수는 기존 시뮬레이션의 결정적 사건 ID/seed 방식에 새 독립 용도를 부여한다. 시간·렌더·조회 순서·`Math.random()`에 의존하지 않는다. ERA 없는 기존 M1A2 사건의 난수와 결과를 보존한다.
- M829A2/A1/M830의 관통표·초속·피해·도탄 규칙을 바꾸지 않는다. 기존 근접 비관통 HP 피해는 유지하되 **공격탄의 명시적 비활성(`M830`)을 우선**한다. T-80U가 장전수 상태를 갖지 않아도 계산돼야 한다. 필요한 A2의 기존 공통 근접 비관통 규칙은 장전/피로와 분리된 전투 규칙으로 참조한다(15mm 미만, 확률 0.30, 기존 0/5/10/15mm → 120/80/35/0 표). 이를 새로운 실차 피해 데이터로 표기하지 않는다. A1의 탄약별 규칙과 기존 M1A2 동작을 보존한다.
- 기존 일반 HP 피해와 표준 격파를 사용한다. T-80U에 WIP15 피로/피격 동요/사통 이상, WIP18 승무원 경중상/기능 이상, WIP20 탄약고 사고를 자동 적용하지 않는다. 기존 M1A2에는 각각의 정상 기능을 계속 적용한다.

## 5. 피격 전용 프로파일과 최소 생성 경로

현재 코드는 모든 차량에 완전한 구동·관측·사격 설정을 요구하고, `combat` 초기화도 발사용 탄약 ID를 요구한다. `makeTank`는 Observation/FireControl을 무조건 초기화하며 피격 후 반응도 장전 상태를 참조한다. **기존 검사 통과를 위해 T-80U에 M829A2/M256·42발·장전수·에이브람스 구동계를 넣는 방식은 금지한다.**

- 작은 명시적 능력 구분으로 **움직이지 않고 쏘지 않는 피격 차량**을 생성할 수 있게 한다. 필드/키 이름은 저장소 관례로 정하되 발사·이동·피격 가능 상태를 혼동하지 않는다. 피격 가능은 HP/장갑·모델/제시 높이·기본 위치를 검증하고, 사격 가능 차량에만 탄약·장전/사통의 필수 조건을 검증한다. 기존 활성 차량의 엄격한 검증을 전역으로 완화하지 않는다.
- T-80U 발사·이동·자동 교전은 비활성이다. UI 명령·자동 발사·AI probe·직접 API에서도 발사 번호/탄약/난수/비행체/경로를 만들지 않고 비활성 사유로 종료해야 한다. 단순 ‘보류’는 수동 발사를 허용하므로 발사 비활성의 대체가 아니다.
- 피격 표적이 공격자를 관측할 필요는 없다. 아군 M1A2 관측에 쓰이는 **표적으로서의** 크기·제시 높이/노출 표본과 표적 자체의 센서 능력을 분리한다. T-80U에 CITV·hunter-killer·2500m/90° 같은 M1A2 센서 성능을 부여하지 않는다.
- 사실 메타데이터를 둘 경우 승무원은 **3명(전차장·포수·조종수)**이며 장전수는 없다. 이번 피격 상태에 세 승무원의 부상·능률·자동장전 상태를 새로 만들지는 않는다.
- 피격 이벤트는 **공격탄 ID를 사건에서** 받아 계산한다. 피격 차량의 발사용 탄약을 요구하거나 그 ID를 공격탄으로 대신 쓰지 않는다. 공격탄 누락을 임의 M829A2로 메우지 않는다. 기존 레거시 테스트/경로가 있다면 호환 범위를 명시하고 실제 새 표적 경로에서는 누락을 거부한다.
- 필수 런타임 수치가 필요한 부분은 소스가 있는 외형 메타데이터를 사용하고, 미확인 높이·숨은 형상은 조정 가능한 **시험용 근사**로 별도 표시한다. 미구현 T-80U 성능을 M1A2와 동일하다고 발표하지 않는다. 이번에 125mm 탄약·자동장전·차량 성능 전체를 구현해 범위를 넓히지 않는다.

## 6. 도안·회전·월드 좌표와 관측 사본

- 기존 도안 소스를 재사용하는 게임용 어댑터/등록을 추가한다. 수정 모델의 주포 외경, 차체 전면 장갑판, 포탑 ERA 팬/지붕 배열과 엔진 덮개를 다시 임의 단순화하지 않는다. 별도 SVG를 다시 그려 Canvas와 달라지게 하지 않는다.
- 미리보기 API는 **도 단위/부모 기준 상대각**, 게임은 **라디안/월드 절대각**이다. 어댑터에서 `heading`, `turret-heading`, `commander-turret`를 변환해 전달한다. 큐폴라가 포탑 회전을 두 번 받거나 차체 중심 주위로 도는 오류를 막는다. 별도 게임용 기관총 방위가 없으면 추가 상대각은 0으로 고정하고 새 무기/사격을 만들지 않는다.
- `MODEL.hullOriginPx`, 각 pivot, `metresPerPixel`와 실제 모델 프레임으로부터 월드 기준점을 도출한다. 포탑의 원점·물리 회전축·포구 끝을 구분하고 M1A2의 전방 0.66m 피벗/포구 길이를 복사하지 않는다. `TacticalVehicleGeometry`와 어댑터가 같은 기준을 쓰도록 한다.
- 도안의 7.012m 길이 기반 **균일 축척**을 유지한다. 참고 전폭 3.628m와 도안 파생 전폭 약 3.610m의 차이는 기존 정렬 메타데이터대로 기록한다. 강제로 폭만 늘리거나 에이브람스 외곽 크기로 그리지 않는다. 차체 길이/폭과 주포 포함 전장을 구분한다.
- 선택 영역, 화면 밖 제거, 피격 표시 위치/기존 근사 제시 형상, 표적/잔해 충돌 범위는 해당 차량 크기를 사용한다. 기본 지도/베이크 길찾기를 전면 재생성하지 않는다. T-80U는 정지 표적이어도 기존 M1A2가 그 표적과 잔해를 통과하면 안 된다. 정밀 장갑 블록·포신 충돌은 추가하지 않는다.
- `app.js`의 현재 `enemy ? 'M1A2' : ...` 강제 도안 선택과 차량 레지스트리의 단일 `artId` 허용을 확장한다. **게임 실행 HTML에 실제 T-80U Canvas 도안이 포함**돼야 한다. 비교용 원본 도면·실차 사진은 게임 빌드에 넣지 않는다.
- 현재 접촉·공유 접촉·기억·잔해 사본에 필요한 도안 식별자/모델 정보를 관측 시점에 보존한다. 미관측 적 실제 객체를 매 프레임 조회해 외형·방향·HP를 갱신하지 않는다. 재관측 때만 정상 갱신한다.
- 미식별 표적은 기존 정책대로 일반 실루엣/문구를 사용하고 차종·장갑/ERA 프로파일을 식별 전 노출하지 않는다. 식별 뒤 T-80U 외형/차종을 표시한다. 기억/관측 확정 잔해에서 M1A2 그림으로 바뀌지 않아야 한다. 기억의 포탑·전차장 방위도 고정한다.
- 같은 사건의 ERA roll/적 내부 상태를 공개 발사체·효과·접촉 사본에 통째로 퍼뜨리지 않는다. 장갑 판정 상세는 비공개 검증 로그에서 확인하고 기존 HP·격파 공개 조건을 보존한다. 미관측 격파가 즉시 확인 잔해를 만들지 않는다.

## 7. 배포 HTML에서 실행 가능한 방호시험

- 우측 기존 명령 영역에 작은 시나리오 선택 등 최소 진입 수단을 제공한다: **기본 전투 / T-80U 방호시험**. 콘솔/개발 서버 전용 fixture로만 끝내지 않는다. 새 대형 설정 패널·차종 편집기는 만들지 않는다.
- 기본 전투는 기존 M1A2 대 M1A2 구성이다. 방호시험은 아군 M1A2(1998)와 고정된 T-80U 표적들로, 관측·실제 발사선이 확보되는 검증된 위치에 배치한다. 전면/측면/후면을 볼 수 있는 자세와 차체·포탑 방위가 다른 사례를 포함한다. 무작위로 건물/수면에 배치하지 않는다.
- T-80U는 위치·시험용 방위를 유지하고 순찰·교전 임무·이동/발사 상태를 만들지 않는다. 순수 검증용 자세 주입과 실제 게임 관측/사격 경로를 구분한다. 정상 게임 전투에서는 기존 확률 판정이 그대로 적용된다.
- 플레이어는 기존 표적 지정/자동·보류/탄종 선택으로 M829A2/A1/M830을 발사할 수 있다. 시험을 쉽게 하려고 조준·시야·관통을 무조건 성공시키거나 실제 전투의 탄약을 무한 생성하지 않는다.
- 시나리오 전환/재시작은 해당 시나리오를 새로 초기화한다. 관측/Worker 응답 토큰, 선택/명령, AI·피격 기록, 비행체·효과, HP와 고정 피복률을 함께 정리해 이전 표적 정보가 섞이지 않게 한다. 일시정지/배속도 기존 규칙을 따른다.
- T-80U는 부상/장전·탄약고·ERA 소모 UI를 새로 표시하지 않는다. 기존 아군 정보와 정상 표적 관측 정보를 사용한다. 피격/도탄은 기존 결과 기반 효과를 재사용하며 ERA 블록 폭발·탈락 애니메이션은 없다.

## 8. 반드시 검증할 사례

| 장갑 계산 | KE/CE 각각 피복 성공/실패, 후면 0%, 상부 45%, `roll==coverage` 실패와 0/1 경계, ERA 한 번만 가산, 새 LOS 배율 없음 |
| 실제 방호 사례 | M829A2 2km/0° KE635 대 차체 전면은 피복 실패 시 500으로 관통, 성공 시 715로 비관통. 포탑 전면은 575/790으로 같은 차이. M830 CE480 대 차체 측면은 120으로 관통/680으로 비관통. 강제 roll 검증과 seed 기반 실제 사격 사례를 구분 |
| 피해와 사건 | 도탄·빗나감 ERA 무판정, 최종 방호력 기준 정상/근접 비관통/과관통 피해, M830 근접 비관통 비활성, HP0 표준 격파 한 번, 중복 ID/동시 착탄/비행 중 사수 격파, 반복 피격 뒤에도 장갑/피복률/도안 동일 |

| 도안/좌표 | 차체·포탑·큐폴라 0/±90/180°와 복합 회전, 게임 라디안 변환, 원점·피벗·포구 일치, 차체/포탑 독립 방호 방향. 주포를 옆으로 돌려 차체 전면 ERA가 아래까지 이어지는지 확인. 정면과 복합 자세를 같은 축척 원본과 대조해 스크린샷 제출 |
| 공개 사본 | 미식별→식별→상실/기억→재관측→관측 확정 잔해의 외형/문구, 기억 고정, 최신 관측 HP 병합 보존, 미관측 격파/ERA 결과·roll/프로파일 ID를 통한 정보 누설 없음 |
| 게임/회귀 | 실제 배포 HTML에서 시나리오 선택과 3종 탄 발사→피격→HP/격파, reset/전환/선택/명령/일시정지, 기본 M1A2 전투·관측·AI·WIP15/18/19/20 기존 동작 보존 |

- ERA 없는 기존 전투 fixture는 같은 seed/사건 입력에서 기존 판정·난수·재고와 일치시킨다. T-80U가 들어간 새 전투 전체가 기존과 같다고 주장하지 않는다.
- 기존 전체 Node/Python 및 실제 Chromium 검사를 실행하고, 독립 LOS·내장 Worker·WIP17 합성 지도 로더에서 새 프로파일/도안 의존성 누락을 확인한다. 기존 검사를 삭제하거나 M1A2 검증을 완화해 통과시키지 않는다. 단독 모델의 회전·원본 대조 검사도 유지한다.
- 실제 Chromium은 데스크톱과 모바일 가로(844×390, DPR1/2), 세로 차단/복원을 확인한다. 새 시나리오에서 실제 T-80U 그림을 캡처한다. Node 통과나 미리보기만으로 게임 내 연결 완료를 보고하지 않는다.
- 같은 장면/장비에서 기본 전투 기준/신규와 방호시험의 틱·렌더 중앙값/P95를 비교한다. ERA는 피격 시 상수 비용이며 추가 매 프레임 LOS/장갑 블록 추적을 넣지 않는다. Path2D/도형 경로를 재사용하고 선택/관측 사본 변경 때만 필요한 정보를 갱신한다. 정지 표적 때문에 M1A2 기존 동작 비용이 증가하지 않는지도 본다.
