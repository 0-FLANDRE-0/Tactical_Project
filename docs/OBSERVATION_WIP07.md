# WIP07 관측 구현 상태

기준은 main `5eea28cf80deaa1ffdf9494090d3e2e3f621e636` (v0.4 WIP06)이다. 작업 시작 시 원격 main과 일치했고 로컬 변경은 없었다. 적용되는 AGENTS.md는 없었다. 지도·차량 반경·길찾기 계약은 유지했다. 첨부 검토안 원문은 [TACTICAL_OBSERVATION_IMPLEMENTATION_PLAN.md](TACTICAL_OBSERVATION_IMPLEMENTATION_PLAN.md)에 보존했다.

WIP07은 독립 선회 → 방향별 관측 → 탐지/식별 → 실루엣/기억 → 경계 명령 → 지정 전달 → 포수 자체 확보까지 연결한다. 사격·탄도·관통·피해·재장전·고각은 후속 범위다. 수치와 확률은 게임 규칙이며 실제 장비의 성능 추정이나 검증값이 아니다.

## 소유자와 갱신

- `vehicle-profiles.js`: 거리·전체 시야각·높이·선회속도·장비 기능·시간/임계값.
- `sim-core.js`: 기동과 별개로 양 진영의 실제 관측/선회를 실행한다. 정지·기동 도착 조기 반환에도 관측은 계속된다. 포수 실제 방위는 `u.turret`, 전차장 실제 방위는 `u.commander`다.
- `observation.js`: 차량별 명령·접촉·지식·인계 상태. 시나리오별 runtime은 WeakMap으로 분리하며 새 시나리오에 이전 기록을 재사용하지 않는다.
- `app.js`: 준비된 팀 접촉의 분리된 사본만으로 적 표시·축소 마커·클릭·패널을 구성한다. draw/패널은 정밀 LOS를 조회하지 않는다. 개발 snapshot에서도 적의 원본 ID·내부 focus/cooldown 키를 제거했다.
- `m1a2-art.js`: 실제 포탑/전차장 방위를 그린다. CITV 머리는 기존 위치를 유지하는 별도 회전 레이어다. 실루엣은 동일 도안의 채움 경로를 검게 그리고 내부 선/재질/그림자를 생략한다.
- `look-animation.js`: 실제 각도를 읽는 호환 어댑터만 남겼다. 별도 연출 시계·포탑 덮어쓰기가 없으며 모션 줄이기는 관측을 바꾸지 않는다.

실제 선회·명령·확률·기억은 0.05초 시뮬레이션 스텝을 따른다. 렌더 FPS, 배속의 프레임 묶음, 카메라, 선택, UI 조회는 난수를 소비하지 않는다. seed 기본값은 7이며 `createScenario(seed)`로 바꾼다. 관측 차량/표적/단계별 해시로 고정 임계값을 생성한다.

## 게임 초깃값

`M1A2.sensors`에서 조절한다. 단위는 m, s, rad, rad/s다.

| 필드 | 초깃값 | 의미 |
|---|---:|---|
| ambient | 200m / 360° / 2.65m | 해당 채널만으로는 식별 불가 |
| commander | 2500m / 90° / 50°/s / 2.65m | 장비 활성·독립 선회 플래그 분리 |
| gunner | 2000m / 60° / 40°/s / 2.65m | 실제 포탑 방위 사용; 기동 프로파일의 40°/s 상한도 적용 |
| hunterKiller | true | 독립 전차장 시야와 별도 플래그 |
| queryPeriod | 0.1s | 20Hz에서 차량별 두 집단으로 분산하는 10Hz 후보/관측 갱신 |
| geometryMaxAge | 0.5s | 정확히 같은 광선만 제한적으로 재사용 |
| detectThreshold | 0.35~1.1 품질·초 | seed별 탐지 임계값 |
| identifyThreshold | 1.4~3.0 품질·초 | seed별 식별 임계값 |
| evidenceHalfLife | 8s | 유효 관측 상실 중 누적 효과 반감기 |
| memorySeconds | 30s | 마지막 위치/자세의 표시 유지 |
| knowledgeSeconds | 120s | 마지막 확인 후 식별 지식 유지 |
| focusSeconds / focusLimit | 2s / 8s | 최소 집중 확인 / 한 접촉 최대 확인 |
| lossGrace | 1.2s | 짧은 접촉/포수 관측 상실 유예 |
| revisitSeconds | 12s | 자동 확인·인계 재시도 유예 |
| designationSeconds / designationStale | 18s / 6s | 미확보 지정 대기 한도 / 오래된 마지막 위치 취소 |
| acquireSeconds | 0.4s | 포수 자신의 연속 유효 관측 요구 |

추가 수색 초깃값: 전차장 넓은 수색 중심 0.24rad/s, 포수 ±0.55rad의 0.24rad/s 위상 수색. 차량 ID/채널/seed별 위상이 다르다. 마지막 플레이어 관심 지점은 명시 해제/시간 만료 후 8초간 자동 수색 중심으로 재사용한다. 명시 인계 취소의 기본 재지정 유예는 12초다. 이 값들도 실제 장비 측정값이 아니다.

`profileOf(u)`는 기본 `profileId` 외에 `profileOverride`를 받는다. 예: `u.profileOverride=structuredClone(C.PROFILE); u.profileOverride.sensors.hunterKiller=false;`. 차량마다 commander.enabled, commander.independent, hunterKiller를 따로 설정할 수 있다. 포탑 연동 장비는 전차장 각도를 포탑에 맞추며 독립 전차장 지점 명령은 거절한다. 포수 지점 경계와 직접 지정은 유지한다. 내보내는 `data/vehicles/M1A2.json`에도 모든 센서 필드와 게임 설정 근거가 들어간다.

## 탐지·기억·정보 공개

관측 후보는 500m 공간 버킷, 거리, 각도로 줄인 후 기존 차체 6개·포탑 3개 표본의 정확한 지형/건물/숲 LOS를 조회한다. 표적 중심이 경계 밖이어도 차체 반경 여유를 두고 실제 표본을 확인한다. 포탑 표본은 실제 포탑 각도를 사용한다.

각 표본 품질은 중심 가중치 `0.2+0.8*cos(정규화 각도*pi/2)^2`, 거리 가중치 `1-0.6*(거리/상한)^2`, 숲 가중치 `exp(-1.5*광학깊이)`의 곱이다. 안 보이는 표본은 0이다. 모든 표본 평균에서 채널 간 최댓값을 취해 탐지를, 전차장/포수 중 최댓값으로 식별을 누적한다. 채널 중첩으로 시간을 중복 적립하지 않는다. 초기 미측정 시간은 적립하지 않고 매 조회의 적립 시간을 최대 queryPeriod로 제한한다.

| 상태 | 공개 |
|---|---|
| 미탐지 | 목록·지도·클릭에 없음 |
| 탐지, 미식별 | 검은 차체/포탑/포신 외곽, 일반 마커, ‘미식별 표적’만 공개. 실제 ID·차종·이름·노출률 비공개 |
| 식별, 현재 관측 | 정상 외형·확인한 이름/차종·현재 관측 표본 비율 |
| 상실, 기억 유지 | 마지막 관측 위치/차체·포탑·전차장 자세의 흐린 사본. 노출률 숨김. 숨은 실제 표적을 따라가지 않음 |
| 30s 기억 만료 | 지도·선택·패널 제거. 식별 지식은 별도 유지 |

개별 차량 지식과 팀 표시를 구분한다. 팀은 현재 관측 유무와 가장 최근 관측 자세/확인한 식별 지식을 합친다. 다른 아군이 안다는 이유로 자기 포수가 확보한 것으로 처리하지 않는다. 재관측은 남아 있는 효과/지식을 사용하며 짧은 차폐 때문에 처음부터 식별을 반복하지 않는다.

## 경계와 인계

전차장/포수를 고르고 ‘지점 경계’(L)로 월드 좌표를 지정한다. 기본은 해제까지, 선택 사항으로 5/10/30초다. 이동하면 그 점으로의 방위를 다시 계산한다. 지정 지점은 자동 접촉 확인과 자동 인계보다 우선한다. ‘자동 경계’로 해당 장비 명령을 해제한다. Esc·선택 변경·드래그/핀치·포커스 상실은 새 입력만 취소하며 이미 실행한 명령은 지우지 않는다.

자동 수색의 제어 경로는 이미 탐지한 접촉 사본과 마지막 위치, 플레이어 관심 지점만 읽는다. 미발견 적 좌표는 후보/LOS 판정에만 쓰며 수색 방향을 정하지 않는다. 집중 최소 시간·상실 유예·재방문 유예로 접촉 전환을 제한한다.

헌터킬러 흐름은 전차장 탐지 → 중앙 집중 → 식별 → `designated` → 실제 포탑 선회 → `waiting/acquiring` → 포수 자체 0.4초 관측 후 `acquired`다. 식별 지식은 전달하며 포수에게 같은 식별 임계값을 다시 요구하지 않는다. 거리/각도/LOS는 포수 채널로 재확인한다. 2000~2500m에서는 거리 밖 대기를 표시한다. 대기는 18초 또는 관측 정보가 6초 이상 오래되면 만료한다. 취소 버튼도 있다.

확보 상태는 유효 관측을 유지하는 동안 지속한다. 전차장은 자동 경계라면 재수색한다. 자동 인계는 최소 2초 확보 후 다른 식별 접촉을 받을 수 있다. 직접 지정은 다른 자동 접촉으로 교체하지 않는다. 포수 관측을 1.2초 넘게 놓치면 다시 유한 대기로 전환한다. 전차장 관측만으로 포수 상실 유예를 연장하지 않는다.

## 캐시와 표시용 마스크

높이가 같은 채널은 같은 조회 안에서 부위 LOS를 공유한다. 추가로 정적 지도에서 관측점 x/y·eye와 표본 x/y/z가 정확히 같을 때만 광선을 최대 0.5초 재사용한다. 차량 이동/차체·포탑 회전으로 표본이 바뀌면 해당 광선을 즉시 갱신한다. 관측 각도/거리는 매 10Hz 조회에서 현재 실제 방위로 다시 계산한다. TTL이 지나면 정밀 LOS를 재조회한다. 단순히 이전 visible 결과만으로 이동한 차량의 관측 시간을 쌓지 않는다.

홀드 마스크는 선택 전차 하나의 지면 위 1.5m 지형 가능 영역이다. 전체 마스크는 같은 위치에서 재사용하고 현재 주변 원·전차장/포수 부채꼴을 합성한다. 모든 차량에 전체 영역 계산을 반복하지 않는다. 4000m는 기하 계산 상한이며, 비활성 3000m 주포 메타데이터가 2000m 포수 범위를 바꾸지 않는다. Worker 취소/선택·초기화 revision 검사는 유지했다.

## 검증과 한계

현재 실행 결과와 HTML 크기·SHA-256은 [릴리스 노트](../TACTICAL_RELEASE_WIP07.md), 기계 기록은 `tests/releases/WIP07-validation.json`을 본다. 순수 관측 검사는 합성 LOS를 주입하고, `observation-core.test.cjs`는 실제 코어/아홉 표본/실제 지도와 평지 fixture를 함께 검사한다. 입력 검사는 가짜 DOM/렌더러다. browser 검사는 실제 Chromium DOM/Canvas/내장 Worker다. 둘을 같은 검사로 취급하지 않는다.

`scripts/benchmark_observation.cjs`는 실제 지도·양 진영 정지 격자·seed 407·20스텝 준비 후 100스텝을 측정한다. 좌표·조건·CPU 시간·정밀 광선/캐시 횟수는 `tests/releases/WIP07-benchmark.json`에 남긴다. 이전 매 프레임 표시 루프 수치와 직접 비교하거나 FPS로 바꾸지 않는다. 이동이 많으면 캐시 적중률이 낮아진다. 실제 Android 터치/발열/지속 성능·원본 DEM/GDAL 대조는 이번에 실행하지 않았다. 이 환경 Chromium은 file://를 정책으로 차단하므로 HTTP로 같은 단일 HTML을 제공해 검사했다. 파일 더블클릭 경로는 미검증이다.
