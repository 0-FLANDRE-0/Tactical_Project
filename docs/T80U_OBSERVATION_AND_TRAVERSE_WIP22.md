# WIP22 T-80U(1989) 자체 관측·인계·선회

WIP22는 WIP21의 `T80U_1989` 모델·장갑·HP·Kontakt-5 프로파일을 그대로 확장해, 기동·발사·교전 AI 없이 정지 차량의 자체 관측만 실행한다. 새 `T-80U 관측시험`에서 차체 위치와 방위는 고정되고 `u.commander`와 `u.turret`만 고정 0.05초 시뮬레이션 틱에서 변한다.

## 적용 데이터

| 항목 | 값 | 근거 성격 |
|---|---:|---|
| 포탑 최대 선회 | 24°/s | Tankograd 해당 T-80U 기술의 2차 자료 채택값 |
| 전차장 큐폴라 최대 선회 | 40°/s | PNK-4S 모터 최대 속도에 대한 2차 자료 채택값 |
| 전차장 | 2,000m, 전체 FOV 90°, 높이 2.50m | 주간 게임 시험값 |
| 포수 | 2,000m, 전체 FOV 30°, 높이 2.15m | 주간 게임 시험값 |
| 주변 인지 | 200m, 360°, 실루엣까지 | 공통 RTS 게임 규칙 |
| 전차장 탐색 | 차체 기준 ±180°, 90초, 12°/s | 게임 시험값 |
| 포수 탐색 | 차체 기준 ±30°, 24초, 8°/s | 게임 시험값 |
| 자동 인계 대기 / 포수 확보 | 0.50초 / 0.40초 | 게임 절차 시험값 |

24/40°/s는 [관측 자료 노트](../data/vehicles/references/t80u/observation_reference_notes.md)에 정리한 2차 자료의 채택 상한이다. 원 교범이나 실기기 측정으로 독립 검증하지 않았다. 나머지 거리·FOV·높이·탐색·시간은 실제 광학계 제원으로 표기하지 않는 조정 가능한 게임 값이다. 야간·열상·날씨·배율은 범위에 없다.

## 구조

- `src/vehicle-profiles.js`는 `target=true, observation=true, mobility=false, fire=false, ai=false`를 다른 기능 검증을 우회하지 않고 정상 표현한다. 관측 채널·선회·탐색·절차 필드를 별도 검증하고, 기존 M1A2 전체 운용 필드 검증은 유지한다.
- T-80U의 포탑·큐폴라 상한은 관측 프로파일의 `gunner.rate`, `commander.rate`에 소유된다. `Observation.control()`은 기동 프로파일이 있는 M1A2에서 기존 `mobility.turretRate`와 관측 상한을 함께 적용하고, 관측 전용 T-80U는 가짜 엔진·변속기 없이 센서 상한만 쓴다.
- `hunterKiller` 호환 필드와 `commanderDesignation`을 분리했다. M1A2는 새 필드가 없으면 기존 `hunterKiller` 값을 그대로 해석해 기존 동작을 유지한다. T-80U는 `hunterKiller=false`, `commanderDesignation=true`를 명시해 CITV 복사 없이 전차장 표적 지시만 허용한다.
- T-80U의 전차장 자체 현재 식별은 후보별 `eligibleSince`로 0.50초 연속 자격을 추적한다. 상실·식별 해제·확정 잔해면 후보를 제거해 재발견 때 대기를 새로 시작한다. M1A2의 지연0초, 플레이어 직접 지정, AI 소유권, 포수 자체 발견은 지연하지 않는다.
- 지정 접수와 포수 확보는 별도 상태다. 포수 현재 채널이 사거리·FOV·LOS를 만족한 상태로 0.40초 누적해야 `acquired`가 된다.
- 시나리오 차량은 프로파일이 `true`로 선언한 기능만 개별 마스크로 끈 수 있다. `false`인 기동·발사·AI를 마스크로 켜려 하면 생성 단계에서 거부한다. WIP21 방호시험은 `observation:false`를 사용해 상태 생성과 선회를 모두 막는다.
- 관측 전용 차량의 직접 지정은 AI 수동 변경 함수를 호출하지 않고, 추적 표적 격파 정리는 발사 기능이 있을 때만 fire-control을 취소한다. 정지 T-80U에 `drive`, `fireControl`, AI, 탄약·장전·부상·일시 이상·탄약고 상태는 생기지 않는다.

## 정상 흐름과 공개 경계

seed 7의 라스도르프 실제 지형 시나리오에서 M1A2는 T-80U 초기 시야 밖에서 시작한다. T-80U는 약 40.45초 전차장 탐지, 46.95초 전차장 식별, 47.50초 인계, 실제 포탑 선회 뒤 53.90초 포수 확보로 진행한다. 시각 시점은 고정 seed의 현재 조정값 재현 값이며 실제 승무원 반응시간을 뜻하지 않는다.

추적 제어는 접촉의 마지막 유효 `pose`만 사용한다. 시야를 잃은 표적의 실제 좌표·방위를 숨은 상태에서 따라가지 않는다. 아군 공개 사본은 접촉의 마지막 관측 자세만 포함하고, 적 T-80U의 시야 원뿔·후보·인계·확보 내부 상태는 정상 UI/스냅샷에 포함하지 않는다. 일시정지에서는 방위·증거·대기시간이 모두 멈추고, 렌더·패널·시야 오버레이 조회는 관측 query를 증가시키지 않는다.

## 검증과 성능

- `tests/wip22-t80u-observation.test.cjs`: 프로파일/마스크, 선회 상한, 실제 지형 자체 탐지→인계→확보, 주변 실루엣 제한, 기억 자세, 격파 정지, seed/배칭/조회 결정성을 검사한다.
- `tests/wip22-browser.test.cjs`: 실제 단일 HTML의 3개 시나리오, 최초 보류, 탐색·인계·선회·확보, 일시정지, 기억, reset, 적 내부 비공개, 1440×900·844×390 DPR1/2·390×844를 검사하고 화면 증거를 남긴다.
- `tests/releases/WIP22-observation-performance.json`: WIP21 기준과 WIP22 기본/방호시험의 0.05초 스텝 CPU, query/ray, 공개 상태 해시와 실제 지형의 합성 관측자 50/100대 탐색/추적 비용을 분리한다. 기본과 방호시험의 trial별 상태 해시·query·ray는 기준과 일치했다.
- `tests/releases/WIP22-browser-performance.json`: 실제 Chromium 1440×900 DPR1의 시뮬레이션+캔버스+DOM 프레임 CPU를 기준/현재 기본·방호시험과 새 관측시험으로 분리한다. 헤드리스 서버 하드웨어의 CPU 시간이며 실기기 FPS·발열 증거가 아니다.

실제 명령·수치·통과/미실행 내역과 배포물 체크섬은 [WIP22 릴리스 문서](../TACTICAL_RELEASE_WIP22.md)와 `tests/releases/WIP22-validation.json`에 있다.
