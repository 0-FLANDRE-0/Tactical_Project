# WIP20 M1A2(1998) 탄약고 사고 구현

## 적용 범위와 데이터 소유권

WIP20 탄약고 사고는 `M1A2_1998.ammoIncidents`에서만 명시적으로 활성화된다. 공통 `M1A2`, 비활성 fixture, 다른 차량·무기와 아카이브의 1989년 96개 적재 프리셋에는 자동 적용하지 않는다. 공통 코드는 설정 검증, 결정적 추첨, 재고 전이와 사건 처리만 제공한다.

활성 프로파일은 피해 차량 ID, M829A2/A1/M830 공격탄 정책 ID, 저장 탄종 반응값, 세 재고 구획 용량, 7개 피격 구역 행과 결과 합계를 로드 단계에서 검증한다. 활성/명시적 비활성/설정 부재를 구분하고 잘못된 ID·NaN·음수·누락·합계 오류를 조용히 기본값으로 대체하지 않는다. 내보낸 레지스트리는 schema v9이며 차량·탄약 JSON에 WIP20 출처와 한계를 기록한다.

아래 구획 분포, 공격탄 기본 확률, 위험 전달 계수, 조건부 결과와 시간은 전부 조정 가능한 게임 시험값이다. 실제 M1A2 탄약 배치·관통 경로·방출판·생존율을 재현하거나 인증하지 않는다.

## 판정 순서와 결정성

사고는 실제 착탄 처리에서 다음 순서로 한 번만 실행한다.

1. 기존 명중·피격 구역·도탄·관통·일반 HP 피해를 계산한다.
2. 일반 피해 뒤 생존한 `M1A2_1998`의 기존 WIP18 반응을 계산한다.
3. 실제 관통·비도탄일 때만 사고 구획, 발생 여부, 결과를 추첨한다.
4. FireControl이 사건 직전 저장/예약/약실 스냅샷에 재고 손실과 안전 중단을 원자적으로 적용한다.
5. 최종 레코드로 기존 WIP15 반응, 공개 HP와 표준 격파/잔해 경로를 한 번 실행한다.

빗나감, 비관통, 근접 비관통, 도탄, 중복 착탄, 이미 격파된 표적과 일반 HP 피해로 이번에 격파된 표적은 사고 대상이 아니다. 과관통은 현재 모델의 관통 성공과 같은 자격을 갖는다. 기존 명중·구역·도탄·WIP15·WIP18 난수는 바꾸지 않았고, 사고 난수는 `seed + impactId + victimId + wip20 단계 키`로 구획/발생/결과를 분리한다. 렌더, UI 조회, Worker 완료와 프레임 묶음은 난수를 소비하지 않는다.

발생 확률은 `공격탄 기본 확률 × 선택 구획 잔존 적재율 × 저장탄 반응 계수 × 위험 전달 계수`다. 이번 M1A2 시험값은 공격탄 A2/A1/M830 0.30/0.30/0.40, 저장탄 반응은 세 탄 모두 1, 전달 계수는 ready/semiReady/reserve 0.50/0.65/0.80이다. 구획과 결과는 표 순서의 반열린 누적 구간으로 선택한다. `none` 또는 소유 탄 0인 구획은 다른 구획으로 재추첨하지 않는다.

## 실제 재고 소유와 세 결과

준비·장전·보충 예약탄은 작업 완료 전까지 원구획 소유다. 사고 스냅샷은 사용 가능한 저장탄에 해당 구획의 유효 예약탄을 더하고 약실 탄은 분리한다. 부분 소실은 `ceil(소유 탄 × 25%)`, 최소 1발이며 탄종 구성 비례의 Hamilton 배분을 사용한다. 버림 뒤 남은 발은 소수부 큰 순서, 동률은 프로파일 지원 탄종 순서로 배분한다. 같은 탄종에서는 저장탄을 먼저 줄이고 부족한 몫에만 같은 구획 예약탄과 작업 토큰을 없앤다.

- `ammoLoss`: 선택 구획 소유 탄의 25%를 올림해 소실한다. 추가 HP·사격 중단은 없다.
- `isolatedFire`: 선택 구획 소유 탄 전부를 소실하고 `max(기존 until, now + 8초)` 안전 중단을 적용한다. 추가 HP·승무원 피해·시간당 피해는 없다.
- `fatal`: 약실, 세 저장 구획과 모든 예약탄을 반환 없이 사건 손실로 정리한다. 일반 피해 뒤 남은 HP만 `incidentDamage`로 기록하고 표준 격파/잔해 콜백을 한 번 실행한다.

내부 기록은 `normalDamage`, `incidentDamage`, 합계 `damage`를 분리하고 `hpBefore - hpAfter = damage`를 유지한다. 여러 착탄은 기존 `impactAt/ID` 순서와 매번 최신 재고를 사용한다. 이미 비행 중인 탄은 사수의 치명 사고와 무관하게 발사 시 동결 데이터로 정상 착탄한다. reset은 42발, A2 장전, 자동 선호와 빈 사고 이력으로 새 상태를 만든다.

## 안전 중단·AI·UI

`ammo-safety`는 발사 직전까지 검사한다. 기간 동안 수동/자동 발사와 WIP16 무발사 probe는 탄약·발사 번호·판정 난수·비행체·효과를 만들지 않는다. 유효 준비/장전/보충 작업은 예약과 진행률을 보존한 채 `ammo-safety` 사유로 멈추고, 만료 뒤 같은 상태에서 재개한다. 이동·관측·지정·포탑 선회와 조준 누적은 유지한다. 시뮬레이션 일시정지는 사건 시간도 멈춘다.

장전탄, 유효 장전 작업 또는 사용 가능한 선호탄이 남아 있으면 안전 기간을 탄약 소진으로 취급하지 않는다. `halt` AI는 같은 실제 표적, 정차 상태와 원래 임무/경유점을 유지하고 만료 뒤 사격을 재개한다. 사고로 실제 총탄이 0이 된 경우만 기존 소진 경로로 임무에 한 번 복귀한다. 자동/보류 모드는 사고가 바꾸지 않는다.

선택 아군 패널은 활성 안전 중단, 최근 사고 시각·구획·탄종별 손실과 작업 중단 사유를 표시한다. 지도 위 아군 상태는 활성 중 `탄약고 화재 대응 Ns`를 최대 두 줄 우선순위 안에 넣는다. 승무원 상태는 계속 우측 선택 정보에만 표시한다.

## 효과와 공개 경계

확정 사건은 사고 시점의 고정 월드 좌표에 작은 반응, 짧은 화염/연기 또는 치명 폭발 효과를 추가한다. 효과는 기존 384 입자 예산과 핵심 입자 보호를 사용하며 추가 피해·연쇄 사건을 만들지 않는다. 미관측 적 사고의 짧은 물리 효과는 보일 수 있지만 차량을 따라가지 않는다.

공개 효과에는 고정 좌표, 시각, 일반화한 효과 등급과 시각 seed만 있다. 실제 표적 ID, 구획, 탄종, 잔탄, 작업, 확률·roll과 내부 결과 레코드는 넣지 않는다. 관측 착탄의 공개 combat 레코드도 `publicRecord`로 다시 축소한다. 사고 효과만으로 접촉·격파·잔해를 생성하지 않으며 기존 관측 HP 기억과 잔해 재발견 규칙을 유지한다.

## 성능과 검증 범위

사고가 없을 때는 차량별 작은 상태/시간 조회만 추가하고, 사고 시 세 구획×세 탄종의 고정 크기 처리를 수행한다. 추가 LOS, 적 전체 쌍 검사나 렌더 단계 판정은 없다.

Node 24.22.1 / AMD EPYC 9V74 환경의 100대 활성 사고 상태는 한 0.05초 상태 갱신 중앙값 0.0722ms·P95 0.2096ms, 분리된 view/상태 문구 조회는 0.4618/0.9569ms였다. 사고 효과 100건 입력은 중앙값 0.1695ms·P95 0.4766ms였고 384개 예산에서 핵심 입자 손실 0, 부가 입자 266개만 줄였다.

Chromium 156, 1440×900의 실제 프레임 콜백 측정은 기본 WIP19/WIP20이 각각 중앙값 0.9/0.9ms, P95 3.5/3.5ms였다. WIP20 100대 비활성은 4.0/6.1ms, 활성은 4.1/5.7ms였다. 시뮬레이션·Canvas·예약 DOM 갱신을 합친 headless 데스크톱 측정이며 전체 FPS나 물리 모바일 성능 보장이 아니다. 원자료는 `tests/releases/WIP20-performance.json`과 `WIP20-browser-performance.json`이다.

핵심 검증은 설정/수학 경계, 실제 저장·예약 소유, 부분/전부/치명 손실, 중복/동시 착탄, 비행 중 사수 격파, 조준 유지와 작업 동결, AI 임무 유지, reset, 공개 레코드/고정 효과와 실제 seed 134 브라우저 사건을 포함한다. 전체 결과와 배포 체크섬은 [WIP20 릴리스 문서](../TACTICAL_RELEASE_WIP20.md)에 있다.

## 제외

일반 엔진/연료 화재, 연속 화염 피해, 영구 모듈 HP·파괴·수리, 승무원 사망·치료·교대, 연쇄 유폭·주변 유닛 피해, 외부 재보급·강제 탈탄·전투 전 적재 편집, 자동장전 차량, 새 차종·무기·지도는 포함하지 않았다.
