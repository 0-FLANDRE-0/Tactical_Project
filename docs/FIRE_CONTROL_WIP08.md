## 차량 데이터의 소유권

`src/vehicle-profiles.js`의 `VEHICLE_PROFILES.registry`가 등록 ID를 관리한다. `ids()`, `list()`, `has(id)`, `get(id)`, `create(entries)`를 제공한다. 입력을 재귀 복사하고 각 프로파일을 깊게 동결한다. 중복·잘못된 ID, 미지원 도안, 누락된 필수 섹션, 범위 밖 확률과 시간은 거부한다. 알 수 없는 차량을 M1A2로 조용히 바꾸지 않는다.

현재 등록은 **M1A2 하나**다. `makeTank(..., team, profileId)`로 차량별 설정을 고른다. `profileId`와 `artId`를 분리했으며, 현재 지원 도안은 M1A2뿐이다. 같은 도안을 쓰는 시험 프로파일도 센서·조준 시간·시험탄을 독립적으로 가진다. 매 차량의 조준/탄수/발사 횟수는 `u.fireControl`에 있고 공유 프로파일에 기록하지 않는다. UI 제원도 선택한 차량의 프로파일에서 읽는다. `profileOverride`는 기존 합성 fixture용 통로이며 일반 차량 등록 방식이 아니다.

`data/vehicles/registry.json`은 등록 목록, `M1A2.json`은 적용값과 근거다. `node scripts/export_vehicle_profile.cjs`로 내보낸다. 현재 길찾기는 기존 M1A2 반경 4.62m/16m 격자 계약을 보존한다. 다른 크기 차체를 추가할 때는 그 차량의 이동·길찾기 계약을 별도로 준비해야 하며, 이번 레지스트리만으로 임의 차체 크기 지원까지 완료한 것은 아니다.

## 상태와 명령

1. 전차장 인계·포수 자체 추적·플레이어 직접 지정으로 표적을 정한다.
2. 선택 차량의 **포수 자체 확보**를 기다린다. 팀 식별이나 전차장 식별만으로 이 단계를 건너뛰지 않는다.
3. 실제 포탑이 표적 방향 허용 오차 안에 들어오고 유효한 자기 포수 관측이 유지되면 조준 시간을 쌓는다.
4. 조준 완료 후 표적을 탭한 상태에서 **발사 버튼 또는 G**로 단발 입력한다. 자동 발사는 없다.
5. 입력은 다음 0.05초 고정 스텝에서 재검증한다. 통과하면 명중/부위 판정을 한 번 수행하고 시험탄 한 발을 차감한다.
6. 발사 간격 이후 다시 조준한다. 탄수가 0이면 더 발사하지 않는다.

상태는 `no-target`, `blocked`, `aligning`, `aiming`, `ready`, `interval`이다. 확보, 정렬, 조준 완료, 발사 입력, 실제 발사 이벤트를 별도로 보관한다. 관측 상실·표적 변경·정렬 이탈 시 조준 누적은 리셋된다. 명시적인 지정 취소는 대기 중 발사도 즉시 취소한다. 이후 기존 자동 관측 규칙에 따라 다시 확보할 수 있지만 취소된 입력은 살아나지 않는다. 초기화는 새로운 시나리오와 WeakMap 런타임을 사용하므로 이전 탄수·명령·이벤트를 이어받지 않는다.

## 발사 순간의 기하 조건

현재 포수 관측 기록은 10Hz이며 `queryPeriod`보다 오래된 자기 포수 표본은 허가하지 않는다. 식별·적군 확인, 자기 포수 확보, 실제 포탑 각도, 센서/사격 거리, 장비 활성, 탄수와 발사 간격을 검사한다. 최종 입력 처리에서는 **현 시점**의 9개 표본으로 포수 시야와 낮은 발사선 시점의 차폐를 다시 검사한다. 포수 FOV·거리 안에 있고 두 시점에서 모두 보이는 표본만 사용한다. 지형·건물·숲은 기존 보수적 LOS 가속 경로를 사용한다.

이 단계의 발사선은 차량 중심의 지정 높이에서 각 표적 표본까지 잇는 게임 근사다. 실제 포구 충돌·고각/내림각·탄속·중력·비행 시간·탄착 좌표는 계산하지 않는다. 관측창은 보이지만 낮은 발사선이 막히면 입력을 거부한다. 따라서 조준 완료 표시는 입력 직전 상태이며 발사 순간의 재검증까지 보장하는 예약이 아니다. 거부된 입력은 탄수·발사 횟수·난수를 소비하지 않고 이전 예상치를 지운다.

## 게임 확률의 두 단계

`src/fire-control.js`는 지형 모듈과 분리된 게임 규칙이다. **아래 값은 실차 사통장치나 무장 성능을 보정한 값이 아닌 시험용 튜닝**이다.

| 프로파일 필드 | 초깃값 | 뜻 |
|---|---:|---|
| `aimSeconds` | 1.2초 | 유효 확보/정렬 후 연속 조준 |
| `alignmentTolerance` | 1.5° | 실제 포탑 정렬 허용 오차 |
| `maxRange` | 2000m | 시험 사격 한도. 포수 거리도 별도로 제한 |
| `fireHeight` | 2.2m | 낮은 발사선의 근사 시점 |
| `shotIntervalSeconds` | 1초 | 중복/연속 입력 제한. 상세 재장전 모델이 아님 |
| `testRounds` | 42 | 차량별 시험탄 카운터 |
| `accuracyNear` / `accuracyFar` | 0.88 / 0.55 | 거리 비율에 따른 기본 시험 명중률의 양 끝 |
| `selfMotionPenalty` | 0.35 | 자기 이동의 최대 비율 감쇠 |
| `targetMotionPenalty` | 0.25 | 관측된 표적 이동의 최대 비율 감쇠 |
| `motionReference` | 20m/s | 이동 감쇠를 포화시키는 게임 척도 |
| `zoneWeights.hull` / `.turret` | 0.65 / 0.35 | 부위의 기본 게임 비중 |

먼저 거리·자기 속도·**관측 위치의 시간차에서 얻은** 표적 이동·가시 표본 비율로 전체 명중 확률을 정한다. 숨겨진 실제 표적 속도를 읽지 않는다. 완전 차폐는 발사를 거부하고 확률도 0이다. 명중 난수에서 실패하면 `hit:false, zone:null`로 끝난다.

명중한 경우에만 차체/포탑 노출과 기본 비중을 정규화해 조건부 부위 확률을 구한다. 차체와 실제 포탑 방향을 각각 사용해 전/측/후의 연속 게임 가중치를 분배한다. 완전히 가려진 차체/포탑에는 확률을 주지 않는다. 이 정규화는 전체 명중 확률을 100%로 만들지 않는다. 화면에도 **예상 명중률**과 **명중 시 부위 확률**을 구분한다. 7번째 `upper` 키는 후속 확장용이며 현재 고각/상부 공격 모델이 없어 0이다. 세부 약점이나 장갑 성능은 계산하지 않는다.

사격 난수는 관측 난수와 분리하며 seed·발사 차량 ID·승인된 단발 번호로 재현한다. 명중과 부위는 별도 난수다. 렌더링·패널 읽기·선택·배속 프레임 묶음은 난수를 소비하지 않는다. 동일 명령과 시뮬레이션 시간의 코어 결과를 대조한다.

## 표시와 공개 정보

미식별/기억 접촉에는 명중률·부위 정보나 새 사격 권한을 공개하지 않는다. 다른 차량이 발견한 팀 접촉은 직접 지정할 수 있지만 자기 포수가 확보·정렬·조준하기 전까지 발사할 수 없다. 이벤트는 아군 팀 필터 후 복사하며 적 실제 ID 대신 불투명한 접촉 키를 쓴다. 최대 200개를 유지한다.

1.2초 선/섬광/문구는 발사 때 기록한 위치의 화면 효과다. 숨겨진 표적의 이후 좌표나 방향을 따라가지 않는다. 빗나감도 점선으로 같은 기록 지점을 가리키며 실제 탄착점·탄도라는 뜻은 아니다. 렌더링/패널은 기하 검사를 재실행하지 않는다. 발사 때만 추가 정밀 LOS를 수행한다.

## 연결과 검증

빌드 순서는 프로파일 → 관측 → fire-control → sim-core다. HTML 스크립트, build.py, 내장 Worker, tests/load.cjs, 입력 VM, 코어 fixture·LOS 비교·길찾기 제작 로더를 함께 갱신했다. 동결된 WIP07A LOS 원본은 수정하지 않았다.

일반 및 별도 프로세스 성능 fixture는 양쪽 모두 현재 관측/사격 상태 처리를 실행하고 지형/LOS 경로만 비교한다. 발사 입력은 없으므로 발사 순간 추가 LOS 비용이나 전투 전체 FPS 측정은 아니다. 재현 조건과 실제 실행 결과는 [WIP08 릴리스](../TACTICAL_RELEASE_WIP08.md)에 기록한다.

관통·장갑·피해·파괴·실제 탄도·고각·탄종 선택·상세 장전·적 자동 사격 AI는 이번 단계의 완료 범위에 포함하지 않는다. 피격 결과는 기록되지만 전차가 파괴되지는 않는다.
