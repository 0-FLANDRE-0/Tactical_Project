- 구현 head: `e9a21ab731e6146422e1646a1eb8272b34820861` (`feat/wip11e-los-optimization`, PR #10).
- main 기준: `a01ae8bd8965f5b035acdcfa40087cf6fe8c3c7d`.

Node는 `node --test --test-concurrency=2 tests/*.test.cjs`로 실행했다. 러너의 219는 자체 검사와 브라우저를 실행하는 파일 단위 항목을 포함하므로 표의 나머지 수를 다시 더해 총계로 만들지 않는다.

새 WIP11D 대조 검사 6개와 기존 WIP07A oracle 7개가 전체 실행에 포함돼 통과했다. 실제 지도 LOS 12,000건·노출 2,000건의 WIP11D 직접 대조, 기존 독립 oracle 대조, 전체/부분/만료 캐시와 회전·눈높이 변경을 확인했다. 추가 검토에서는 실제 지도와 합성 평지·숲·능선·건물에서 32m/지도 경계, 정·역방향, 영길이, 높이 순서 반전, 수관 경계, 범위 밖·비유한 입력을 공유 helper에 직접 전달해 기준 단일 광선 두 번과 정확히 비교했다.

자동교전 대조는 실제 발사가 발생한 10대·50대의 각 15초 시나리오다. 매 스텝 전체 시나리오와 공개 접촉·발사 이벤트가 기준과 일치했다. 9표본, 논리 광선/캐시 통계, 탐지·기억·공개 HP·전투 규칙은 변경되지 않았다.

기준 fixture는 WIP11D 원본과 바이트 단위로 일치하며 해시 `8ee5cc9f4374db0afcffaf9ae49df9e6c818a089fd72a7f1319f29c994788ee8`을 확인했다. 관측·차량 프로파일·전투·시야 표시/Worker·지도 렌더러·원본 지도·지형 파생 데이터·공통 성능 fixture와 기존 oracle도 main 기준과 동일했다.

## 반복 성능 측정

Node v24.22.1, AMD EPYC 9V74. 기준/최적화 코어를 각각 새 프로세스에서 5회 교대 실행했다. 기존 seed 407, 준비 20스텝·측정 100스텝, 스텝 0.05초와 궤적을 유지했다. 진단 계측은 본 측정에서 껐으며 모든 사례의 최종 상태 JSON·기존 통계가 정확히 일치했다.

| 사례 | 기준 중앙값 / P95 | 최적화 중앙값 / P95 | 중앙값 변화 |
|---|---:|---:|---:|
| 정지 50대 | 3.136 / 6.578ms | 2.899 / 6.664ms | 7.57% 개선 |
| 정지 100대 | 8.764 / 19.058ms | 8.839 / 16.865ms | 0.86% 악화 |
| 이동 50대 | 5.113 / 6.842ms | 4.119 / 6.064ms | 19.45% 개선 |
| 이동 100대 | 19.230 / 25.156ms | 16.798 / 22.196ms | **12.65% 개선** |

작성자 측정에서 정지 50대 P95가 12.95% 악화됐던 항목은 이번에는 1.31% 악화였다. 정지 100대 중앙값은 0.86% 느려졌지만 P95는 11.51% 개선됐다. 주요 기본 사례에서 5%를 넘는 지속적 악화는 확인되지 않았다. 개별 최대 시간은 일부 더 커졌으므로 최악 지연까지 개선됐다고 주장하지 않는다.

실제 Chromium 156.0.8078.79에서도 각 3회 교대 비교했고 모든 최종 상태가 일치했다.

| 사례 | 기준 중앙값 / P95 | 최적화 중앙값 / P95 |
|---|---:|---:|
| 정지 10대 | 0.4 / 1.5ms | 0.4 / 1.5ms |
| 이동 50대 | 5.1 / 8.4ms | 4.9 / 7.8ms |
| 이동 100대 | 19.0 / 28.9ms | 18.2 / 25.1ms |

Chromium 이동 100대는 중앙값 4.21%, P95 13.15% 개선이다. 작성자 측정의 14.71% 중앙값 개선을 이번 재실행 수치로 재사용하지 않았다.

고정 사면·마을·숲·접선 능선·조기 건물 차폐도 재측정했다. 최초 3회에서는 두 합성 배치의 긴 실행 시간이 보여, 같은 배치·준비·반복 작업량을 유지하며 부모 프로세스의 시도 수만 메모리에서 5회로 늘려 확인했다. 체크인된 스크립트는 변경하지 않았다. 5회 결과의 중앙값 개선은 13.83~27.40%, 꼬리 통계 개선은 13.41~20.11%였고 결과는 모두 일치했다. 각 프로세스의 7개 배치 측정에서 기존 도구가 표시하는 P95는 사실상 최댓값이므로, 전체 시뮬레이션 스텝 P95와 구분한다. 최초 결과와 5회 결과를 모두 검토 데이터에 남겼다. 지연 원인을 GC 등으로 확정하지 않았다.

## 실행 파일·남은 제한

`python3 build.py` 결과가 버전 HTML과 일치했다. ZIP 단일 항목·CRC·해제 바이트·SHA-256을 검증하고, 두 번 재패키징해 체크인된 파일과 바이트 단위 일치를 확인했다.

- HTML SHA-256: `61a4b23a4e5d7bcc7619494aa09e2ba3c64a2a0f47b2afdf4242cfc48d72d096`
- ZIP SHA-256: `66c730fc37bbf5e5a959712b3dd360a557dfdd8cef685726195e83c643c8adc2`

이 수치는 CPU 고정 스텝/노출 계산이며 전체 게임 FPS나 실제 모바일 성능 보장값이 아니다. `file://`는 `ERR_BLOCKED_BY_ADMINISTRATOR`로 차단돼 같은 단일 HTML을 로컬 HTTP로 검증했다. 실제 Android/iOS의 지속 프레임률·발열·멀티터치는 미검증이다. 지도 재빌드 비용과 별도의 화면 시야 오버레이 최적화는 이번 범위에 포함되지 않는다.
