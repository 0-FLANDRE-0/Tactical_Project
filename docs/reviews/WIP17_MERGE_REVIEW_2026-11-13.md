# WIP17 병합 검토 — 2026-11-13 KST

최종 검토 구현은 `624d80d94ffb63697c7e478ea23508b6557af8b5`, 통합 기준 main은 `30e78c1c99882cafb9d7eddc83c17709a74d1f30`다. 사용자 병합 요청에 따라 최종 수정본과 이 검토 기록을 main에 통합한다. 최신 main의 설계 아카이브를 보존하고, 실행 코드·지도 데이터·빌드 도구·배포물은 검토한 최종본과 동일하게 유지한다.

## 결과와 수정 확인

기본 라스도르프 4×4를 유지하면서 지도 폭/높이·격자·캐시 계약을 공통으로 검증하고, 실제 해상도의 합성 8×8 및 직사각형을 코어·앱·내장 Worker에서 사용할 수 있는 기반을 확인했다. 최초 `127fe7f` 검토에서 발견한 두 문제는 최종본에서 해결됐다.

| 항목 | 최종 확인 |
|---|---|
| DEM 미포함 영역·NoData를 정상 고도로 생성 | 평활화 전 원본 CRS·격자·커버리지·GDAL 유효 마스크 검사, 재표본 출력도 규격·마스크·유한값 확인 |
| 독립 LOS 비교의 신규 모듈 누락 | 현재 코어 로더에 `TacticalMapSpec` 명시 전달, 새 프로세스의 optimized Worker 정상 완료 |

이전 재현과 같은 NoData 태그 없는 16×16m DEM으로 32×32m를 요청하면 이제 출력 지도 생성 전에 실패한다. 내부 `NoData=0`도 거부하고, 메타데이터/마스크상 유효한 고도 0m는 허용한다. CRS 누락·불일치를 명확히 거부한다. 비교용 WIP11D 동결 코어와 로더는 변경하지 않았다.

## 독립 검증 범위

최초 `127fe7f`에서 Node 305개, Python 지형·원본 각 7개, 실제 Chromium 일반 앱 31개·WIP17 3개·WIP16 7개·WIP15 4개·WIP12 효과 18개를 실행해 통과했다. 이후 도구/로더 수정본 `624d80d`에서는 다음을 재실행했다.

- 비브라우저 Node runner **306/306 통과**. 독립 LOS optimized Worker를 새 자식 프로세스에서 실제 실행하는 회귀를 포함한다.
- 시스템 Python DEM **4/4**, 지형 **7/7**, 원본 품질 **7/7 통과**.

- 기본 4×4 생성기를 재실행해 별도 bake하는 navigation을 제외한 지도 구조 전체의 동일성과 기존 mapHash를 확인했다.

최종 수정에서 실행 코어·앱·내장 지도·HTML/ZIP 바이트가 최초 검토본과 동일한 것을 확인했다. 일반 앱·WIP12/15/16 Chromium 검사는 최초 검토 결과이며 최종 수정에서 재실행한 수치와 구분한다. 브라우저 항목 수를 Node 총합에 다시 더하지 않는다. 통합 기준 main 이후 변경은 설계 문서뿐이므로, 병합 시에도 검토한 실행/데이터/도구/배포 파일의 동일성을 확인한다.
