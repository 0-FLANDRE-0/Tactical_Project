# WIP21 T-80U(1989) 모델·장갑 통합

## 범위와 데이터 소유권

WIP21은 기존 `M1A2_1998` 운용 차량과 분리된 `T80U_1989` 피격 전용 프로파일을 추가한다. 프로파일은 표적 크기·제시 높이, 1,400 HP, 7개 기본 방호 행, Kontakt-5 추가 방호와 부위별 고정 피복률만 소유한다. 기동, 관측 장비, 사격 통제, 무장·탄약, AI, 자동장전, 승무원·장비 반응과 탄약고 사고를 만들지 않는다.

차량 레지스트리의 `capabilities`는 표적·기동·관측·사격·AI를 명시적으로 구분한다. 완전 운용 차량은 기존 필드를 계속 엄격하게 검증하고, 피격 전용 차량에는 필요한 표적/전투 데이터만 검증한다. 따라서 T-80U를 M1A2 ID, M256/M829A2, 4인 승무원이나 에이브람스 구동계로 위장하지 않는다. 사실 메타데이터의 역할은 전차장·포수·조종수 3명뿐이며 런타임 부상 상태는 생성하지 않는다.

장갑과 ERA 값은 조정 가능한 게임 시험 데이터다. 장갑판 실측 두께나 실차 보장 성능을 뜻하지 않는다. 적용값은 다음과 같다.

| 구역 | 기본 KE / CE | 피복률 | 피복 성공 KE / CE |
|---|---:|---:|---:|
| 차체 전면 | 500 / 690 | 0.90 | 715 / 1250 |
| 차체 측면 | 115 / 120 | 0.50 | 330 / 680 |
| 차체 후면 | 40 / 40 | 0 | 40 / 40 |
| 포탑 전면 | 575 / 740 | 0.95 | 790 / 1300 |
| 포탑 측면 | 305 / 390 | 0.45 | 520 / 950 |
| 포탑 후면 | 70 / 70 | 0 | 70 / 70 |
| 통합 상부 | 45 / 45 | 0.45 | 260 / 605 |

## ERA 판정과 사건 결정성

기존 명중·구역·입사각·도탄을 먼저 확정한다. 빗나감과 도탄에는 피복 난수를 만들지 않고, 피복률 0인 구역도 추가 난수를 요구하지 않는다. 나머지는 사건당 한 번 `eraRoll < coverage`를 검사해 성공했을 때만 KE +215 또는 CE +560을 기본 방호에 더한다. `roll == coverage`는 실패이며 피복률 1은 유효 난수 범위 전체에서 성공한다. 평균 방호 가산, 새 경사/LOS 배율, ERA 뒤 기본 장갑 재판정은 없다.

런타임 난수는 기존 판정과 분리된 `seed + impactId + victimId + :wip21:era` 키를 쓴다. 피복 결과와 최종 방호는 중복 ID가 재추첨하지 못하도록 내부 착탄 레코드에 고정된다. 공개 착탄, 효과, 접촉과 기억에서는 ERA roll·피복 여부·실제 최종 방호를 제거한다. ERA는 전투 내내 같은 피복률을 유지하며 블록 소모·폭발·파편·추가 도탄을 만들지 않는다.

착탄은 공격 사건의 `ammoId`를 사용한다. 피격 차량의 장전탄이나 기본 탄종으로 대체하지 않는다. T-80U 실제 경로에서 공격탄 누락은 거부하며, 제한된 레거시 fallback은 사격 가능한 기존 fixture에만 남긴다. M829A2 근접 비관통 규칙은 공격탄 데이터로 이동해 피격 전용 차량에도 기존 15mm/0.30/120·80·35·0 표를 그대로 적용한다. M830의 비관통 피해 비활성은 계속 우선한다.

## 수정 도안과 좌표

게임은 `src/art/t80u-topview.js`의 수정 모델을 그대로 내장하고 `src/t80u-art-adapter.js`로만 좌표 계약을 변환한다. 게임의 차체·포탑·전차장 월드 절대 라디안을 원본의 차체 절대 도, 포탑-차체 상대 도, 전차장-포탑 상대 도로 바꾼다. 별도 기관총 무장 상태는 만들지 않고 상대각 0, 비장착으로 전달한다.

모델은 원본 874px 차체에 7.012m 균일 축척을 사용한다. 450px에서 파생한 차체 폭은 약 3.610297m이며 참고 전폭 3.628m에 맞추려고 폭만 늘리지 않는다. 차체 원점, 포탑 피벗과 포구는 원본 landmark에서 계산한다. 포탑 피벗의 차체 원점 대비 종방향 오프셋은 `(807-810) × 7.012/874m`, 차체 중심에서 포구까지는 `(807-50) × 7.012/874m`, 포구부터 차체 후단까지의 주포 포함 전장은 약 9.579m다. 차체 길이와 주포 포함 전장을 분리한다. 실제 브라우저 검사의 공통 월드 포구 오차는 약 `1.10e-13m`였다.

미식별 표적은 같은 외곽을 검게 채우되 내부 선·색·상세를 그리지 않는다. 식별 뒤 정상 도안을 표시한다. 현재 접촉·팀 공유·기억·관측 확정 잔해는 `artId`, 모델 크기와 마지막 관측 차체/포탑/전차장 자세를 복사한다. 프로파일 ID와 ERA 내부는 노출하지 않고, 기억이 숨은 실제 표적을 따라가지 않는다. 충돌은 차량별 반경을 사용해 살아 있는 T-80U와 잔해를 모두 통과하지 못하게 한다.

## 방호시험 시나리오와 초기화

배포 HTML 우측 명령 영역에 `기본 전투 / T-80U 방호시험` 선택을 추가했다. 기본 전투는 기존 M1A2(1998) 5대와 같은 임무를 유지한다. 방호시험은 아군 M1A2(1998) 1대와 검증된 통행 가능 위치의 고정 T-80U 세 대를 전면·측면·후면 및 독립 포탑 자세로 배치한다.

T-80U에 대한 이동·정지·임무·경계·지정·직접/자동 사격 API는 탄약, 발사 번호, 난수, 비행체나 경로를 만들기 전에 비활성으로 종료한다. 반대로 M1A2 관측 후보, 표적 지정, 명중·피해·격파·잔해와 충돌에는 정상 참여한다. 플레이어는 기존 탄종 메뉴, 자동/보류, 표적 지정과 발사 명령을 그대로 사용한다.

시나리오 전환과 초기화는 코어, 관측/Worker 세대 토큰, 선택·미완성 명령, AI/접촉, 비행체·효과·HP를 새 장면으로 함께 바꾼다. `초기화`는 현재 선택한 시나리오를 다시 만들고 시나리오 선택은 해당 시나리오를 즉시 새로 만든다. 오래된 비동기 가시 영역 응답은 새 장면을 덮지 못한다.

## 성능과 검증 범위

`scripts/benchmark_wip21.cjs`는 seed 7, 100회 예열 뒤 800개 0.05초 코어 스텝, 20,000개 착탄 계산, Chromium 1440×900의 180개 프레임 간격과 일시정지 60프레임 LOS 불변성을 측정한다. 기준 main `be32d23`과 WIP21 기본 전투의 관측 통계는 queries 2,250, candidates/samples 3,682, rayQueries 27,537, rayCacheHits 5,601로 정확히 같았다. 중앙값/P95는 기준 0.3040/0.9476ms, WIP21 기본 0.2918/0.9309ms였다.

방호시험은 운용 관측자 한 대만 있어 0.0841/0.8869ms였다. Chromium 프레임 간격은 기본 16.7/16.8ms, 방호시험 16.7/16.7ms였고 일시정지 렌더에서 LOS 통계가 변하지 않았다. ERA 착탄은 사건당 상수 크기 조회와 난수 한 번뿐이며 매 프레임 장갑 블록 추적이나 추가 LOS가 없다. 단일 실행의 headless 환경 수치로 전체 FPS나 물리 모바일 성능을 보장하지 않는다.

전체 결과, 실행 명령, 브라우저 캡처와 배포 체크섬은 [WIP21 릴리스 문서](../TACTICAL_RELEASE_WIP21.md)와 `tests/releases/WIP21-*.json`에 기록했다.

## 명시적 제외

T-80U 기동·관측 장비·AI·125mm 무장·자동장전, 승무원/장비/탄약고 피해, ERA 블록 좌표 충돌·소모·폭발·파편·추가 도탄, 새 상부 공격 무기와 장갑 편집 UI는 포함하지 않았다. 실제 휴대폰의 장시간 발열·메모리·지속 프레임률도 실행하지 않았다.
