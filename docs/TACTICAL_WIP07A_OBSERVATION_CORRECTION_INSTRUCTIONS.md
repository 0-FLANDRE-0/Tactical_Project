## 2 목표와 작업 범위

전차장은 전방을 넓게 좌우 수색하고, 포수는 전차 전방의 좁은 범위를 조금씩 수색한다. 의심 물체를 먼저 확인한 관측 장비와 표적을 넘겨받은 경로를 구분한다. 전차장 식별 후 인계하는 흐름과 포수 자체 식별 후 표적을 유지하는 흐름을 모두 구현한다.

이번 범위는 다음과 같다.

1. 포수 시야각 축소와 전차장·포수의 전방 왕복 수색.
2. 관측 출처에 따른 집중 확인·적군 확인·인계·표적 유지.
3. 탐지와 미완료 식별 누적 효과의 독립 감쇠.
4. 플레이어의 팀 공유 정보와 개별 차량의 자체 관측 구분.
5. 움직이는 표적과 관측 차량을 사용한 기능·캐시·성능 회귀.

실제 발사·조준 완료 판정·탄도·장갑·관통·피해·재장전·고각은 후속 범위로 유지한다. 포수의 관측 확보를 향후 발사 가능 조건 전체와 동일하게 취급하지 않는다. 이 작업을 위해 적 전술 AI나 전장·길찾기를 전면 개편하지 않는다.

## 3 관측 초깃값

| 채널 | 최대 거리 | 순간 시야각 전체 폭 | 자동 수색 중심의 왕복 범위 | 최대 구동속도 |
|---|---:|---:|---|---:|
| 주변 관측 | 200m | 360° | 해당 없음 | 해당 없음 |
| 전차장 | 2,500m | 90° | 차체 전방 기준 -45°~+45° | 50°/초 |
| 포수 | 2,000m | 30° | 차체 전방 기준 -15°~+15° | 40°/초 |

- 시야각과 수색 중심의 이동 범위는 별도 프로파일 값이다. 표의 ±값을 순간 시야각의 전체 폭으로 오해하지 않는다.
- 전방 기준은 차량의 실제 차체 방위다. 차량이 선회하면 자동 경계의 기준도 따라간다.
- 전차장은 전방을 왕복 수색한다. 현재의 시간에 따라 계속 360°를 도는 기본 수색을 전방 왕복 수색으로 바꾼다.
- 평상시 수색 속도와 표적 확인 시 최대 구동속도를 구분한다. 수색은 느리게, 확인·인계 시에는 필요에 따라 최대 속도까지 사용한다. 반복 주기·반전 완화·위상은 게임 초깃값으로 정해 문서화한다.
- 수색 각도의 끝점에서 목표 방향이 순간 이동하거나 포탑이 급격히 되돌아가지 않게 한다. 각 차량과 장비의 수색 위상도 독립적으로 유지한다.
- 지정 경계·직접 지정·확인 중인 표적 추적은 기본 자동 수색 범위 밖의 방향도 볼 수 있다. ±45°/±15°를 장비의 기계적 회전 한계로 사용하지 않는다.
- 포수 부채꼴 중심은 실제 `u.turret`, 전차장 중심은 실제 독립 방위와 일치시킨다.
- 최대 속도는 매 고정 스텝에서 적용한다. 인계 시 즉시 목표 방위를 정하되 실제 각도는 순간 이동하지 않는다.
- 주변 관측만으로는 미식별 실루엣 단계까지만 허용한다. 200m 안에서도 전차장·포수의 유효 관측으로 식별할 수 있다.
- 기존 지형·건물·숲 차폐, 관측 높이, 부위 노출, 중심 가중치·시간 누적을 보존한다.

## 4 관측 출처와 상태의 구분

차량의 공통 접촉 목록에 있다는 사실만으로 모든 장비가 그 표적을 직접 발견한 것으로 처리하지 않는다.

최소한 다음 의미를 구분할 수 있어야 한다. 실제 필드명과 구현 방식은 기존 구조에 맞게 정한다.

- 주변 관측이 제공한 의심 접촉.
- 전차장이 직접 발견·현재 관측한 접촉.
- 포수가 직접 발견·현재 관측한 접촉.
- 탐지·식별 완료의 출처와 시각.
- 현재 집중 확인 또는 표적 유지를 담당하는 장비.
- 전차장에 의한 명시적인 헌터킬러 지정 전달.
- 플레이어의 직접 지정.
- 다른 아군이 제공한 팀 공유 접촉.
- 마지막 관측 위치와 현재 자체 관측의 유무.

차량 내부의 식별 지식 공유는 유지할 수 있다. 다만 지식을 공유받았다는 사실이 포수의 자체 관측이나 사전 선회 허가를 자동으로 충족시키지 않게 한다. 출처 판단을 현재 `channels` 배열 하나만으로 처리해서 관측 상실 시 이력까지 사라지거나 서로의 발견을 자기 발견으로 오인하지 않게 한다.

## 5 상황별 동작

### 5.1 평상시 자동 경계

포수와 전차장은 각자 전방을 왕복 수색한다. 포수는 좁은 시야와 작은 왕복 범위를 사용하고, 전차장은 넓은 시야와 큰 왕복 범위를 사용한다. 한 장비의 자동 수색 목표를 다른 장비에 그대로 복사하지 않는다.

### 5.2 전차장 또는 주변 관측이 먼저 의심 접촉을 제공한 경우

1. 전차장이 의심 접촉의 관측된 위치를 중심으로 가져와 집중 확인한다.
2. 포수는 자신의 전방 수색 또는 기존 임무를 계속한다.
3. 전차장만 발견한 미식별 접촉 때문에 포수가 먼저 돌아가서는 안 된다.
4. 식별이 완료되고 적군으로 확인됐으며 헌터킬러가 활성화돼 있으면 포수에게 지정 전달한다.
5. 포수가 비어 있다면 다음 시뮬레이션 갱신부터 지정된 방향으로 실제 포탑을 선회시킨다. 불필요한 별도 지연은 넣지 않는다.
6. 포수는 자신의 시야각·거리·가시선으로 표적을 확보한다. 전달받은 식별 정보를 처음부터 다시 쌓게 하지 않는다.
7. 포수 확보 후 전차장이 자동 경계 상태라면 주변 수색으로 복귀한다.

미식별 의심 접촉과 적군 확인은 구분한다. 현재 두 진영 게임에서는 식별 후 진영 확인을 간단하게 구현해도 되지만, 미식별 상태를 이미 적군 확인이 끝난 자동 인계 대상으로 취급하지 않는다. 이번 작업에서 복잡한 별도 식별 시뮬레이터를 새로 만들 필요는 없다.

### 5.3 포수가 자신의 시야로 먼저 발견한 경우

1. 포수가 직접 관측한 의심 접촉을 자기 시야 중심으로 가져와 확인할 수 있다.
2. 이 경로는 전차장이 먼저 식별할 때까지 기다릴 필요가 없다.
3. 포수가 식별과 적군 확인을 완료하면 그 표적의 관측·유지를 계속한다.
4. 전차장이 자동 경계 상태라면 같은 표적에 자동으로 붙들리지 않고 다른 주변 구역을 수색한다. 이미 같은 표적을 확인하던 경우에는 자동 집중을 해제하고 수색한다.
5. 포수 자체 확인 경로에 가짜 전차장 인계 사건을 생성하지 않는다. 헌터킬러 OFF에서도 이 경로는 정상적으로 작동해야 한다.

현재 확인 담당과 식별 완료 출처가 경계 시점에서 경합하더라도 결과를 결정적으로 처리한다. 같은 표적을 서로 인계하며 상태가 반복 전환되는 현상을 막는다.

### 5.4 포수가 이미 표적을 확보한 경우

- 포수가 현재 확인한 적을 계속 관측한다.
- 전차장이 새 표적을 식별하면 다음 후보로 보관하고 수색을 이어갈 수 있다.
- 새 표적 때문에 기존 포수 표적을 일정 시간마다 자동으로 덮어쓰지 않는다. WIP07의 확보 후 2초 경과 시 다른 접촉으로 바꾸는 경로를 확인해 수정한다.
- 현재 표적 유지가 끝나는 조건은 플레이어 변경·해제, 유효 관측 상실 후 유예 만료, 접촉 만료 등 이번 관측 시스템에서 판정 가능한 사건으로 정의한다.
- 후속 피해 시스템의 파괴 판정은 연결 지점만 남긴다. 아직 없는 파괴 판정을 이번에 추가하지 않는다.
- 대기 후보는 숨겨진 실제 위치를 따라 갱신하지 않으며, 각 후보의 관측 시각·기억 만료를 따른다.

### 5.5 명령 우선순위와 장비 유무

- 플레이어가 새로 내린 직접 지정·경계·해제 명령을 존중한다.
- 지정 경계 중에는 구역 밖 접촉이나 자동 인계가 명령을 임의로 빼앗지 않는다. 명시적인 새 직접 지정으로 명령을 바꾸는 경우는 구분한다.
- 전차장의 수색 복귀도 자동 경계인 경우에 적용한다. 포수 확보를 이유로 플레이어가 지정한 전차장 경계를 삭제하지 않는다.
- 자동 관측에서 포수의 유효한 기존 표적 유지는 새 자동 후보보다 우선한다.
- 헌터킬러 OFF에서는 전차장이 찾은 표적으로 포탑을 자동 유도하지 않는다. 포수 자체 수색·식별과 플레이어 직접 지정은 유지한다.
- 독립 전차장 시야 유무와 헌터킬러 유무는 별도 프로파일 기능으로 유지한다. 전차장 장비가 없는 차량도 포수 자체 관측과 직접 지정으로 작동해야 한다.
- 직접 지정된 미식별 접촉은 기존 수동 확인 경로를 유지할 수 있다. 직접 지정 자체를 식별 완료·적군 확인·자동 헌터킬러 사건으로 간주하지 않는다.

## 6 탐지 누적과 식별 누적의 독립 감쇠

다음 세 가지를 분리한다.

| 상태 | 갱신 기준 |
|---|---|
| 탐지 누적 효과 | 주변·전차장·포수 중 유효한 탐지 관측 |
| 미완료 식별 누적 효과 | 전차장·포수의 유효한 식별 관측 |
| 완료된 식별 지식 | 마지막 확인 시각과 별도의 지식 유지·만료 규칙 |

- 주변 관측만 유효하면 탐지 누적은 계속 쌓을 수 있다.
- 같은 상황에서 전차장·포수의 식별 품질이 0이면 미완료 식별 누적은 시간에 따라 감소해야 한다.
- 모든 채널의 관측을 잃었을 때만 두 값을 한꺼번에 감소시키는 현재 처리를 수정한다.
- 이미 완료한 식별 지식은 짧은 단절 때문에 초기화하지 않는다. 30초 위치 기억과 120초 식별 지식 등의 기존 설정은 별도 값으로 유지한다.
- 누적 효과 반감기 8초는 기본값으로 유지하고 프로파일에서 조절 가능하게 한다. 검사에서는 초기값 대비 감소 비율을 허용 오차와 함께 확인한다.
- 누적·감쇠·재획득은 시뮬레이션 시간을 기준으로 처리한다. UI 조회나 렌더링이 값이나 난수를 바꾸면 안 된다.
- 두 장비가 동시에 관측한다고 같은 경과 시간을 두 번 적립하지 않는다.

## 7 팀 화면과 차량 자체 시야

여기서 플레이어 화면의 표적 정보는 아군의 팀 공유 관측을 기준으로 한다. 카메라 위치나 화면에 도안이 들어왔는지는 차량의 탐지 조건이 아니다.

필수 예시는 다음과 같다.

1. A전차가 표적을 발견해 플레이어 화면에 보인다.
2. B전차는 건물·능선·숲에 가렸거나 다른 방향을 보거나 자기 장비의 거리 밖이어서 표적을 직접 보지 못한다.
3. 이때 화면에 표적이 표시돼도 B의 자체 관측·식별 누적·포수 확보가 자동으로 참이 되지 않는다.
4. 플레이어는 팀 접촉을 B에게 직접 지정할 수 있다. B는 전달된 마지막 관측 위치로 선회한 뒤 자신의 센서로 확보해야 한다.
5. A도 관측을 잃으면 팀 화면은 기억으로 전환한다. 가려진 실제 표적의 현재 위치와 자세는 화면이나 B의 제어에 역유입되지 않는다.

같은 차량 안에서도 전차장 2,000~2,500m 관측과 포수 2,000m 관측은 구분한다. 전차장에게 보인다는 이유로 포수의 관측 거리를 늘리거나 확보를 선언하지 않는다.

정보 공개 규칙은 정상 도안·실루엣·축소 마커·클릭·표적 패널에 일관되게 적용한다. 미식별 표적의 상세정보를 숨기고, 기억 표적은 마지막 관측 위치와 자세를 유지한다.

## 8 확인된 기존 문제와 재현 근거

아래 결과는 검토 커밋에서 실제 `observation.js`와 저장소의 합성 관측 fixture를 실행한 결과다. 가시선은 fixture가 주입하므로 실제 지형·브라우저 검사와 구분한다. 수정 전에 같은 원인 경로를 재현하고 회귀 검사로 남긴다.

### A 전차장 접촉을 포수가 식별 전부터 따라가는 문제

- `tests/helpers/observation-fixture.cjs`의 `fixture({bearing:1.5})`를 사용한다.
- 전차장에게 표적 지점 경계를 지정하고 포수는 자동 경계로 둔다.
- 헌터킬러 ON과 OFF를 각각 실행한다.
- 기존 결과: 전차장 단독 탐지 2.10초, 포수 자동 집중 시작 2.15초, 식별 완료 3.00초.
- 2.15초 시점의 채널은 commander뿐이고 식별은 미완료, designation은 idle이었다. ON/OFF 모두 포수가 같은 시각에 표적으로 선회했다.
- 원인 진입점: `src/observation.js`의 `focus()`가 공통 접촉을 장비 출처 구분 없이 사용하고 `control()`의 포수 경로에서도 호출한다.
- 수정 후에는 전차장 단독 미식별 접촉만으로 포수의 자동 관심 방향이 바뀌지 않아야 한다. 포수가 나중에 자기 시야로 실제 발견하는 경우는 별도 정상 경로다.

새 시야각과 수색 궤적으로 재현 시각은 달라질 수 있다. 과거의 특정 초 수치를 새 검사 정답으로 하드코딩하지 말고 사건 순서·관측 출처·방향 변화 원인을 검증한다.

### B 주변 탐지가 미완료 식별 진행도를 영구 보존하는 문제

- 거리 150m, 포수 비활성, 헌터킬러 OFF, 전차장 지점 경계 조건을 사용한다.
- 식별 임계값을 넘기기 전에 일부 식별 효과만 쌓은 뒤 전차장도 비활성화하고 주변 관측만 남긴다.
- 기존 재현에서는 1.2초의 식별 효과 약 1.097624가 주변 관측만으로 20초가 지나도 같았다. 식별 임계값은 약 1.637133이었다.
- 모든 관측을 끊은 뒤에는 8초 동안 약 0.548812로 줄었다. 즉 감쇠 경로가 전체 탐지 상실에만 묶여 있다.
- 원인 진입점: `query()`에서 주변 채널도 공통 `seen`에 넣고, `!seen.has(id)`일 때만 두 누적값을 같이 감쇠한다.
- 수정 후에는 주변 관측 중에도 미완료 식별 효과가 감소해야 한다. 완료된 식별 지식의 보존은 별도로 검증한다.

개발용 기록에는 시뮬레이션 시각, 관측 차량·장비, 탐지와 식별 출처, 관측 상태, 실제 방위, 인계·확보 전이와 사유를 남긴다. 진단용 실제 표적 데이터는 검사 비교에 사용할 수 있지만 자동 수색·인계 입력으로 역유입시키지 않는다.

## 10 코드 연결과 성능

우선 확인할 위치는 다음과 같다. 행 번호보다 현재 함수와 호출 경로를 기준으로 수정한다.

| 위치 | 확인·변경 대상 |
|---|---|
| `src/vehicle-profiles.js` | 포수 30°와 장비별 전방 왕복 수색 설정 |
| `src/observation.js` | 관측 출처, 확인 담당, `focus`·`control`·`query`·`handoff`·팀 공유 |
| `src/sim-core.js` | 고정 스텝 연결, 실제 선회, 장비별 노출·LOS와 광선 캐시 |
| `src/app.js` | 팀 접촉 표시와 선택 차량의 자체 확보 상태 구분, 명령 처리 |
| `src/visibility.js`, `visibility-client.js` | 표시용 마스크·부채꼴 및 오래된 비동기 응답 차단 |
| `src/m1a2-art.js`, `look-animation.js` | 실제 각도와 그림의 일치, 모션 설정과 관측의 독립성 |

| `tests/observation*.cjs`, `tests/input.test.cjs`, `tests/browser.test.cjs` | 역할별 순수·코어·입력·실제 브라우저 회귀 |
| `scripts/export_vehicle_profile.cjs`, 차량 설명 문서 | 새 프로파일 값과 동작 설명 동기화 |

기존 20Hz 고정 시뮬레이션과 10Hz 분산 관측 구조를 유지한다. 화면과 패널에서 정밀 LOS를 반복하지 않는다. 모든 차량에 전체 시야 마스크를 계산하지 않는다. 정확히 같은 광선의 제한적 재사용과 양 끝점·높이·부위 자세 변화에 따른 무효화를 유지한다.

정지·이동 각각 50대와 100대의 재현 가능한 fixture로 비용을 측정한다. 환경·seed·배치·이동 궤적·준비 구간·측정 구간, 스텝 중앙값·p95·최대값, 정밀 광선·캐시 재사용 횟수를 기록한다. 이동 벤치마크의 경로와 표본 기간은 결과를 쉽게 반복할 수 있는 짧은 구간으로 잡는다.

이전 재검사 환경의 정지 fixture는 50대 중앙값 약 6.00ms, 100대 약 23.49ms였고 100대 최대값은 약 85.79ms였다. 참고값이며 현재 환경의 실측을 대체하거나 전체 FPS로 환산하지 않는다. 처리량이 부족하면 먼저 후보 선별·분산·중복 조회를 확인하고, 관측 시간을 임의로 적립하거나 확률 기준을 바꿔 성능을 맞추지 않는다.

지도 원본·높이장·4.62m 차량 반경·길찾기 계약은 이번 작업에서 보존한다. 관측 값 변경만으로 내비게이션 캐시를 다시 제작하지 않는다.

## 11 빌드와 검증 실행

현재 README와 검사 명령을 확인한 뒤 기존 회귀와 새 회귀를 함께 실행한다. 검토 당시 기존 기준선은 Node 127/127과 JS/CJS 구문 28/28 통과였다. 검사 개수 자체를 목표로 삼지 말고 변경된 계약에 맞는 검사를 추가·갱신한다.

기존 실행 명령의 기준은 다음과 같다.

```sh
node scripts/export_vehicle_profile.cjs
python3 build.py
node --test tests/look-animation.test.cjs tests/ui-cache.test.cjs tests/observation.test.cjs tests/observation-core.test.cjs
node tests/input.test.cjs
node tests/map.test.cjs
node tests/visibility.test.cjs
node tests/vehicle.test.cjs
node tests/browser.test.cjs
node scripts/benchmark_observation.cjs
```

새 검사 파일은 실제 검사 실행 목록에 포함한다. 수정한 JS/CJS의 구문도 확인한다. `src`를 수정하고 빌드로 배포 HTML을 생성하며 `dist/index.html`만 직접 수정하지 않는다. 모듈을 추가하면 본문·Worker·빌드·검사 로더 순서를 함께 갱신한다.

실제 브라우저에서는 장비 선택·지점 경계·자동 복귀·직접 지정·취소, 실제 선회와 부채꼴 일치, 실루엣·기억·표적 패널, 모바일 가로·세로 배치를 확인한다. 팀 화면에 표적이 있지만 선택 차량이 자체 확보하지 못한 상황도 확인한다.

기존 WIP07에는 별도 환경의 Chromium 10/10 기록이 있다. 앞선 검토 환경에서는 Chromium이 `socket() failed: Operation not permitted`로 시작하지 못했다. 이번 환경의 가능 여부를 직접 확인하고, 과거 결과를 새 버전 결과로 복사하지 않는다. 가짜 DOM·모의 접촉·실제 브라우저·실제 Android 검사를 구분한다. 브라우저나 실기기 검사를 못 했으면 미실행 이유와 남은 확인을 기록한다.

## 12 완료 기준과 결과물

다음 조건을 충족해야 관측 보정을 완료한 것으로 보고한다.

- 전방 왕복 수색과 포수 30°가 실제 관측·도안·홀드 표시·프로파일에 일치한다.
- 전차장 단독 발견 때문에 식별·인계 이전에 포수가 먼저 돌아가지 않는다.
- 포수 자체 식별은 별도 경로로 작동하며 포수가 표적을 유지하는 동안 자동 경계 중인 전차장은 주변 수색한다.
- 확보 중인 표적을 새로운 전차장 후보가 일정 시간마다 강제로 바꾸지 않는다.
- 주변 탐지와 미완료 식별 감쇠가 분리된다.
- 팀 공유 화면과 개별 차량의 자체 관측·확보가 분리된다.
- 움직이는 표적의 차폐·기억·캐시 회귀와 정지·이동 비용 측정을 실행했다.
- 이번 범위에 필요한 기존 회귀와 새 회귀의 결과를 남겼으며, 미실행 항목은 구분했다.

결과물은 다음을 포함한다.

1. 변경 소스와 새 회귀 검사.
2. 새 버전 실행 HTML과 내용이 같은 `dist/index.html`.
3. README, 차량 프로파일 설명, 관측 상태 문서와 실제 검증 기록.
4. 기존 두 문제의 수정 전·후 재현 요약과 움직이는 표적 회귀 결과.
5. 정지·이동 50대·100대 성능 결과와 재현 조건.
6. 실행 HTML의 파일 크기·SHA-256 및 다운로드 가능한 결과.
7. 작업 브랜치·커밋·PR 상태, 남은 문제와 정확한 다음 진입점.

기존 배포 HTML과 과거 검증 기록은 보존한다. 다운로드 편의를 위해 ZIP을 만들면 압축 해제한 HTML이 배포 HTML과 동일한 바이트인지 확인한다. 게임은 계속 외부 라이브러리 다운로드 없이 실행 가능한 단일 HTML을 유지한다.

가능하면 기존 검토용 PR을 갱신한다. main 병합이나 공개 배포는 이번 지시 범위에 포함하지 않는다. 일부 경로만 연결한 상태를 전체 완료로 보고하지 않는다.
